# ฟอร์ม IOC — ความสอดคล้องของตัวชี้วัดกับแบบทดสอบ

สถานะ: **IOC ระยะ 0 — สเปกและภาพร่าง** ยังไม่มีโค้ด ไม่มี migration และยังไม่มีหน้าจอจริง

อัปเดตล่าสุด: 13 กันยายน 2569

เอกสารนี้คือข้อตกลงก่อนเขียนโค้ด ไม่ใช่คำอธิบายของสิ่งที่ deploy แล้ว อะไรที่ยังไม่ได้ทำจะเขียนว่ายังไม่ได้ทำ

## ปัญหาที่แก้

ครูที่ออกข้อสอบหนึ่งฉบับต้องทำงานซ้ำสี่อย่างทุกภาคเรียน

1. ทำฟอร์ม IOC ใน Word — คัดลอกข้อสอบทั้งฉบับลงตารางด้วยมือ จัดคอลัมน์ +1/0/−1 ให้ไม่แตกข้ามหน้า
2. พิมพ์แจกผู้ทรงคุณวุฒิหรือส่งไฟล์ให้ แล้วรอรับคืน
3. คำนวณดัชนีความสอดคล้องรายข้อด้วยเครื่องคิดเลข
4. ทำตารางสรุปอีกใบ พร้อมย่อหน้าสรุปผลและร้อยละความสอดคล้อง

ข้อ 1 เว็บทำให้ได้ทันทีเพราะรู้อยู่แล้วว่าข้อสอบคือข้อไหน ข้อ 3 กับ 4 เป็นเลขคณิตที่เครื่องควรคิด ส่วนข้อ 2 ย่นลงเป็นลิงก์ได้ เหลือเพียงงานที่ต้องเป็นครูทำเองคือการระบุว่าข้อสอบข้อไหนวัดตัวชี้วัดตัวใด

## เอกสารต้นแบบ

อ้างจากไฟล์ที่เจ้าของผลิตภัณฑ์ให้ไว้: IOC ของแบบทดสอบกลางภาคเรียนที่ 2 คณิตศาสตร์พื้นฐาน 6 (ค 33102) ชั้น ม.6 จำนวน 11 ข้อ ผู้ทรงคุณวุฒิ 3 ท่าน ทั้งไฟล์มี 5 หน้า แยกเป็นสามชนิด

| ชนิดหน้า | ในไฟล์ต้นแบบ | เนื้อหาที่ต้องผลิตซ้ำให้ได้ |
| --- | --- | --- |
| หัวเอกสาร + คำชี้แจง | หน้า 1 | ชื่อเรื่อง IOC · ช่วงสอบ/รายวิชา/รหัสวิชา/ชั้น · โรงเรียน · คำชี้แจง · ความหมายของ +1 / 0 / −1 |
| ตารางประเมิน | หน้า 1–3 | มาตรฐานตัวชี้วัด · แบบทดสอบ · ค่าความสอดคล้อง (+1 / 0 / −1) · ข้อเสนอแนะ |
| หน้าลายเซ็น | หน้า 4 | เส้นประ + ชื่อในวงเล็บ ของผู้ออกข้อสอบ และผู้ประเมินคนที่ 1–3 |
| ตารางสรุป | หน้า 5 | ร้อยละความสอดคล้อง · ย่อหน้าสรุปผลการประเมิน · ตาราง: ตัวชี้วัด / ข้อที่ / ผลการประเมิน (คน) สอดคล้อง-ไม่แน่ใจ-ไม่สอดคล้อง / ดัชนีความสอดคล้อง |

**จุดที่แก้จากต้นแบบ** ต้นแบบมีคอลัมน์ "ผู้เชี่ยวชาญคนที่" ที่แตกทุกข้อออกเป็นสามแถว (1, 2, 3) ในฉบับเดียว ซึ่งเป็นความสับสนของเอกสารต้นทาง เพราะผู้ทรงแต่ละท่านต้องประเมินแยกกัน คอลัมน์นี้ถูกตัดออก และแทนที่ด้วยหลักที่ชัดกว่า

> **หนึ่งฉบับ = หนึ่งผู้ทรงคุณวุฒิ** หนึ่งข้อสอบจึงมีหนึ่งแถว และหน้าลายเซ็นของฉบับนั้นมีเฉพาะผู้ออกข้อสอบกับผู้ประเมินท่านนั้น ส่วนหน้าลายเซ็นรวมทุกท่านใช้เมื่อส่งออกเป็นเล่ม

สิ่งที่ต้นแบบบอกเราเพิ่มอีกสองอย่างและต้องรักษาไว้ในฟอร์มที่เว็บสร้าง

- **หัวข้อตอน** — "ตอนที่ 1 ข้อสอบปรนัย 4 ตัวเลือก" และ "ตอนที่ 2 ข้อสอบอัตนัย" มีอยู่ในระบบแล้วเป็น `question_set_sections`
- **โจทย์ร่วมของหลายข้อ** — ตารางแจกแจงความถี่ที่ตามด้วย "จงตอบคำถาม 3 ข้อดังต่อไปนี้" ตรงกับโจทย์ที่มี `group_id` เดียวกันในคลัง ทั้งสองอย่างดึงมาใช้ได้โดยครูไม่ต้องพิมพ์ใหม่

## ขอบเขตที่ตกลงแล้ว

เจ้าของผลิตภัณฑ์เคาะสี่ข้อนี้เมื่อ 13 กันยายน 2569

1. **ส่งออก PDF ด้วยหน้าพิมพ์ A4 ของเบราว์เซอร์** ไม่เพิ่ม PDF library และไม่ใช้ headless Chrome บนเซิร์ฟเวอร์ เหตุผลคือภาษาไทย: `pdf-lib` และ `pdfmake` วางสระกับวรรณยุกต์ซ้อนผิดตำแหน่งเพราะไม่ทำ GPOS mark positioning และตัดบรรทัดคำไทยที่ไม่มีช่องว่างไม่ได้ ขณะที่เบราว์เซอร์ทำทั้งสองอย่างถูกต้องอยู่แล้ว เว็บนี้มีแบบอย่างอยู่แล้วที่ `app/(app)/classrooms/[id]/report`
2. **ฟอร์ม IOC ใช้ได้ทั้งกับโครงการวิจัยและข้อสอบทั่วไป** ไฟล์ต้นแบบเองเป็นข้อสอบกลางภาคปกติ ไม่ใช่งานวิจัย ดังนั้น `ioc_forms.project_id` เป็น nullable ตั้งแต่ migration แรก
3. **ลิงก์แยกต่อผู้ทรงหนึ่งคนหนึ่งลิงก์ ครูใส่ชื่อไว้ก่อน** ชื่อจึงไหลไปหน้าลายเซ็นและตารางสรุปได้เองแบบเอกสารต้นแบบ และแดชบอร์ดรู้ว่าใครส่งแล้วใครยังไม่ส่ง
4. **เกณฑ์ตั้งต้น 0.50 และร้อยละความสอดคล้องคิดจากจำนวนข้อที่ผ่านเกณฑ์** ครูเปลี่ยนได้ทั้งสองค่า และเอกสารที่ส่งออกพิมพ์กำกับไว้ว่าใช้เกณฑ์เท่าไรและคิดร้อยละด้วยกฎใด

## สิ่งที่ไม่อยู่ในรุ่นแรก

- มาตรวัด 5 ระดับ และแบบประเมินชนิดอื่น (แผนการสอน นวัตกรรม แบบสอบถาม) — กลไกเดียวกันต่อยอดได้ แต่ไม่ทำในรุ่นแรก
- ไม่มี AI เดาตัวชี้วัดให้ ครูเป็นผู้ระบุเอง
- **เว็บไม่ส่งอีเมลหรือข้อความหาผู้ทรงเอง** ยังไม่มีระบบส่งอีเมลของผลิตภัณฑ์นอกจากอีเมลของ Supabase Auth ครูคัดลอกลิงก์หรือ QR ไปส่งทางช่องทางของตัวเอง และหน้าจอจะไม่พูดว่า "ส่งอีเมลแล้ว"
- ไม่ใช่ลายมือชื่ออิเล็กทรอนิกส์ที่รับรองตามกฎหมาย เป็นเพียงภาพลายเซ็นที่ผู้ลงนามยินยอมให้ใช้ในเอกสารฉบับนั้น หน้าจอและเอกสารห้ามอ้างการรับรองทางกฎหมายหรือมาตรฐานใด ๆ
- ไม่คำนวณความเชื่อมั่น (KR-20 / α) ในรุ่นนี้ — ดู "ต่อยอดที่เตรียมทางไว้"

## สูตรและกฎการคำนวณ

กฎทั้งหมดอยู่ใน `lib/ioc.ts` เป็น pure function มี vitest ครอบ และไม่มีการคำนวณซ้ำในหน้าเว็บหรือในเอกสารส่งออก

**ดัชนีความสอดคล้องรายข้อ**

```
IOC(i) = ΣR(i,j) / N(i)
```

- `R(i,j) ∈ {+1, 0, −1}` คะแนนที่ผู้ทรงคนที่ `j` ให้ข้อ `i` · +1 แน่ใจว่าสอดคล้อง · 0 ไม่แน่ใจ · −1 แน่ใจว่าไม่สอดคล้อง
- `N(i)` = จำนวนผู้ทรงที่ **ส่งผลแล้วและให้คะแนนข้อนั้น** ไม่ใช่จำนวนผู้ทรงที่ถูกเชิญ
- ค่าอยู่ในช่วง −1.00 ถึง 1.00 แสดงผลสองตำแหน่งทศนิยมตามเอกสารต้นแบบ
- **เทียบเกณฑ์ด้วยค่าเต็มความละเอียดก่อนปัด** ห้ามปัดเป็นสองตำแหน่งแล้วค่อยเทียบ
- ผ่านเมื่อ `IOC(i) ≥ threshold` ค่าตั้งต้น 0.50

ที่มาของเกณฑ์: วิธีนี้ Rovinelli และ Hambleton (1977) ปรับมาจาก Hemphill และ Westie (1950) ตำราไทยที่ครูอ้างกันใช้ 0.50 ขึ้นไป ส่วนงานต่างประเทศหลายชิ้นใช้ 0.67 ข้อสังเกตที่ต้องเขียนไว้ในคำอธิบายบนหน้าจอ: **ถ้ามีผู้ทรง 3 ท่าน ค่าที่เป็นไปได้มีแค่ 1.00, 0.67, 0.33, 0.00 ลงไป ดังนั้นเกณฑ์ 0.50 กับ 0.67 ให้ผลเหมือนกันทุกกรณี** ความต่างเกิดเมื่อมีผู้ทรง 4 ท่านขึ้นไป

**ผลการประเมิน (คน)** นับจำนวนผู้ทรงที่ให้ +1, 0 และ −1 ของข้อนั้นตรง ๆ สามตัวเลขนี้ต้องรวมกันได้เท่ากับ `N(i)` เสมอ ถ้าไม่เท่าให้ถือเป็นบั๊กไม่ใช่ข้อมูล

**ร้อยละความสอดคล้อง** สองกฎ เลือกได้ตอนสร้างฟอร์ม

- `items_passing` (ตั้งต้น) = จำนวนข้อที่ผ่านเกณฑ์ ÷ จำนวนข้อทั้งหมด × 100
- `mean_index` = ค่าเฉลี่ย IOC ทุกข้อ × 100

ในไฟล์ต้นแบบทุกข้อได้ 1.00 พอดี ทั้งสองกฎจึงให้ 100.00 เท่ากัน แยกไม่ออกจากตัวอย่าง เอกสารที่ส่งออกต้องพิมพ์ว่าใช้กฎใด ไม่ปล่อยให้กรรมการเดา

**กรณีที่ห้ามคำนวณเงียบ ๆ**

| กรณี | สิ่งที่ต้องทำ |
| --- | --- |
| ผู้ทรงข้ามบางข้อ | `N(i)` ต่างกันได้ระหว่างข้อ · แสดงหมายเหตุว่าข้อนั้นคิดจากกี่คน · ไม่แทนข้อที่ข้ามด้วย 0 |
| ผู้ทรงยังส่งไม่ครบ | แสดงผลได้ แต่ติดป้าย "ผลชั่วคราว" ทั้งบนหน้าจอและบนเอกสารที่ส่งออก |
| ผู้ทรงน้อยกว่า 3 ท่าน | เตือนว่าจำนวนผู้ทรงต่ำกว่าที่งานวิจัยทั่วไปใช้ · ไม่ห้าม |
| ผู้ทรงเป็นจำนวนคู่ | เตือนว่าค่าอาจออกมาคาบเกณฑ์พอดี · ไม่ห้าม |
| ไม่มีคะแนนเลยในข้อหนึ่ง | ดัชนีเป็น "—" ไม่ใช่ 0.00 และข้อนั้นไม่ถูกนับเป็นผ่านหรือไม่ผ่าน |

**ย่อหน้าสรุปผลการประเมิน** ระบบเติมตัวเลขจริงลงแม่แบบข้อความ ครูแก้ถ้อยคำได้ แต่ตัวเลขในย่อหน้ามาจากการคำนวณเท่านั้น ถ้าครูแก้ตัวเลขเองระบบจะไม่ตามไปแก้ให้ จึงเก็บข้อความที่ครูแก้แยกจากตัวเลข และเตือนเมื่อคะแนนเปลี่ยนหลังจากครูแก้ย่อหน้าไปแล้ว

**ตัวช่วยสร้าง 4 ขั้น**

1. **หัวเอกสาร** — ชื่อแบบทดสอบ/ช่วงสอบ รายวิชา รหัสวิชา ชั้น ภาคเรียน ปีการศึกษา โรงเรียน ชื่อผู้ออกข้อสอบ เติมค่าตั้งต้นจากองค์กร ห้องเรียน และโปรไฟล์ครูให้ก่อน
2. **เลือกข้อสอบ** — สามทาง: ข้อสอบก่อนเรียน/หลังเรียนของโครงการวิจัย · งานที่มอบหมายในห้องเรียน · แฟ้มและคลังโจทย์ เมื่อเลือกแล้วระบบคัดลอกโจทย์ หัวข้อตอน โจทย์ร่วม และเลขข้อมาให้ครบ
3. **มาตรฐานและตัวชี้วัด** — งานที่ครูต้องทำเอง มีเครื่องมือทุ่นแรง: สร้างรายการตัวชี้วัดของฟอร์มไว้ก่อนแล้วจ่ายให้หลายข้อพร้อมกัน · "ใช้ค่าเดียวกับข้อก่อนหน้า" · วางข้อความตัวชี้วัดเป็นก้อนแล้วให้ระบบแยกบรรทัด
4. **ผู้ทรงคุณวุฒิและลายเซ็นครู** — ใส่ชื่อผู้ทรงตามลำดับ "ผู้ประเมินคนที่ 1…N" เลือกวิธีลงนามของครู แล้วกดสร้างลิงก์

ตัวชี้วัดหนึ่งตัวมักครอบหลายข้อ เอกสารต้นแบบจึงผสานช่องตัวชี้วัดเป็นช่องเดียวคร่อมหลายแถว ฐานข้อมูลรองรับเรื่องนี้ด้วยการแยกตัวชี้วัดเป็นตารางของตัวเองแล้วให้ข้อสอบอ้างถึง ไม่ใช่เก็บข้อความซ้ำทุกแถว

**หน้าผู้ทรงคุณวุฒิ** เปิดจากลิงก์ → ยืนยันว่าเป็นชื่อนั้นจริง → คำชี้แจงและความหมายของ +1/0/−1 → ประเมินทีละข้อพร้อมบันทึกร่างอัตโนมัติ → ทบทวนก่อนส่ง → ลงนามและข้อเสนอแนะภาพรวม → ส่ง แล้วหน้ากลายเป็นอ่านอย่างเดียวพร้อมปุ่มดาวน์โหลดสำเนาของตัวเอง ครูเปิดให้แก้ใหม่ได้ถ้าผู้ทรงขอ

ผู้ทรงส่วนใหญ่จะเปิดลิงก์จาก LINE บนมือถือ หน้านี้จึงเป็นการ์ดทีละข้อบนจอแคบ ไม่ใช่ตารางกว้างย่อส่วน และต้องคุมขนาด JavaScript เพราะเป็น public route — โหลด KaTeX เฉพาะเมื่อข้อนั้นมีคณิตศาสตร์จริง

## ฐานข้อมูลที่เสนอ

ตั้งชื่อด้วยคำนำหน้า `ioc_` ไม่ใช่ `education_research_ioc_` เพราะฟอร์มมีชีวิตอยู่ได้โดยไม่มีโครงการวิจัย ทุกตารางมี `org_id` และ RLS แบบเดียวกับตาราง `education_research_*` ที่มีอยู่

| ตาราง | เก็บอะไร | หมายเหตุ |
| --- | --- | --- |
| `ioc_forms` | หัวเอกสาร · แหล่งข้อสอบ · เกณฑ์และกฎร้อยละ · สถานะ · ย่อหน้าสรุปที่ครูแก้ · ลายเซ็นครู | `project_id`, `assignment_id`, `measurement_id` เป็น nullable ทั้งหมด · `status` ∈ draft / collecting / closed |
| `ioc_form_standards` | มาตรฐานและตัวชี้วัดของฟอร์ม (รหัส + ข้อความ + ลำดับ) | ทำให้ช่องตัวชี้วัดผสานแถวในเอกสารได้ และไม่เก็บข้อความซ้ำ |
| `ioc_form_items` | สำเนาข้อสอบที่ตรึงไว้ · เลขข้อที่พิมพ์ · หัวข้อตอน · โจทย์ร่วม · `standard_id` | อ้าง `source_question_id` ไว้ดูที่มา แต่เนื้อหาที่พิมพ์มาจากสำเนา |
| `ioc_form_experts` | ชื่อ ตำแหน่ง หน่วยงาน ลำดับ · hash ของ token · วันหมดอายุ · สถานะ · ข้อเสนอแนะภาพรวม · ลายเซ็น | `UNIQUE (form_id, expert_order)` |
| `ioc_ratings` | คะแนน −1/0/+1 และข้อเสนอแนะรายข้อ | `UNIQUE (expert_id, item_id)` · `CHECK (score BETWEEN -1 AND 1)` |
| `ioc_form_events` | append-only: เปิดลิงก์ ส่งผล เพิกถอน ต่ออายุ เปิดให้แก้ใหม่ ส่งออก | ตามแบบ `education_research_export_events` · ไม่เก็บข้อมูลนักเรียน |

**ตรึงสำเนาข้อสอบ** คัดลอกเนื้อข้อสอบลง `ioc_form_items` ตอนเปิดฟอร์มให้ผู้ทรง ตามหลัก immutable snapshot ที่โมดูลวิจัยใช้อยู่ (`questions.is_research_snapshot` และ trigger `protect_education_research_snapshot_question`) เหตุผลตรงไปตรงมา: ผู้ทรงลงนามรับรองข้อสอบฉบับใด เอกสารต้องเป็นฉบับนั้นตลอดไป แม้ครูจะไปแก้โจทย์ในคลังวันรุ่งขึ้น

**ลายเซ็น** เก็บเป็น PNG ใน bucket ส่วนตัว `ioc-signatures` จำกัดขนาดต่อไฟล์ และอัปโหลดผ่าน server action ที่ตรวจ token แล้วเท่านั้น ไม่เปิดให้เขียน Storage โดยตรงจากเบราว์เซอร์ที่ไม่ได้ล็อกอิน ลายเซ็นครูเก็บแบบใช้ซ้ำได้ต่อบัญชี เพื่อไม่ต้องวาดใหม่ทุกฟอร์ม

## สิทธิ์และความปลอดภัย

**ไม่เปิด policy `TO anon` แม้แต่ข้อเดียว** ทั้ง repository ยังไม่มีเลย และฟีเจอร์นี้จะไม่เป็นข้อแรก หน้า `/ioc/[token]` ทำงานแบบเดียวกับ `acceptClassroomInvitation`: server ตรวจ token ก่อน แล้วอ่าน/เขียนผ่าน `createAdminClient()` ทุกตารางสั่ง `REVOKE ALL ... FROM anon`

**token** สุ่ม 32 ไบต์ เก็บเฉพาะ SHA-256 ในฐานข้อมูลและค้นด้วย hash ของค่าที่ผู้ใช้ส่งมา ลิงก์ที่หลุดจากฐานข้อมูลจึงไม่มีอยู่ อายุตั้งต้น 30 วัน ต่ออายุและเพิกถอนได้ ทุกกรณีที่ตรวจไม่ผ่าน — ไม่มี หมดอายุ ถูกเพิกถอน — ตอบด้วยหน้าเดียวกันว่าลิงก์ใช้ไม่ได้แล้ว ให้ขอลิงก์ใหม่จากครู ไม่บอกว่าเพราะอะไร

**ลิงก์ IOC คือข้อสอบฉบับเต็มที่ออกไปอยู่นอกระบบ** นี่คือความเสี่ยงที่ต้องยอมรับอย่างรู้ตัว เพราะขัดกับงานคุมสอบ SEB และลายน้ำที่เพิ่งทำไป มาตรการที่ต้องมีตั้งแต่วันแรก

- ลิงก์หมดอายุ และปิดอัตโนมัติเมื่อผู้ทรงส่งผลแล้ว
- `noindex` บนหน้า และไม่ cache
- ลายน้ำ "สำเนาเพื่อประเมินความสอดคล้อง" ทั้งบนหน้าจอและบนเอกสารที่ส่งออก
- เตือนครูก่อนคัดลอกลิงก์ว่าไฟล์นี้มีข้อสอบทั้งฉบับ และเตือนแรงขึ้นถ้าข้อสอบชุดนั้นยังเปิดให้นักเรียนทำอยู่
- บันทึกการเปิดลิงก์ไว้ใน `ioc_form_events`

**เฉลยต้องไม่หลุดไปกับฟอร์ม** สำเนาโจทย์มี `answer_formula` และ `solution_text` ติดมาด้วย ค่าตั้งต้นคือไม่ส่งเฉลยไปถึงเบราว์เซอร์ของผู้ทรงเลย ไม่ใช่ส่งไปแล้วซ่อนด้วย CSS — หลักเดียวกับที่ `271e777` เขียนไว้ว่าเฉลยที่ถูกกันไว้ต้องไม่ไปถึงเบราว์เซอร์ มีสวิตช์ "ให้ผู้ทรงเห็นแนวคำตอบ" สำหรับครูที่ต้องการ ปิดไว้เป็นค่าตั้งต้น

**ไม่มีข้อมูลนักเรียนในโมดูลนี้** ฟอร์ม IOC อ่านเฉพาะโจทย์ ไม่อ่าน roster คะแนน หรือคำตอบ ข้อนี้เขียนไว้เพื่อให้การตรวจความปลอดภัยครั้งหน้ายืนยันได้เร็ว

ทำด้วยหน้าพิมพ์ A4 ที่ `/research/ioc/[formId]/print` แล้วผู้ใช้สั่งพิมพ์หรือบันทึกเป็น PDF

| ฉบับรายผู้ทรง | ผลที่ผู้ทรงท่านนั้นประเมิน พร้อมข้อเสนอแนะและลายเซ็นของท่าน |

**ตัวเลือกตอนส่งออก** แทรกลายเซ็นครู · แทรกลายเซ็นผู้ทรงเลือกเป็นรายคน · เว้นเส้นประไว้เซ็นจริง · แสดง/ซ่อนคอลัมน์ข้อเสนอแนะ · พิมพ์เกณฑ์และกฎร้อยละกำกับท้ายตาราง

**ข้อกำหนดทางช่าง**

- แบ่งหน้าเองเป็นกล่องขนาด 210×297 มม. ไม่ปล่อยให้เบราว์เซอร์แบ่ง เพราะ Chrome ไม่รองรับ `@top-center`/`@bottom-center` จึงพิมพ์เลขหน้า "หน้า x จาก y" เองไม่ได้ถ้าไม่คุมการแบ่งหน้า
- หัวตารางซ้ำทุกหน้าด้วย `<thead>` และกันข้อสอบขาดครึ่งด้วย `break-inside: avoid`
- ฟอนต์ `Sarabun` จาก `next/font/google` โหลดเฉพาะเส้นทางพิมพ์ ไม่ไปเพิ่มน้ำหนักให้หน้าอื่น เว็บทั้งระบบใช้ IBM Plex Sans Thai ซึ่งอ่านดีบนจอแต่ไม่ใช่ฟอนต์ที่เอกสารราชการไทยใช้ (ถ้าโรงเรียนยืนยันว่าต้อง TH Sarabun New ตัวจริง ค่อยพิจารณา self-host ภายหลัง)
- บันทึกเหตุการณ์ส่งออกแบบ append-only เหมือน `education_research_export_events`

**เรื่องนี้ไม่ขัดกับการเลิกใช้เส้นทางกระดาษ** `bdafbca` เลิกใช้โหมดพิมพ์ของงานที่มอบหมาย เพราะครูที่ได้ไฟล์ข้อสอบไปพิมพ์ไม่มีเหตุผลต้องกลับมาที่เว็บอีก ฟอร์ม IOC ต่างออกไป: การกรอกและการคำนวณอยู่บนเว็บทั้งหมด เอกสารเป็นผลลัพธ์ปลายทางที่กรรมการต้องได้เป็นกระดาษหรือไฟล์แนบ ไม่ใช่ทางเลือกแทนการใช้เว็บ

## ต่อยอดที่เตรียมทางไว้

- **ตัวชี้วัดติดไปกับโจทย์** เมื่อครูระบุว่าข้อนี้วัดตัวชี้วัดใด ควรจำไว้ที่โจทย์ในคลัง ฟอร์มครั้งถัดไปจะเติมให้เอง และเปิดทางไปทำผังข้อสอบ (Table of Specifications) ซึ่งเป็นอีกเอกสารที่ครูต้องทำมือทุกเทอม — นี่คือจุดที่ประหยัดเวลาครูที่สุดในระยะยาว ต้องตัดสินใจเรื่องที่เก็บข้อมูลก่อนเริ่มเฟส 2 เพราะกระทบ schema
- **แท็บคุณภาพเครื่องมือ** `lib/question-stats.ts` คำนวณค่าความยาก (p) และอำนาจจำแนก (point-biserial) ได้อยู่แล้ว IOC เป็นหลักฐานก่อนสอบ ค่าความยาก/อำนาจจำแนกเป็นหลักฐานหลังสอบ เพิ่มความเชื่อมั่น (KR-20 / α) อีกชิ้นก็ครบบท "คุณภาพเครื่องมือ" ของรายงานวิจัยไทยทั้งบท
- **แบบประเมินชนิดอื่นด้วยกลไกเดียวกัน** ลิงก์ + ลายเซ็น + สรุปอัตโนมัติ ใช้ซ้ำกับแบบประเมินความเหมาะสมของแผนการสอน นวัตกรรม และแบบสอบถามแบบ 5 ระดับได้

## เรื่องที่ยังรอเจ้าของผลิตภัณฑ์ยืนยัน

1. ให้ผู้ทรงเห็นแนวคำตอบหรือเฉลยได้ไหม — ข้อเสนอคือมีสวิตช์และปิดไว้เป็นค่าตั้งต้น
2. เก็บตัวชี้วัดไว้ที่โจทย์ในคลังเพื่อให้ฟอร์มครั้งถัดไปเติมให้เองหรือไม่ — กระทบ schema ต้องตอบก่อนเฟส 2
3. ลิงก์ผู้ทรงควรมีอายุกี่วันเป็นค่าตั้งต้น ข้อเสนอคือ 30 วัน
4. เมื่อผู้ทรงส่งครบแล้ว ควรล็อกฟอร์มเป็น "ฉบับสมบูรณ์" โดยเก็บ hash ของเนื้อหาไว้อ้างอิงหรือไม่
