## ปัญหาที่แก้

ครูที่ออกข้อสอบหนึ่งฉบับต้องทำงานซ้ำสี่อย่างทุกภาคเรียน

1. ทำฟอร์ม IOC ใน Word — คัดลอกข้อสอบทั้งฉบับลงตารางด้วยมือ จัดคอลัมน์ +1/0/−1 ให้ไม่แตกข้ามหน้า
2. พิมพ์แจกผู้ทรงคุณวุฒิหรือส่งไฟล์ให้ แล้วรอรับคืน
3. คำนวณดัชนีความสอดคล้องรายข้อด้วยเครื่องคิดเลข
4. ทำตารางสรุปอีกใบ พร้อมย่อหน้าสรุปผลและร้อยละความสอดคล้อง

ข้อ 1 เว็บทำให้ได้ทันทีเพราะรู้อยู่แล้วว่าข้อสอบคือข้อไหน ข้อ 3 กับ 4 เป็นเลขคณิตที่เครื่องควรคิด ส่วนข้อ 2 ย่นลงเป็นลิงก์ได้ เหลือเพียงงานที่ต้องเป็นครูทำเองคือการระบุว่าข้อสอบข้อไหนวัดตัวชี้วัดตัวใด

## เอกสารต้นแบบ

อ้างจากไฟล์ที่เจ้าของผลิตภัณฑ์ให้ไว้: IOC ของแบบทดสอบกลางภาคเรียนที่ 2 คณิตศาสตร์พื้นฐาน 6 (ค 33102) ชั้น ม.6 จำนวน 11 ข้อ ผู้ทรงคุณวุฒิ 3 ท่าน ทั้งไฟล์มี 5 หน้า แยกเป็นสามชนิด

| ชนิดหน้า | ในไฟล์ต้นแบบ | เนื้อหาที่ต้องผลิตซ้ำให้ได้ |
| --- | --- | --- |
| หัวเอกสาร + คำชี้แจง | หน้า 1 | ชื่อเรื่อง IOC · ช่วงสอบ/รายวิชา/รหัสวิชา/ชั้น · โรงเรียน · คำชี้แจง · ความหมายของ +1 / 0 / −1 |
| ตารางประเมิน | หน้า 1–3 | มาตรฐานตัวชี้วัด · แบบทดสอบ · ค่าความสอดคล้อง (+1 / 0 / −1) · ข้อเสนอแนะ |
| หน้าลายเซ็น | หน้า 4 | เส้นประ + ชื่อในวงเล็บ ของผู้ออกข้อสอบ และผู้ประเมินคนที่ 1–3 |
| ตารางสรุป | หน้า 5 | ร้อยละความสอดคล้อง · ย่อหน้าสรุปผลการประเมิน · ตาราง: ตัวชี้วัด / ข้อที่ / ผลการประเมิน (คน) สอดคล้อง-ไม่แน่ใจ-ไม่สอดคล้อง / ดัชนีความสอดคล้อง |

**จุดที่แก้จากต้นแบบ** ต้นแบบมีคอลัมน์ "ผู้เชี่ยวชาญคนที่" ที่แตกทุกข้อออกเป็นสามแถว (1, 2, 3) ในฉบับเดียว ซึ่งเป็นความสับสนของเอกสารต้นทาง เพราะผู้ทรงแต่ละท่านต้องประเมินแยกกัน คอลัมน์นี้ถูกตัดออก และแทนที่ด้วยหลักที่ชัดกว่า

> **หนึ่งฉบับ = หนึ่งผู้ทรงคุณวุฒิ** หนึ่งข้อสอบจึงมีหนึ่งแถว และหน้าลายเซ็นของฉบับนั้นมีเฉพาะผู้ออกข้อสอบกับผู้ประเมินท่านนั้น ส่วนหน้าลายเซ็นรวมทุกท่านใช้เมื่อส่งออกเป็นเล่ม

สิ่งที่ต้นแบบบอกเราเพิ่มอีกสองอย่างและต้องรักษาไว้ในฟอร์มที่เว็บสร้าง

- **หัวข้อตอน** — "ตอนที่ 1 ข้อสอบปรนัย 4 ตัวเลือก" และ "ตอนที่ 2 ข้อสอบอัตนัย" มีอยู่ในระบบแล้วเป็น `question_set_sections`
- **โจทย์ร่วมของหลายข้อ** — ตารางแจกแจงความถี่ที่ตามด้วย "จงตอบคำถาม 3 ข้อดังต่อไปนี้" ตรงกับโจทย์ที่มี `group_id` เดียวกันในคลัง ทั้งสองอย่างดึงมาใช้ได้โดยครูไม่ต้องพิมพ์ใหม่

## ขอบเขตที่ตกลงแล้ว

เจ้าของผลิตภัณฑ์เคาะสี่ข้อนี้เมื่อ 13 กันยายน 2569

1. **ส่งออก PDF ด้วยหน้าพิมพ์ A4 ของเบราว์เซอร์** ไม่เพิ่ม PDF library และไม่ใช้ headless Chrome บนเซิร์ฟเวอร์ เหตุผลคือภาษาไทย: `pdf-lib` และ `pdfmake` วางสระกับวรรณยุกต์ซ้อนผิดตำแหน่งเพราะไม่ทำ GPOS mark positioning และตัดบรรทัดคำไทยที่ไม่มีช่องว่างไม่ได้ ขณะที่เบราว์เซอร์ทำทั้งสองอย่างถูกต้องอยู่แล้ว เว็บนี้มีแบบอย่างอยู่แล้วที่ `app/(app)/classrooms/[id]/report`
2. **ฟอร์ม IOC ใช้ได้ทั้งกับโครงการวิจัยและข้อสอบทั่วไป** ไฟล์ต้นแบบเองเป็นข้อสอบกลางภาคปกติ ไม่ใช่งานวิจัย ดังนั้น `ioc_forms.project_id` เป็น nullable ตั้งแต่ migration แรก
3. **ลิงก์แยกต่อผู้ทรงหนึ่งคนหนึ่งลิงก์ ครูใส่ชื่อไว้ก่อน** ชื่อจึงไหลไปหน้าลายเซ็นและตารางสรุปได้เองแบบเอกสารต้นแบบ และแดชบอร์ดรู้ว่าใครส่งแล้วใครยังไม่ส่ง
4. **เกณฑ์ตั้งต้น 0.50 และร้อยละความสอดคล้องคิดจากจำนวนข้อที่ผ่านเกณฑ์** ครูเปลี่ยนได้ทั้งสองค่า และเอกสารที่ส่งออกพิมพ์กำกับไว้ว่าใช้เกณฑ์เท่าไรและคิดร้อยละด้วยกฎใด

## สิ่งที่ไม่อยู่ในรุ่นแรก

- มาตรวัด 5 ระดับ และแบบประเมินชนิดอื่น (แผนการสอน นวัตกรรม แบบสอบถาม) — กลไกเดียวกันต่อยอดได้ แต่ไม่ทำในรุ่นแรก
- ไม่มี AI เดาตัวชี้วัดให้ ครูเป็นผู้ระบุเอง
- **เว็บไม่ส่งอีเมลหรือข้อความหาผู้ทรงเอง** ยังไม่มีระบบส่งอีเมลของผลิตภัณฑ์นอกจากอีเมลของ Supabase Auth ครูคัดลอกลิงก์หรือ QR ไปส่งทางช่องทางของตัวเอง และหน้าจอจะไม่พูดว่า "ส่งอีเมลแล้ว"
- ไม่ใช่ลายมือชื่ออิเล็กทรอนิกส์ที่รับรองตามกฎหมาย เป็นเพียงภาพลายเซ็นที่ผู้ลงนามยินยอมให้ใช้ในเอกสารฉบับนั้น หน้าจอและเอกสารห้ามอ้างการรับรองทางกฎหมายหรือมาตรฐานใด ๆ
- ไม่คำนวณความเชื่อมั่น (KR-20 / α) ในรุ่นนี้ — ดู "ต่อยอดที่เตรียมทางไว้"

## สูตรและกฎการคำนวณ

กฎทั้งหมดอยู่ใน `lib/ioc.ts` เป็น pure function มี vitest ครอบ และไม่มีการคำนวณซ้ำในหน้าเว็บหรือในเอกสารส่งออก

**ดัชนีความสอดคล้องรายข้อ**

```
IOC(i) = ΣR(i,j) / N(i)
```

- `R(i,j) ∈ {+1, 0, −1}` คะแนนที่ผู้ทรงคนที่ `j` ให้ข้อ `i` · +1 แน่ใจว่าสอดคล้อง · 0 ไม่แน่ใจ · −1 แน่ใจว่าไม่สอดคล้อง
- `N(i)` = จำนวนผู้ทรงที่ **ส่งผลแล้วและให้คะแนนข้อนั้น** ไม่ใช่จำนวนผู้ทรงที่ถูกเชิญ
- ค่าอยู่ในช่วง −1.00 ถึง 1.00 แสดงผลสองตำแหน่งทศนิยมตามเอกสารต้นแบบ
- **ไม่ปัดค่าดัชนีก่อนเทียบเกณฑ์** แต่ขยายการเทียบออกครึ่งหลักของที่แสดง (`IOC_COMPARISON_TOLERANCE = 0.005`) เพราะครูพิมพ์เกณฑ์ด้วยทศนิยมสองตำแหน่งชุดเดียวกับที่เอกสารพิมพ์ค่าดัชนี · ถ้าเทียบตรง ๆ ข้อที่ผู้ทรง 3 ท่านเห็นตรงกัน 2 ใน 3 จะได้ 0.6666… ซึ่ง "น้อยกว่า" เกณฑ์ 0.67 ที่ครูพิมพ์ตามค่าที่เห็นบนกระดาษ แล้วตกเกณฑ์ทั้งที่ควรผ่าน · การขยายนี้ไม่ช่วยข้อที่ตกจริง: 0.33 ยังคงตกเกณฑ์ 0.50 ห่างมาก
- ผ่านเมื่อ `IOC(i) ≥ threshold` ค่าตั้งต้น 0.50

ที่มาของเกณฑ์: วิธีนี้ Rovinelli และ Hambleton (1977) ปรับมาจาก Hemphill และ Westie (1950) ตำราไทยที่ครูอ้างกันใช้ 0.50 ขึ้นไป ส่วนงานต่างประเทศหลายชิ้นใช้ 0.67 ข้อสังเกตที่ต้องเขียนไว้ในคำอธิบายบนหน้าจอ: **ถ้ามีผู้ทรง 3 ท่าน ค่าที่เป็นไปได้มีแค่ 1.00, 0.67, 0.33, 0.00 ลงไป ดังนั้นเกณฑ์ 0.50 กับ 0.67 ให้ผลเหมือนกันทุกกรณี** ความต่างเกิดเมื่อมีผู้ทรง 4 ท่านขึ้นไป

**ผลการประเมิน (คน)** นับจำนวนผู้ทรงที่ให้ +1, 0 และ −1 ของข้อนั้นตรง ๆ สามตัวเลขนี้ต้องรวมกันได้เท่ากับ `N(i)` เสมอ ถ้าไม่เท่าให้ถือเป็นบั๊กไม่ใช่ข้อมูล

**ร้อยละความสอดคล้อง** สองกฎ เลือกได้ตอนสร้างฟอร์ม

- `items_passing` (ตั้งต้น) = จำนวนข้อที่ผ่านเกณฑ์ ÷ จำนวนข้อทั้งหมด × 100
- `mean_index` = ค่าเฉลี่ย IOC ทุกข้อ × 100

ในไฟล์ต้นแบบทุกข้อได้ 1.00 พอดี ทั้งสองกฎจึงให้ 100.00 เท่ากัน แยกไม่ออกจากตัวอย่าง เอกสารที่ส่งออกต้องพิมพ์ว่าใช้กฎใด ไม่ปล่อยให้กรรมการเดา

**กรณีที่ห้ามคำนวณเงียบ ๆ**

| กรณี | สิ่งที่ต้องทำ |
| --- | --- |
| ผู้ทรงข้ามบางข้อ | `N(i)` ต่างกันได้ระหว่างข้อ · แสดงหมายเหตุว่าข้อนั้นคิดจากกี่คน · ไม่แทนข้อที่ข้ามด้วย 0 |
| ผู้ทรงยังส่งไม่ครบ | แสดงผลได้ แต่ติดป้าย "ผลชั่วคราว" ทั้งบนหน้าจอและบนเอกสารที่ส่งออก |
| ผู้ทรงน้อยกว่า 3 ท่าน | เตือนว่าจำนวนผู้ทรงต่ำกว่าที่งานวิจัยทั่วไปใช้ · ไม่ห้าม |
| ผู้ทรงเป็นจำนวนคู่ | เตือนว่าค่าอาจออกมาคาบเกณฑ์พอดี · ไม่ห้าม |
| ไม่มีคะแนนเลยในข้อหนึ่ง | ดัชนีเป็น "—" ไม่ใช่ 0.00 และข้อนั้นไม่ถูกนับเป็นผ่านหรือไม่ผ่าน แต่ยังอยู่ในตัวหารของร้อยละ |
| ยังไม่มีใครส่งผลเลยทั้งฟอร์ม | ร้อยละเป็น "—" ไม่ใช่ 0.00% เพราะ 0.00% อ่านเหมือนผลที่แย่มาก ไม่ใช่ผลที่ยังไม่มี |

**ย่อหน้าสรุปผลการประเมิน** ระบบเติมตัวเลขจริงลงแม่แบบข้อความ ครูแก้ถ้อยคำได้ แต่ตัวเลขในย่อหน้ามาจากการคำนวณเท่านั้น ถ้าครูแก้ตัวเลขเองระบบจะไม่ตามไปแก้ให้ จึงเก็บข้อความที่ครูแก้แยกจากตัวเลข และเตือนเมื่อคะแนนเปลี่ยนหลังจากครูแก้ย่อหน้าไปแล้ว

1. **หัวเอกสาร** — ชื่อแบบทดสอบ/ช่วงสอบ รายวิชา รหัสวิชา ชั้น ภาคเรียน ปีการศึกษา โรงเรียน ชื่อผู้ออกข้อสอบ เติมค่าตั้งต้นจากองค์กร ห้องเรียน และโปรไฟล์ครูให้ก่อน
2. **เลือกข้อสอบ** — สามทาง: ข้อสอบก่อนเรียน/หลังเรียนของโครงการวิจัย · งานที่มอบหมายในห้องเรียน · แฟ้มและคลังโจทย์ เมื่อเลือกแล้วระบบคัดลอกโจทย์ หัวข้อตอน โจทย์ร่วม และเลขข้อมาให้ครบ
3. **มาตรฐานและตัวชี้วัด** — งานที่ครูต้องทำเอง มีเครื่องมือทุ่นแรง: สร้างรายการตัวชี้วัดของฟอร์มไว้ก่อนแล้วจ่ายให้หลายข้อพร้อมกัน · "ใช้ค่าเดียวกับข้อก่อนหน้า" · วางข้อความตัวชี้วัดเป็นก้อนแล้วให้ระบบแยกบรรทัด
4. **ผู้ทรงคุณวุฒิและลายเซ็นครู** — ใส่ชื่อผู้ทรงตามลำดับ "ผู้ประเมินคนที่ 1…N" เลือกวิธีลงนามของครู แล้วกดสร้างลิงก์

ตัวชี้วัดหนึ่งตัวมักครอบหลายข้อ เอกสารต้นแบบจึงผสานช่องตัวชี้วัดเป็นช่องเดียวคร่อมหลายแถว ฐานข้อมูลรองรับเรื่องนี้ด้วยการแยกตัวชี้วัดเป็นตารางของตัวเองแล้วให้ข้อสอบอ้างถึง ไม่ใช่เก็บข้อความซ้ำทุกแถว

**หน้าผู้ทรงคุณวุฒิ** เปิดจากลิงก์ → ยืนยันว่าเป็นชื่อนั้นจริง → คำชี้แจงและความหมายของ +1/0/−1 → ประเมินทีละข้อพร้อมบันทึกร่างอัตโนมัติ → ทบทวนก่อนส่ง → ลงนามและข้อเสนอแนะภาพรวม → ส่ง แล้วหน้ากลายเป็นอ่านอย่างเดียวพร้อมปุ่มดาวน์โหลดสำเนาของตัวเอง ครูเปิดให้แก้ใหม่ได้ถ้าผู้ทรงขอ

ผู้ทรงส่วนใหญ่จะเปิดลิงก์จาก LINE บนมือถือ หน้านี้จึงเป็นการ์ดทีละข้อบนจอแคบ ไม่ใช่ตารางกว้างย่อส่วน และต้องคุมขนาด JavaScript เพราะเป็น public route — โหลด KaTeX เฉพาะเมื่อข้อนั้นมีคณิตศาสตร์จริง

## ฐานข้อมูล

อยู่ใน `supabase/migrations/20260913135353_ioc_forms_foundation.sql` ตั้งชื่อด้วยคำนำหน้า `ioc_` ไม่ใช่ `education_research_ioc_` เพราะฟอร์มมีชีวิตอยู่ได้โดยไม่มีโครงการวิจัย ทุกตารางมี `org_id` และ RLS แบบเดียวกับตาราง `education_research_*` ที่มีอยู่

| ตาราง | เก็บอะไร | หมายเหตุ |
| --- | --- | --- |
| `ioc_forms` | หัวเอกสาร · แหล่งข้อสอบ · เกณฑ์และกฎร้อยละ · สถานะ · ย่อหน้าสรุปที่ครูแก้ · ลายเซ็นครู | `project_id`, `assignment_id`, `measurement_id` เป็น nullable ทั้งหมด · `status` ∈ draft / collecting / closed |
| `ioc_form_standards` | มาตรฐานและตัวชี้วัดของฟอร์ม (รหัส + ข้อความ + ลำดับ) | ทำให้ช่องตัวชี้วัดผสานแถวในเอกสารได้ และไม่เก็บข้อความซ้ำ |
| `ioc_form_items` | สำเนาข้อสอบที่ตรึงไว้ · เลขข้อที่พิมพ์ · หัวข้อตอน · โจทย์ร่วม · `standard_id` | อ้าง `source_question_id` ไว้ดูที่มา แต่เนื้อหาที่พิมพ์มาจากสำเนา |
| `ioc_form_experts` | ชื่อ ตำแหน่ง หน่วยงาน ลำดับ · hash ของ token · วันหมดอายุ · สถานะ · ข้อเสนอแนะภาพรวม · ลายเซ็น | `UNIQUE (form_id, expert_order)` |
| `ioc_ratings` | คะแนน −1/0/+1 และข้อเสนอแนะรายข้อ | `UNIQUE (expert_id, item_id)` · `CHECK (score BETWEEN -1 AND 1)` |
| `ioc_form_events` | append-only: เปิดลิงก์ ส่งผล เพิกถอน ต่ออายุ เปิดให้แก้ใหม่ ส่งออก | ตามแบบ `education_research_export_events` · ไม่เก็บข้อมูลนักเรียน |

**ตรึงสำเนาข้อสอบ** คัดลอกเนื้อข้อสอบลง `ioc_form_items` ตอนเปิดฟอร์มให้ผู้ทรง ตามหลัก immutable snapshot ที่โมดูลวิจัยใช้อยู่ (`questions.is_research_snapshot` และ trigger `protect_education_research_snapshot_question`) เหตุผลตรงไปตรงมา: ผู้ทรงลงนามรับรองข้อสอบฉบับใด เอกสารต้องเป็นฉบับนั้นตลอดไป แม้ครูจะไปแก้โจทย์ในคลังวันรุ่งขึ้น

**ลายเซ็น** เก็บเป็น PNG ใน bucket ส่วนตัว `ioc-signatures` จำกัดขนาดต่อไฟล์ และอัปโหลดผ่าน server action ที่ตรวจ token แล้วเท่านั้น ไม่เปิดให้เขียน Storage โดยตรงจากเบราว์เซอร์ที่ไม่ได้ล็อกอิน ลายเซ็นครูเก็บแบบใช้ซ้ำได้ต่อบัญชี เพื่อไม่ต้องวาดใหม่ทุกฟอร์ม

## สิทธิ์และความปลอดภัย

**ไม่เปิด policy `TO anon` แม้แต่ข้อเดียว** ทั้ง repository ยังไม่มีเลย และฟีเจอร์นี้จะไม่เป็นข้อแรก หน้า `/ioc/[token]` ทำงานแบบเดียวกับ `acceptClassroomInvitation`: server ตรวจ token ก่อน แล้วอ่าน/เขียนผ่าน `createAdminClient()` ทุกตารางสั่ง `REVOKE ALL ... FROM anon`

**token** สุ่ม 32 ไบต์ เก็บเฉพาะ SHA-256 ในฐานข้อมูลและค้นด้วย hash ของค่าที่ผู้ใช้ส่งมา ลิงก์ที่หลุดจากฐานข้อมูลจึงไม่มีอยู่ อายุตั้งต้น 30 วัน ต่ออายุและเพิกถอนได้ ทุกกรณีที่ตรวจไม่ผ่าน — ไม่มี หมดอายุ ถูกเพิกถอน — ตอบด้วยหน้าเดียวกันว่าลิงก์ใช้ไม่ได้แล้ว ให้ขอลิงก์ใหม่จากครู ไม่บอกว่าเพราะอะไร

**ลิงก์ IOC คือข้อสอบฉบับเต็มที่ออกไปอยู่นอกระบบ** นี่คือความเสี่ยงที่ต้องยอมรับอย่างรู้ตัว เพราะขัดกับงานคุมสอบ SEB และลายน้ำที่เพิ่งทำไป มาตรการที่ต้องมีตั้งแต่วันแรก

- ลิงก์หมดอายุ และปิดอัตโนมัติเมื่อผู้ทรงส่งผลแล้ว
- `noindex` บนหน้า และไม่ cache
- ลายน้ำ "สำเนาเพื่อประเมินความสอดคล้อง" ทั้งบนหน้าจอและบนเอกสารที่ส่งออก
- เตือนครูก่อนคัดลอกลิงก์ว่าไฟล์นี้มีข้อสอบทั้งฉบับ และเตือนแรงขึ้นถ้าข้อสอบชุดนั้นยังเปิดให้นักเรียนทำอยู่
- บันทึกการเปิดลิงก์ไว้ใน `ioc_form_events`

**เฉลยต้องไม่หลุดไปกับฟอร์ม** สำเนาโจทย์มี `answer_formula` และ `solution_text` ติดมาด้วย ค่าตั้งต้นคือไม่ส่งเฉลยไปถึงเบราว์เซอร์ของผู้ทรงเลย ไม่ใช่ส่งไปแล้วซ่อนด้วย CSS — หลักเดียวกับที่ `271e777` เขียนไว้ว่าเฉลยที่ถูกกันไว้ต้องไม่ไปถึงเบราว์เซอร์ มีสวิตช์ "ให้ผู้ทรงเห็นแนวคำตอบ" สำหรับครูที่ต้องการ ปิดไว้เป็นค่าตั้งต้น

**ไม่มีข้อมูลนักเรียนในโมดูลนี้** ฟอร์ม IOC อ่านเฉพาะโจทย์ ไม่อ่าน roster คะแนน หรือคำตอบ ข้อนี้เขียนไว้เพื่อให้การตรวจความปลอดภัยครั้งหน้ายืนยันได้เร็ว

## สิ่งที่ระยะ 1 ทำแล้ว

**`lib/ioc.ts` กับ `lib/ioc.test.ts`** — คณิตศาสตร์ทั้งหมดอยู่ที่นี่ที่เดียว ทั้งหน้าเว็บและเอกสารที่ส่งออกต้องอ่านตัวเลขจากโมดูลนี้ ห้ามคำนวณซ้ำที่อื่น เทสต์ 22 เคสครอบ: ค่าดัชนีรายข้อ, การเทียบเกณฑ์แบบมีระยะผ่อน, เกณฑ์ที่เป็นไปได้จริงตามจำนวนผู้ทรง (`effectiveIocThreshold`), ร้อยละสองกฎ, ผู้ทรงที่ยังไม่ส่ง, ข้อที่ไม่มีใครประเมิน, คำเตือนทั้งสี่แบบ และข้อมูลที่ผิดจนต้องโยน error · ชุดตัวอย่างในเทสต์เป็นชุดเดียวกับที่วาดในภาพร่าง (ผู้ทรง 3 ท่าน 11 ข้อ ตก 2 ข้อ ร้อยละ 81.82) เพื่อให้หน้าจอ เอกสาร และเลขคณิตตรวจกันเองได้

**`supabase/migrations/20260913135353_ioc_forms_foundation.sql`** — 6 ตาราง (`ioc_forms`, `ioc_form_standards`, `ioc_form_items`, `ioc_form_experts`, `ioc_ratings`, `ioc_form_events`), bucket `ioc-signatures` แบบส่วนตัวจำกัด PNG 256 KB, RLS ครบทุกตาราง, `can_manage_ioc_form()` และ `record_ioc_form_event()` ที่ให้เฉพาะ service role เรียก

สิ่งที่บังคับไว้ใต้ RLS เพราะเส้นทางของผู้ทรงทำงานด้วย service role ซึ่ง RLS ไม่คุม

- **ข้อสอบและตัวชี้วัดแก้ไม่ได้หลัง `items_frozen_at`** — trigger บล็อกทั้ง insert, update และ delete ของ `ioc_form_items`/`ioc_form_standards` เมื่อฟอร์มถูกตรึงแล้ว แต่ยอมให้ผ่านเมื่อแถวแม่หายไปแล้ว ซึ่งคือกรณีลบทั้งฟอร์มแล้ว cascade ตามลงมา
- **คะแนนของผู้ทรงที่ส่งแล้วแก้ไม่ได้** จนกว่าครูจะเปิดให้แก้ใหม่ (ย้ายสถานะกลับเป็น `opened` และบันทึกเป็นเหตุการณ์)
- **ฟอร์มจะเป็น `collecting` ไม่ได้ถ้ายังไม่ตรึงข้อสอบ** ผู้ทรงจึงไม่มีทางเห็นข้อที่ยังแก้อยู่
- **token เก็บเฉพาะ SHA-256** และต้องมีวันหมดอายุคู่เสมอ · ไม่มี policy ของ `anon` แม้แต่ข้อเดียวในทั้ง migration
- **`record_ioc_form_event()` ปฏิเสธ detail ที่มีคีย์ `token`, `token_hash` หรือ `signature`** เพื่อไม่ให้ของที่ตั้งใจปกปิดไหลกลับเข้าสู่ audit trail

สิ่งที่ยังไม่ได้ทำในระยะนี้ ตั้งใจทั้งหมด

- **ยังไม่ได้ apply migration กับฐานข้อมูลจริง** ไฟล์อยู่ใน repo แต่ schema จริงยังไม่มีตารางเหล่านี้
- ไม่มี route, server action, type ของแถวในฐานข้อมูล หรือหน้าจอใดเรียกใช้ — ทั้งหมดเป็นงานระยะ 2 ขึ้นไป
- ยังไม่มีการทดสอบ RLS, trigger และ constraint กับฐานข้อมูลจริง เพราะเครื่องที่พัฒนาไม่มี Docker จึงรัน Postgres ในเครื่องไม่ได้ · ตรวจได้เท่าที่ทำคือโครงสร้างไฟล์ SQL และตารางปลายทางของ foreign key ทุกตัวมีอยู่จริงใน schema นี้

**server action** `lib/actions/ioc-forms.ts` — สร้าง/แก้หัวเอกสาร, เลือกแหล่งข้อสอบและคัดลอกเข้าฟอร์ม, บันทึกตัวชี้วัดและการจับคู่, บันทึกผู้ทรงคุณวุฒิและวิธีลงนาม ทุกตัวตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์เองและปฏิเสธการแก้ฟอร์มที่ตรึงข้อสอบไปแล้ว

**ตัวชี้วัดจำได้จริง** เมื่อครูจับคู่ตัวชี้วัดแล้วบันทึกโดยเปิดสวิตช์ “จำตัวชี้วัดไว้กับโจทย์ในคลัง” ระบบเขียนลง `learning_standards` และ `question_standards` · ครั้งถัดไปที่นำข้อสอบชุดเดิม (หรือชุดที่มีโจทย์ข้อเดิม) เข้าฟอร์มใหม่ ระบบสร้างตัวชี้วัดของฟอร์มและจับคู่ให้เองตั้งแต่ต้น แล้วบอกจำนวนข้อที่เติมให้ในข้อความยืนยัน

**กฎที่ฝังไว้ในขั้นตอน**

- เลือกชุดข้อสอบใหม่แทนที่ข้อเดิมทั้งหมด แต่ **ไม่ลบตัวชี้วัดที่ครูพิมพ์ไว้** เพราะนั่นเป็นถ้อยคำของครู ไม่ใช่ของข้อสอบ
- ลบตัวชี้วัดออกจากฟอร์ม ข้อที่เคยผูกไว้จะกลับเป็น “ยังไม่ได้เลือก” เอง (foreign key เป็น `ON DELETE SET NULL`)
- ขั้นที่ 4 บอกตรง ๆ ว่ายังมีข้อไหนไม่มีตัวชี้วัด และเหลือกี่ข้อ
- คำใบ้ใต้ช่องเกณฑ์คำนวณให้เห็นเลยว่าถ้ามีผู้ทรง 3 ท่าน เกณฑ์ 0.50 มีผลเท่ากับ 0.67

**เลื่อนไปทำระยะ 3 โดยตั้งใจ** การวาดและอัปโหลดรูปลายเซ็น (ระยะนี้รองรับ “พิมพ์ชื่อ” กับ “เว้นไว้เซ็นเอง”) เพราะแผงเซ็นจะถูกสร้างพร้อมกับฝั่งผู้ทรงและใช้ตัวเดียวกัน · การสร้างลิงก์ ตรึงข้อสอบ และหน้ากรอกของผู้ทรง เป็นงานระยะ 3 ทั้งหมด

## สิ่งที่ระยะ 3 ทำแล้ว

**ลิงก์ผู้ทรงคุณวุฒิ** `lib/ioc-token.ts` สร้าง token สุ่ม 32 ไบต์ เก็บเฉพาะ SHA-256 ในฐานข้อมูล และตัดสินว่าลิงก์ยังใช้ได้ไหมจากวันหมดอายุ การเพิกถอน และสถานะ · `lib/actions/ioc-links.ts` ออกลิงก์ทั้งชุด ออกใหม่รายคน ต่ออายุ เพิกถอน และเปิดให้แก้ใหม่ ทุกอย่างบันทึกเป็นเหตุการณ์ผ่าน `record_ioc_form_event`

**การตรึงข้อสอบ** การกดออกลิงก์ครั้งแรกตั้ง `items_frozen_at` เปลี่ยนสถานะเป็น `collecting` แล้วค่อยแจก token — เรียงแบบนี้เพราะถ้าตรึงสำเร็จแต่แจก token พลาด ครูแค่กดออกลิงก์ใหม่ ส่วนลำดับกลับกันจะได้ลิงก์ที่ชี้ไปยังข้อสอบที่ยังแก้ได้อยู่ใต้ลายเซ็น

**หน้าผู้ทรงคุณวุฒิ** `/ioc/[token]` อยู่นอก `app/(app)` ไม่มี session ไม่มีบัญชี · ประเมินทีละข้อ บันทึกร่างอัตโนมัติ (คะแนนบันทึกทันที ข้อเสนอแนะหน่วงไว้ 0.9 วินาทีหลังหยุดพิมพ์) · หน้าตรวจทานก่อนส่ง · ลงนามด้วยการวาด พิมพ์ชื่อ หรือเว้นไว้เซ็นเอง · ส่งแล้วล็อกเป็นอ่านอย่างเดียว

**แดชบอร์ดของครู** ฟอร์มที่ส่งลิงก์แล้วจะแสดงหน้าติดตามแทนตัวช่วยสร้าง: สถานะรายคน เวลาที่เปิดอ่านครั้งแรก เวลาที่ส่ง จำนวนข้อที่ประเมินแล้ว อายุลิงก์ที่เหลือ พร้อมปุ่มออกลิงก์ใหม่ ต่ออายุ เพิกถอน และเปิดให้แก้ใหม่ · มีข้อความพร้อมส่งให้คัดลอก เพราะเว็บไม่ได้ส่งให้เอง

**หลักที่ยึดไว้**

- **ลิงก์แสดงครั้งเดียว** ฐานข้อมูลเก็บแต่ hash ครูที่ปิดหน้าไปก่อนคัดลอกต้องกดออกลิงก์ใหม่ ซึ่งยกเลิกอันเดิมด้วย · หน้าจอเขียนบอกไว้ตรง ๆ ไม่ปล่อยให้ไปเจอเอง
- **ทุกเหตุผลที่ลิงก์ใช้ไม่ได้ ตอบข้อความเดียวกัน** ผิด หมดอายุ ถูกเพิกถอน หรือฟอร์มปิด — บอกต่างกันคือบอกวิธีลองใหม่
- **เฉลยไม่ถูก query ออกมาเลยเมื่อครูไม่เปิดให้เห็น** ไม่ใช่ส่งไปแล้วซ่อนด้วย CSS
- **ต้องประเมินครบทุกข้อจึงส่งได้** ช่องว่างในตารางที่พิมพ์ออกมาคือการให้คนอ่านเดาว่าผู้ทรงคิดอะไร
- **ลบฟอร์มได้จนกว่าจะมีคนส่งผล** เส้นแบ่งคือการส่ง ไม่ใช่การออกลิงก์ — ครูที่ออกลิงก์ผิดต้องถอยได้ แต่เมื่อมีผู้ทรงส่งผลและลงนามแล้ว ฟอร์มคือหลักฐาน · ลบฟอร์มแล้วไฟล์ลายเซ็นใน Storage ถูกลบตามด้วย เพราะ cascade ของฐานข้อมูลไปไม่ถึง

**บั๊กที่เจอตอนทดสอบจริงและแก้แล้ว**

- `revalidatePath` ในขั้นตอนออกลิงก์ทำให้หน้าสลับจากตัวช่วยสร้างไปแดชบอร์ดทันที ลิงก์ที่เพิ่งสร้าง — ซึ่งมีอยู่ที่เดียวในหน้าจอนั้น — หายไปก่อนครูจะคัดลอกได้ · ตอนนี้หน้ารีเฟรชเมื่อครูกดว่าคัดลอกเสร็จแล้ว
- แผงเซ็นอ่าน "มีหมึกหรือยัง" จาก React state ซึ่งยังไม่อัปเดตภายในการลากเส้นเดียวกัน ลายเซ็นที่ขีดเร็วจึงถูกส่งเป็นค่าว่างแบบเงียบ ๆ · ย้ายไปใช้ ref
- ขั้นจับคู่ตัวชี้วัดตั้งค่าเริ่มต้นจากข้อสอบชุดเก่าค้างไว้หลังเปลี่ยนชุดข้อสอบ · ใส่ `key` ให้ remount ตามข้อมูลที่เซิร์ฟเวอร์ส่งมาใหม่

**ตรวจครบวงบนฐานข้อมูลจริงแล้ว** สร้างฟอร์ม → นำข้อสอบ 5 ข้อเข้า (ตัวชี้วัดถูกเติมให้เองจากที่จำไว้) → ใส่ผู้ทรง 1 ท่าน → ตรึงข้อสอบและออกลิงก์ → เปิดลิงก์ในแท็บใหม่แบบไม่ล็อกอิน → ประเมินครบ 5 ข้อ → เซ็นด้วยการวาด → ส่ง → ครูเห็น "ส่งผลแล้ว 1 จาก 1 ท่าน ประเมินแล้ว 5 จาก 5 ข้อ" → เปิดให้แก้ใหม่ → ลบฟอร์มทิ้งพร้อมไฟล์ลายเซ็น

## สิ่งที่ระยะ 4 ทำแล้ว

**แท็บสรุปผล** ฟอร์มที่ส่งลิงก์แล้วมีสองมุมมอง: ผู้ทรงคุณวุฒิ (ติดตามใคร่ส่งแล้ว) และสรุปผล · ตัวเลขทั้งหมดคำนวณฝั่งเซิร์ฟเวอร์ด้วย `summarizeIocForm` ตัวเดียวกับที่เอกสารจะใช้พิมพ์ในระยะ 5 หน้าเว็บกับกระดาษจึงอ่านเลขชุดเดียวกัน

**สิ่งที่หน้าสรุปบอก** ร้อยละความสอดคล้องพร้อมกฎที่ใช้คิด · จำนวนผู้ทรงที่ส่งแล้วและค่า N · เกณฑ์พร้อมค่าที่มีผลจริงตามจำนวนผู้ทรง · ข้อที่ต้องปรับปรุง · ตารางรายข้อ (จำนวนคนที่ให้ +1/0/−1, ดัชนี, ผลการตัดสิน) · ข้อเสนอแนะของผู้ทรงแทรกใต้ข้อนั้นทันที ไม่ต้องเปิดดูทีละฉบับ

**คำเตือนที่ไม่ปล่อยให้ตัวเลขพูดลอย ๆ** ผลชั่วคราวเมื่อยังส่งไม่ครบ · ผู้ทรงน้อยกว่า 3 ท่าน · ผู้ทรงเป็นจำนวนคู่ · ข้อที่มีผู้ประเมินไม่ครบทุกท่าน (บอกว่าดัชนีของข้อนั้นคิดจากกี่คน) · ยังไม่มีใครส่งผล

**ย่อหน้าสรุป** `lib/ioc-summary.ts` เขียนย่อหน้าจากตัวเลขจริง ครูแก้ถ้อยคำได้และกดกลับไปใช้ข้อความที่ระบบสร้างได้ · ถ้ามีผลประเมินเปลี่ยนหลังจากครูแก้ข้อความ (เช่นเปิดให้ผู้ทรงแก้ใหม่) หน้าจะเตือนว่าตัวเลขในย่อหน้าอาจไม่ตรงกับตารางแล้ว

**ตรวจกับข้อมูลจริงแล้ว** สร้างฟอร์ม 5 ข้อ ผู้ทรง 3 ท่าน ให้คะแนนคละกันโดยตั้งใจให้ตกเกณฑ์ 2 ข้อ ผลที่ได้ตรงกับการคำนวณมือทุกตัว: ข้อ 1/4/5 = 1.00 ผ่าน · ข้อ 2 (1,2,0) = 0.33 ตก · ข้อ 3 (1,1,1) = 0.00 ตก · ร้อยละ 60.00 · N = 3 และหน้าบอกว่าเกณฑ์ 0.50 มีผลเท่ากับ 0.67 · ข้อเสนอแนะของผู้ประเมินคนที่ 2 ขึ้นใต้ข้อ 3 พร้อมชื่อและลำดับ · ย่อหน้าสรุปเขียนว่า "3 จาก 5 ข้อ … 60.00 … ได้แก่ ข้อ 2 และ ข้อ 3"

## สิ่งที่ระยะ 5 ทำแล้ว

**เอกสาร 4 แบบจากฟอร์มเดียว** ฟอร์มเปล่า · ฉบับที่ผู้ทรงกรอกแล้ว (เลือกรายท่าน) · ตารางสรุปผลการประเมิน · เล่มรวมทั้งชุด (ฟอร์มเปล่า + ทุกฉบับ + ตารางสรุป เรียงต่อกัน เลขหน้าเดินต่อเนื่อง) · เปิดจากแท็บ “ส่งออกเอกสาร” ในหน้าฟอร์ม

**แบ่งหน้าเอง ไม่ปล่อยให้เบราว์เซอร์แบ่ง** หน้าพิมพ์วัดความสูงจริงของทุกแถวก่อน แล้วจัดลงกล่องขนาด A4 พอดี (210×297 มม.) · ผลคือหัวตารางซ้ำทุกหน้า ไม่มีข้อไหนถูกตัดครึ่งข้ามหน้า และพิมพ์ “หน้า x จาก y” ได้เอง ซึ่ง Chrome ทำผ่าน CSS ไม่ได้

**หน้าพิมพ์อยู่นอก app shell** (`/ioc-print/[formId]`) เพราะ shell ล็อกความสูงและซ่อน overflow ไว้ให้แอปเลื่อนในกรอบของตัวเอง ถ้าพิมพ์จากในนั้นเอกสารจะถูกตัดเหลือหน้าจอเดียวและมีแถบเมนูติดไปบนกระดาษ

**ฟอนต์** `Sarabun` จาก `next/font/google` โหลดเฉพาะเส้นทางนี้ · ทั้งเว็บยังใช้ IBM Plex Sans Thai ตามเดิม

**สิ่งที่เอกสารทำตามต้นฉบับ** หัวกระดาษ 3 บรรทัด · คำชี้แจงและเกณฑ์ +1/0/−1 · ช่องตัวชี้วัดผสานเมื่อหลายข้อใช้ตัวเดียวกัน (ผสานใหม่ต่อหน้า เพราะช่องผสานข้ามหน้าไม่ได้ และคนอ่านหน้าใหม่ก็ต้องเห็นตัวชี้วัดอยู่ดี) · ✓ ในช่อง +1/0/−1 ตามที่ผู้ทรงเลือก · คอลัมน์ข้อเสนอแนะ · หน้าลายเซ็นที่มีเฉพาะผู้ออกข้อสอบกับผู้ทรงของฉบับนั้น · ลายน้ำและเกณฑ์ท้ายหน้าเปิดปิดได้

**ลายเซ็น** ดึงจาก bucket ส่วนตัวด้วย signed URL อายุ 15 นาที และสร้างเฉพาะไฟล์ที่เอกสารฉบับนั้นจะแสดงจริง · แบบพิมพ์ชื่อพิมพ์ชื่อเหนือเส้น · แบบเว้นไว้เซ็นเองได้เส้นประว่าง

**ตรวจกับข้อมูลจริงแล้ว** ฟอร์ม 22 ข้อ ผู้ทรง 1 ท่าน: ฉบับผู้ทรงออกมา 8 หน้า ทุกหน้าสูง 1123px พอดี ไม่มีหน้าไหนล้น หัวตารางซ้ำครบ จำนวนข้อรวม 22 ตรง และหน้าลายเซ็นอยู่หน้าสุดท้ายพร้อมวันที่ลงนาม · ตารางสรุปคิดร้อยละได้ 86.36 (19 จาก 22 ข้อ) ตรงกับย่อหน้าสรุปที่เขียนว่า "ได้แก่ ข้อ 4, ข้อ 7 และ ข้อ 11" · เล่มรวม 24 หน้า เลขหน้าเดินต่อเนื่องถึง "หน้า 24 จาก 24" และมีหน้าลายเซ็นที่ท้ายแต่ละฉบับ

**ยังไม่ได้ทำ** ส่งออกตารางสรุปเป็น Excel (มี `exceljs` อยู่แล้วในโครงการ) และยังไม่ได้สั่งพิมพ์เป็นไฟล์ PDF จริงในเซสชันนี้ — ตรวจถึงระดับกล่องหน้ากระดาษ A4 บนหน้าจอและกฎ `@page` เท่านั้น

## สิ่งที่ระยะ 6 ทำแล้ว

**ส่งออกตารางสรุปเป็น Excel** `/api/ioc/[formId]/summary-export` สร้างไฟล์ด้วย `exceljs` ที่มีอยู่แล้วในโครงการ · หัวไฟล์มีชื่อแบบทดสอบ รายวิชา โรงเรียน ผู้ออกข้อสอบ รายชื่อผู้ประเมิน ร้อยละความสอดคล้อง เกณฑ์ และกฎที่ใช้คิด · ตารางมีคอลัมน์ข้อเสนอแนะของผู้ทรงรายข้อซึ่งเอกสาร A4 แสดงไม่ไหว · **ตัวเลขมาจาก `summarizeIocForm` ตัวเดียวกับหน้าเว็บและเอกสาร** ไม่ได้คำนวณใหม่ · ข้อที่ไม่มีใครประเมินเว้นช่องว่างไว้ ไม่ใส่ 0 · การดาวน์โหลดถูกบันทึกเป็นเหตุการณ์ `document_exported`

**สร้างฟอร์มใหม่จากฟอร์มเดิม** คัดลอกหัวเอกสาร เกณฑ์ ตัวชี้วัด ข้อสอบ และรายชื่อผู้ทรงไปเป็นฉบับร่างใหม่ (ชื่อเดิม + "(รอบใหม่)") · **ไม่คัดลอกคะแนน ลายเซ็น ลิงก์ หรือเวลาใด ๆ** เพราะฟอร์มที่ยังไม่มีใครประเมินแต่มีติ๊กของคนอื่นติดมาด้วยคือเอกสารปลอม · นี่คือทางกลับสำหรับฟอร์มที่มีข้อตกเกณฑ์ ซึ่งหน้าสรุปผลแนะนำให้ทำอยู่แล้ว

**คลังตัวชี้วัดของโรงเรียน** `/research/ioc/standards` แสดงตัวชี้วัดทั้งหมดพร้อมจำนวนโจทย์ที่ผูกไว้ · แก้ไขและลบได้เฉพาะแถวที่ตัวเองเพิ่ม (ตาม RLS) · คำเตือนตอนลบบอกตรง ๆ ว่าโจทย์กี่ข้อจะไม่ถูกเติมให้อัตโนมัติอีก และย้ำว่าฟอร์มที่ทำไปแล้วไม่เปลี่ยน เพราะแต่ละฟอร์มเก็บสำเนาของตัวเองไว้

**อัปโหลดรูปลายเซ็น** ผู้ทรงเลือกได้ 4 ทาง: วาด · อัปโหลดรูป · พิมพ์ชื่อ · เว้นไว้เซ็นเอง · รูปที่อัปโหลดถูกวาดใหม่ลง canvas แล้วแปลงเป็น PNG ก่อนส่ง (bucket รับ PNG อย่างเดียว รูปจากมือถือมักเป็น JPEG หลายเมกะไบต์ และการแปลงฝั่งเบราว์เซอร์ทำให้เซิร์ฟเวอร์ไม่ต้องเดาว่าไฟล์เป็นอะไรจริง ๆ) · ตรวจขนาดอีกครั้งก่อนส่ง และตรวจ magic number ของ PNG ที่ฝั่งเซิร์ฟเวอร์เหมือนเดิม

**ตรวจกับข้อมูลจริงแล้ว** อัปโหลด JPEG เป็นลายเซ็น → แปลงเป็น PNG → ส่ง → ขึ้นในเอกสารที่พิมพ์ผ่าน signed URL · ดาวน์โหลด Excel ได้ไฟล์ 7.8 KB ชื่อ `IOC-สรุปผล-<ชื่อข้อสอบ>-<วันที่>.xlsx` · สร้างฟอร์มใหม่จากฟอร์มเดิมแล้วได้ข้อสอบ 5 ข้อพร้อมตัวชี้วัดครบ 5/5 และรายชื่อผู้ทรงเดิม โดยฟอร์มใหม่เป็นฉบับร่าง · คลังตัวชี้วัดแสดงจำนวนโจทย์ที่ผูกไว้ถูกต้อง และลบออกได้

**ส่งออก Word** ยกไปทำหลังปล่อยรุ่น เมื่อเจ้าของผลิตภัณฑ์ตอบว่าเอาทั้งฟอร์มและตารางสรุป · รายละเอียดอยู่ในหัวข้อ “ส่งออกเป็นไฟล์ Word” ข้างล่าง

## สิ่งที่ระยะ 7 ทำแล้ว

**UAT ด้านเทคนิคผ่านครบ** รายการตรวจ 6 หมวดอยู่ใน `docs/EDUCATION_RESEARCH_IOC_UAT.md` ทำบน dev server ที่ต่อฐานข้อมูล production ด้วยบัญชีครูจริงและข้อสอบจริง · หมวดที่เพิ่มขึ้นจากการตรวจของแต่ละระยะคือความปลอดภัย 11 ข้อ ซึ่งพิสูจน์บนสายจริงว่า anon ถูกปฏิเสธที่ระดับ grant ทุกตาราง (ไม่ใช่แค่ RLS คืน 0 แถว) · `record_ioc_form_event` ปฏิเสธ detail ที่มี `token`/`signature` จริง · bucket ลายเซ็นเปิดอ่านสาธารณะไม่ได้ · และ **เฉลยไม่ถึงเบราว์เซอร์ของผู้ทรงเมื่อสวิตช์ปิด** (เปิดสวิตช์พบคำว่า `solution` 6 ครั้งใน payload ปิดสวิตช์เหลือ 1 ครั้งซึ่งคือตัวสวิตช์เอง โดยข้อสอบยังครบทุกข้อ)

**คู่มือครู** `docs/EDUCATION_RESEARCH_IOC_USER_GUIDE.md` เดินตั้งแต่เตรียมตัว ผ่านทั้งสี่ขั้น การส่งลิงก์ การอ่านผล ไปจนถึงวิธีตั้งค่ากล่องพิมพ์ให้ได้ PDF ที่ถูกต้อง · เขียนเรื่องที่ระบบ **ไม่ได้** ทำไว้ชัด: ไม่ส่งอีเมลให้เอง ไม่ใช่ลายมือชื่ออิเล็กทรอนิกส์ตามกฎหมาย ไม่เดาตัวชี้วัดให้ และยังไม่มีส่งออก Word

**บันทึกการปล่อยรุ่น** `docs/EDUCATION_RESEARCH_IOC_RELEASE.md` ระบุว่าเกณฑ์ก่อน merge ผ่านครบ แต่ยังไม่ merge และไม่ deploy เพราะการเข้า `master` เท่ากับปล่อยขึ้น production · มีเรื่อง schema ที่ต้องรู้ก่อน merge (migration ทั้งสามขึ้น production ไปก่อน code แล้วตั้งแต่ระยะ 2) และมีรายการที่ต้องตรวจหลัง deploy เตรียมไว้

**ล้างข้อมูลทดสอบหมดแล้ว** นับแถวผ่าน service role หลังจบ UAT: ทั้ง 6 ตารางของฟอร์ม รวมถึง `learning_standards` และ `question_standards` เป็นศูนย์ และ bucket `ioc-signatures` ไม่มีไฟล์ · การลบตัวชี้วัดออกจากคลังทำให้ `question_standards` 5 แถวหายตามโดยโจทย์ในคลังยังอยู่ครบ ซึ่งยืนยัน cascade ไปในตัว

**สิ่งที่ระยะนี้ยังทำไม่ได้และไม่แกล้งว่าทำได้** คณะผู้ทรงคุณวุฒิตัวจริงยังไม่เคยเปิดลิงก์จากเครื่องของตัวเอง · ยังไม่มีใครกดพิมพ์ผ่านกล่องพิมพ์ของเบราว์เซอร์แล้วเปิดไฟล์ PDF ที่ได้ (เครื่องมืออัตโนมัติเปิดกล่องพิมพ์ของระบบไม่ได้) · ยังไม่ได้ยืนยันการแยกองค์กรด้วยบัญชีครูคนที่สองจริง · และยังไม่ได้ลองบนมือถือเครื่องจริง

## ส่งออกเป็นไฟล์ Word

`/api/ioc/[formId]/docx-export` สร้าง `.docx` ด้วย `docx@9` ใช้ query string เดียวกับหน้าพิมพ์ ตัวเลือกบนแผงส่งออกจึงมีผลกับทั้งสองรูปแบบโดยไม่ต้องมีสวิตช์ชุดที่สอง

**เนื้อหามาจากที่เดียวกับหน้าพิมพ์** `lib/ioc-document-server.ts` ประกอบ `PrintSection[]` ครั้งเดียว แล้วให้สองตัวเรนเดอร์วาดคนละแบบ — หน้า A4 ของเบราว์เซอร์ กับไฟล์ Word · ตัวเลขจึงต่างกันไม่ได้ เพราะไม่มีฝั่งไหนคำนวณเอง

**สิ่งที่ Word ทำได้ดีกว่าหน้าพิมพ์** แบ่งหน้าเองจึงไม่ต้องวัดความสูงแถวล่วงหน้า · หัวตารางซ้ำทุกหน้าด้วย `tableHeader` และกันข้อขาดครึ่งด้วย `cantSplit` ซึ่งเป็นสิ่งที่หน้าพิมพ์ต้องเขียน packer ทั้งชุดเพื่อให้ได้ · เลขหน้าเป็น field `PAGE`/`NUMPAGES` จึงยังถูกต้องหลังครูแก้เอกสาร

**ฟอนต์** ตั้งเป็น `TH SarabunPSK` ขนาด 16pt ตามระเบียบงานสารบรรณ · ถ้าเครื่องไม่มีฟอนต์นี้ Word เลือกฟอนต์อื่นแทนและเอกสารยังเปิดได้ ซึ่งเป็นเหตุผลที่รูปแบบนี้มีค่า จึงตั้งเป็นค่าตั้งต้นไม่ใช่ข้อบังคับ

**ลายเซ็น** ดาวน์โหลดไบต์จาก bucket ส่วนตัวมาฝังในไฟล์ (Word พก media ของตัวเอง signed URL จึงใช้ไม่ได้) · ไฟล์ที่หายไปได้เส้นประแทน ไม่ทำให้การดาวน์โหลดล้ม · ปิดสวิตช์ลายเซ็นแล้วไฟล์ไม่มี `word/media/` เลย

**ลายน้ำ** เป็นข้อความกลางหัวกระดาษทุกหน้า ไม่ใช่ลายน้ำทแยงแบบ VML ที่ `docx` ไม่ได้สร้างให้ · ข้อดีคือค้นหาด้วยข้อความได้

**ข้อจำกัดที่บอกไว้บนหน้าจอ** รูปภาพในโจทย์ไม่ติดไปกับไฟล์ (อยู่ใน Storage หลัง URL ส่วนไฟล์ Word ต้องพกไบต์เอง) จะขึ้นเป็นข้อความบอกตำแหน่งแทนการหายเงียบ ๆ · สูตรคณิตศาสตร์เป็นโค้ด LaTeX ตามที่พิมพ์ไว้ เพราะ Word ไม่มี KaTeX · ข้อสอบที่มีรูปหรือสูตรมากจึงควรใช้ PDF

**`lib/ioc-docx-html.ts`** แปลง HTML ของโจทย์เป็นย่อหน้าและ run ของ Word รองรับชุดแท็กที่ตัวแก้ไขสร้างจริง (`p`, `br`, `li`, `b/strong`, `i/em`, `u`, `sup`, `sub`) และทิ้งแท็กอื่นโดยไม่กลืนข้อความข้างใน · มี vitest 20 เคส

**หน้าพิมพ์เรนเดอร์สูตรแล้ว** ระหว่างทำระยะนี้พบว่าเอกสาร A4 ส่ง `prompt` เข้า `dangerouslySetInnerHTML` ตรง ๆ โดยไม่ผ่าน `renderMathInHtml` สูตรที่ครูเขียนแบบ `\(…\)` จึงพิมพ์ออกมาเป็นแบ็กสแลชดิบ ทั้งที่หน้าข้อสอบของนักเรียนเรนเดอร์ให้ · แก้แล้วทั้งสามจุด (โจทย์ร่วม โจทย์ ตัวเลือก) และการแบ่งหน้ายังได้ 2 หน้าสูง 1123px เท่าเดิม

### สิ่งที่ภาพร่างตกลงเพิ่มจากสเปกข้างต้น

- **ฉบับของผู้ทรงแต่ละท่านมีเฉพาะลายเซ็นของท่านนั้นกับของผู้ออกข้อสอบ** ตรงกับที่ท่านเห็นตอนลงนาม · หน้าลายเซ็นรวมทุกท่านมีเฉพาะใน “เล่มรวมทั้งชุด”
- **ลายน้ำเปิดเป็นค่าตั้งต้นในฟอร์มเปล่าและฉบับรายผู้ทรง แต่ปิดในตารางสรุป** เพราะตารางสรุปเป็นเอกสารแนบรายงาน ไม่ใช่ฉบับที่ส่งออกไปให้ใครกรอก
- **ตารางสรุปทำเครื่องหมาย `*` ที่ข้อต่ำกว่าเกณฑ์** พร้อมหมายเหตุใต้ตาราง รายชื่อผู้ทรงคุณวุฒิ และ `N` ที่ใช้คำนวณกำกับท้ายหน้า
- **หน้าสรุปบนเว็บแทรกแถวข้อเสนอแนะไว้ใต้ข้อที่ไม่ผ่านทันที** ครูไม่ต้องเปิดดูทีละฉบับเพื่อรู้ว่าต้องแก้อะไร
- **หน้าผู้ทรงบนจอใหญ่มีแถบซ้ายไว้กระโดดข้ามข้อและดูว่าเหลือข้อไหน** ส่วนบนมือถือเป็นการ์ดทีละข้อพร้อมปุ่มคะแนนขนาดใหญ่ ทั้งสองแบบเป็นการไหลเดียวกันและบันทึกร่างอัตโนมัติเหมือนกัน
- **แดชบอร์ดมีกล่อง “ข้อความพร้อมส่ง” ให้คัดลอก** เพราะเว็บไม่ส่งอีเมลหรือข้อความเอง ครูเป็นผู้ส่งลิงก์ด้วยช่องทางของตัวเอง
- **ปุ่ม “ถัดไป” ของขั้น 3 ถูกปิดไว้จนกว่าจะกรอกตัวชี้วัดครบทุกข้อ** และบอกจำนวนข้อที่ยังขาดไว้ข้างปุ่ม
- **ขั้น 2 เตือนเป็นพิเศษเมื่อข้อสอบชุดนั้นยังเปิดให้นักเรียนทำอยู่** พร้อมเสนอให้บันทึกเป็นร่างไว้ก่อนแล้วค่อยสร้างลิงก์หลังปิดการสอบ

## เรื่องที่ยังรอเจ้าของผลิตภัณฑ์ยืนยัน

ข้อ 1 และ 3 ทำไปตามข้อเสนอแล้วและใช้งานได้จริง เขียนไว้ตรงนี้เพื่อให้เปลี่ยนใจได้ ไม่ใช่เพราะยังไม่ได้ทำ

1. ~~ให้ผู้ทรงเห็นแนวคำตอบหรือเฉลยได้ไหม~~ — ทำตามข้อเสนอแล้ว: มีสวิตช์และปิดไว้เป็นค่าตั้งต้น พิสูจน์บนสายจริงในระยะ 7 ว่าเฉลยไม่ถึงเบราว์เซอร์เมื่อปิด · เหลือแค่ยืนยันว่าค่าตั้งต้นนี้ถูกใจ
2. ~~เก็บตัวชี้วัดไว้กับโจทย์~~ — ตกลงแล้วเมื่อ 13 ก.ย. 2569 ว่าเก็บ ทำเสร็จในระยะ 2
3. ~~ลิงก์ผู้ทรงควรมีอายุกี่วันเป็นค่าตั้งต้น~~ — ทำตามข้อเสนอแล้วที่ 30 วัน ต่ออายุและเพิกถอนได้ · เหลือแค่ยืนยันว่า 30 วันเหมาะกับจังหวะงานจริง
4. **ยังไม่ได้ทำ** เมื่อผู้ทรงส่งครบแล้ว ควรล็อกฟอร์มเป็น "ฉบับสมบูรณ์" โดยเก็บ hash ของเนื้อหาไว้อ้างอิงหรือไม่ — ตอนนี้ฟอร์มที่มีคนส่งผลแล้วลบไม่ได้และข้อสอบแก้ไม่ได้ ซึ่งกันปัญหาไปแล้วเกือบหมด hash จะเพิ่มได้อีกอย่างเดียวคือการพิสูจน์ย้อนหลังว่าเอกสารที่พิมพ์ตรงกับที่ลงนาม
