# Product: KorKru / ก่อครู

อัปเดตล่าสุด: 18 สิงหาคม 2026

เอกสารนี้เป็นแหล่งอ้างอิงหลักของตัวตนผลิตภัณฑ์ หากข้อความการตลาดหรือโค้ดขัดกับเอกสารนี้ ให้แจ้งความขัดแย้งก่อนเปลี่ยนทิศทางผลิตภัณฑ์

## ตัวตนของแบรนด์

- ชื่อภาษาไทย: **ก่อครู**
- ชื่อภาษาอังกฤษ: **KorKru**
- แนวคิดของชื่อ: ครูเป็นผู้ “ก่อ” สิ่งที่ทำให้การเรียนรู้เกิดขึ้น
- Brand line: **“ก่อ…โดยครู”**

Brand line ไม่ใช่สโลแกนตายตัว คำตรงกลางเปลี่ยนตามบริบทและเปิดให้ครูตีความได้ เช่น:

- ก่อการเรียนรู้โดยครู
- ก่อข้อสอบโดยครู
- ก่อห้องเรียนโดยครู
- ก่อการจัดการเรียนรู้โดยครู
- ก่อโอกาสโดยครู

การใช้คำนี้ควรรักษา “ก่อ” และ “โดยครู” ไว้ ส่วนคำกลางสลับได้ ไม่ควรประกาศ “ก่อการเรียนรู้ โดยครู” เป็นชื่อเต็มถาวรโดยไม่ได้รับการยืนยันจากเจ้าของผลิตภัณฑ์

## วิสัยทัศน์

ช่วยให้ครูสร้าง จัดการ มอบหมาย และประเมินการเรียนรู้ได้ในระบบเดียว โดยลดงานซ้ำของครูและทำให้ครูมองเห็นนักเรียนได้ครบทั้งด้านวิชาและชีวิตในโรงเรียน

## ปัญหาที่ต้องการแก้

- ครูสร้างและเก็บโจทย์กระจัดกระจาย นำกลับมาใช้ซ้ำหรือแชร์ยาก
- การสร้างตัวเลือกหลอกและโจทย์หลายชุดใช้เวลา
- นักเรียนลอกคำตอบกันได้เมื่อทุกคนได้ตัวเลขเดียวกัน
- การตรวจแบบฝึกหัดและข้อสอบกินเวลาครู
- ครูประจำชั้นมองไม่เห็นภาระงานจากทุกวิชาของนักเรียนในที่เดียว

## คุณค่าหลัก

1. **สร้างโจทย์ได้หลายรูปแบบ** — จากโจทย์ปรนัยจนถึงโจทย์ตัวเลขแบบสุ่มและโจทย์ผสม
2. **นำกลับมาใช้และจัดชุดได้** — เก็บเป็นคลัง แบ่งปัน และนำไปสร้างงานหรือข้อสอบ
3. **ลดโอกาสลอกกัน** — สุ่มค่าของตัวแปรต่อการทำข้อสอบและเก็บค่าที่สุ่มไว้กับ attempt
4. **ช่วยตรวจคะแนน** — ตรวจอัตโนมัติเมื่อชนิดคำตอบรองรับ และเปิดให้ครูตรวจหรือแก้คะแนนเมื่อจำเป็น
5. **มองนักเรียนแบบองค์รวม** — โฮมรูมรวมงานจากห้องเรียนรายวิชาให้ครูประจำชั้นติดตามได้

## ผู้ใช้ในเวอร์ชันแรก

- ครูผู้สอน
- นักเรียน
- ครูประจำชั้น ซึ่งเป็นครูในบริบทของห้อง `homeroom`
- ครูผู้สอนร่วม ซึ่งเป็นความสัมพันธ์กับห้องเรียนและมีระดับสิทธิ์
- แอดมิน

คำว่า “ครูประจำชั้น” และ “ครูผู้สอนร่วม” ไม่ควรถูกสร้างเป็น global user role โดยอัตโนมัติ เพราะเป็นบทบาทตามบริบท ดูรายละเอียดใน `docs/DOMAIN.md`

## ขอบเขตผลิตภัณฑ์ระยะแรก

ลำดับความสำคัญคือ:

1. คลังโจทย์
2. ห้องเรียนรายวิชา
3. งานและข้อสอบ
4. การส่งคำตอบและตรวจอัตโนมัติ/โดยครู
5. ห้องโฮมรูม

รายละเอียดสิ่งที่ต้องเสร็จและสิ่งที่เลื่อนไปภายหลังอยู่ใน `docs/SCOPE.md`

## รูปแบบธุรกิจ

เป้าหมายคือบริการรายเดือนแบบ Freemium:

- Free: ใช้งานได้โดยจำกัดความสามารถหรือปริมาณ
- Paid: ปลดล็อกความสามารถและโควตาเพิ่มเติม

ราคา ชื่อแพ็กเกจ โควตา ระยะทดลองใช้ ช่องทางชำระเงิน และ entitlement ยังไม่ใช่ข้อสรุป ห้ามใช้ตัวเลขหรือข้อความที่อยู่ในหน้า pricing/billing ปัจจุบันเป็นข้อมูลธุรกิจจริงจนกว่าเจ้าของผลิตภัณฑ์จะอนุมัติ

## หลักการผลิตภัณฑ์

- ครูต้องเข้าใจได้โดยไม่ต้องเป็นผู้เชี่ยวชาญเทคโนโลยี
- งานประจำของครูควรสั้นลง ไม่เพิ่มขั้นตอนเพื่อโชว์ความสามารถของระบบ
- การตรวจอัตโนมัติต้องอธิบายได้และครูมีสิทธิ์ตรวจทาน
- ข้อมูลนักเรียนต้องเป็นส่วนตัวตามบทบาทและห้องเรียน
- ฟีเจอร์ที่แสดงต่อผู้ใช้ต้องทำงานจริงหรือระบุชัดว่าเป็นตัวอย่าง
- การเพิ่มฟีเจอร์ใหม่ต้องไม่ทำลายโจทย์ งาน และผลคะแนนเดิม

## อนาคตหลัง MVP

- แบบสำรวจ เช่น ความเครียด ความถนัด และข้อมูลเพื่อการดูแลนักเรียน
- เครื่องมือสนับสนุนงานวิจัยการศึกษา
- ระบบสมาชิกและชำระเงินจริง
- ความสามารถระดับโรงเรียนหรือองค์กรที่ยังไม่ได้จัดลำดับ

ข้อมูลแบบสำรวจและงานวิจัยอาจมีความอ่อนไหวสูง ต้องออกแบบ consent, สิทธิ์เข้าถึง, retention และการไม่ระบุตัวตนก่อนเริ่มพัฒนา

## เรื่องที่ยังต้องตัดสินใจ

- นิยามและขอบเขตของ “แอดมิน” ระหว่าง system admin, organization admin และ super admin
- แพ็กเกจ ราคา โควตา และนโยบาย trial
- นโยบายการเก็บ ลบ ส่งออก และใช้ข้อมูลนักเรียน
- เกณฑ์ที่ถือว่า MVP พร้อมเปิดให้ผู้ใช้จริง
