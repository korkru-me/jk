# Exam recovery and proctor QA

อัปเดต: 20 กันยายน 2026

เอกสารนี้แยก **สิ่งที่พิสูจน์ได้จากโค้ดแบบไม่แตะข้อมูลจริง** ออกจาก **การซ้อมใน staging/อุปกรณ์จริง** อย่างชัดเจน ห้ามนำผล unit test ไปอ้างว่าเครือข่าย, Supabase Realtime หรือห้องคุมสอบจริงผ่านแล้ว

## สิ่งที่ agent ตรวจอัตโนมัติแล้ว

- คำตอบที่บันทึกไม่ทันเก็บคู่กับโหมดคณิตศาสตร์ DEG/RAD และอ่าน backup รูปแบบเก่าได้
- recovery รับเฉพาะ answer id ที่ยังอยู่ใน attempt ปัจจุบัน ข้อมูลค้างจาก attempt เก่าจะไม่ถูกส่งซ้ำจนสถานะค้างว่า “รอซิงก์”
- request บันทึกคำตอบที่ไม่มี response ลองซ้ำได้เฉพาะ action แบบ idempotent; action ที่ตอบปฏิเสธจะไม่ถูกเรียกซ้ำ
- เวลาสอบคำนวณใหม่จาก `started_at` ทุกครั้ง จึงไม่เพิ่มเวลาเมื่อ reload, เปิดแท็บสำเนา, sleep หรือ browser throttle timer และค่าที่หมดอายุ/ผิดรูปจะปิดที่ศูนย์
- Realtime snapshot ของห้องคุมสอบนำ event ที่เข้าระหว่างโหลด snapshot มารวมต่อ ไม่ย้อนสถานะกลับ
- เมื่อ Realtime ใช้ไม่ได้ dashboard เปลี่ยนไป polling fallback และเมื่อกลับมา live จะ reconcile snapshot
- proctor signal ที่ส่งไม่สำเร็จถูกใส่กลับหน้าคิวโดยจำกัดจำนวน; signal ใหม่ที่เกิดระหว่าง request จะถูกส่งต่อทันทีหลัง request สำเร็จ ไม่รอ heartbeat รอบถัดไป
- alert เดิมไม่ดังซ้ำหลัง reconnect/poll, event ที่ครูยังไม่รับทราบไม่หายจาก review queue และสัญญาณหลายตัวจากนักเรียนคนเดียวในช่วงเดียวกันถูกรวมเพื่อลดเสียงรัว

## สิ่งที่ยังต้องซ้อมหลังมี staging แยก

ใช้บัญชี/ข้อสอบจำลองเท่านั้น และเปิดหน้าคุมสอบของครูอีกเครื่องหนึ่ง ห้ามใช้ production:

1. ตอบอย่างน้อยสองข้อแล้วตัด Wi‑Fi ระหว่างพิมพ์ ยืนยันว่าขึ้น “รอซิงก์” และคำตอบยังอยู่หลัง reload
2. ต่อ Wi‑Fi กลับ ยืนยันว่าคำตอบซิงก์ครบเพียงครั้งเดียว แล้วส่งข้อสอบได้
3. ปิด/เปิด browser หรือ SEB ระหว่าง attempt ยืนยันว่า resume attempt เดิมและเวลาไม่เริ่มใหม่
4. ปล่อยเวลาหมดระหว่าง offline/reload ยืนยันว่าไม่ได้เงินเพิ่มและระบบส่ง/ปิด attempt ตามกติกา
5. ทดสอบอัปโหลดรูป/ไฟล์สำเร็จ ล้มเหลว และลองส่งทั้งที่หลักฐานบังคับยังไม่ครบ
6. จากเครื่องนักเรียน สลับแท็บ ออกจาก fullscreen ตัด/ต่อเน็ต และเปิด attempt ซ้ำอีกหน้าต่าง ตรวจว่า dashboard แสดงสถานะ/จำนวน connection ถูกต้อง
7. ปิด Realtime ชั่วคราวในสภาพแวดล้อมทดสอบ ตรวจว่า dashboard ระบุ fallback, polling ยังอัปเดต และกลับ live ได้โดยไม่แจ้ง event ซ้ำ
8. ให้ครูรับทราบ event ตรวจว่า review queue/รายงานลดถูกคนและ audit ยังคงอยู่

แต่ละกรณีต้องเก็บเฉพาะเวลาโดยประมาณ รุ่น OS/SEB/browser สถานะผ่าน/ไม่ผ่าน และอาการที่ไม่ระบุตัวบุคคล ห้ามบันทึกคำตอบจริง ชื่อเด็ก token, CK/BEK, password หรือภาพหน้าจอที่มีข้อมูลนักเรียน
