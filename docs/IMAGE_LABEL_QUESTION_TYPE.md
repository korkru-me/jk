# ประเภทโจทย์ `image_label` (ติดป้ายบนรูป)

อัปเดตล่าสุด: 17 กันยายน 2026 · สถานะ: **เฟส 0–6 เสร็จ · ครูสร้างโจทย์ได้จริง นักเรียนตอบได้จริง เหลือปลายทางหลังสอบ**
· เบรนช์ `feat/image-label-question-type` แตกจาก `master` ที่ `fe687a3`

เอกสารนี้คือช่องทาง handoff ของงานนี้ตาม `AGENTS.md` แชตและ memory ของ agent ไม่ใช่ช่องทาง handoff
ใครมาทำต่อ (Claude Code หรือ Codex เครื่องไหนก็ตาม) ให้เริ่มจากไฟล์นี้

## โจทย์ที่ต้องการรองรับ

ใบงาน "ระบุส่วนประกอบจากภาพ" ที่ครูวิทย์/ชีววิทยาใช้กันทั่วไป — ครูแนบรูปไดอะแกรมมาหนึ่งใบ
แล้ววางกล่องคำตอบชี้ไปที่จุดไหนของรูปก็ได้ ตัวอย่างต้นแบบคือใบงาน "อวัยวะในระบบหายใจ":
รูปทางเดินหายใจหนึ่งใบ · กล่องคำตอบ 7 กล่องกระจายรอบรูป แต่ละกล่องมีเส้นโยงไปยังอวัยวะของมัน ·
ใต้รูปมีคลังคำ 9 คำ (จมูก หลอดลม ปอด โพรงจมูก หลอดลมฝอย กระบังลม ท่อลม ถุงลม กระดูกซี่โครง)
ให้ลากมาใส่กล่อง

**7 กล่อง แต่ 9 คำ** — ใบงานจริงมีตัวลวง คลังคำยาวกว่าจำนวนจุดได้และต้องรองรับตั้งแต่รุ่นแรก

ครูต้องเลือกวิธีตอบได้เอง สามแบบ: พิมพ์เอง · ดรอปดาวน์ · ลากคำจากคลังมาใส่กล่อง

### ทำไมไม่ใช้ประเภทที่มีอยู่

ไม่มีชนิดไหนเก็บ**พิกัด**ได้เลย ซึ่งเป็นสิ่งเดียวที่โจทย์แบบนี้ต้องการจริง ๆ:

| ชนิดเดิม | ทำได้แค่ไหน | ตกตรงไหน |
|---|---|---|
| `fill_blank` | ช่องกรอก/ดรอปดาวน์ครบ ตรวจให้แล้ว | ช่องถูกวางด้วย marker `[___1]` **ในข้อความ** (`lib/fill-blank.ts`) ไม่มีที่ให้ x,y — เติม coordinate ลง `FillBlankConfig` คือเปลี่ยนความหมายของโจทย์เติมคำเก่าทุกข้อ |
| `matching` | มีทั้งโหมดลากและโหมดลากเส้นอยู่แล้ว | คู่เก็บใน `mcq_options` เป็นลิสต์สองคอลัมน์ ไม่มีพิกัด · เฉลย `MATCH:` คือ "ข้อความฝั่งขวาเรียงตามลำดับฝั่งซ้าย" ซึ่งผูกกับเลย์เอาต์สองคอลัมน์โดยตรง |
| `composite` | รวมหลายชนิดใต้โจทย์เดียว | `CompositePart` เรียงแนวตั้งเป็น ก) ข) ค) ไม่มีมิติเชิงพื้นที่เลย |

เหตุผลเดียวกับที่ `classify` ไม่ยอมใช้ `composite` (ดู `docs/CLASSIFY_QUESTION_TYPE.md`):
**ความสัมพันธ์ที่โจทย์ต้องการแสดง ชนิดเดิมแสดงไม่ได้** ในที่นี้คือ "กล่องนี้ชี้ไปที่จุดนี้ของรูป"

## สิ่งที่ยืมของเดิมได้ — และนี่คือเหตุผลที่งานนี้ไม่ใหญ่เท่าที่ชื่อฟัง

| ยืมอะไร | จากไหน | ยืมได้แค่ไหน |
|---|---|---|
| กติกาตรวจคำตอบข้อความ | `isBlankCorrect()` ใน `lib/fill-blank.ts` | ใช้ได้ทั้งดุ้น ไม่ต้องแก้ — `dropdown` เทียบเป๊ะ `fixed` เคารพ case_sensitive |
| รูปร่างเฉลยรายช่อง | `FillBlankItem` (`answers[]`, `case_sensitive`, `options[]`) | ลอกโครงมาเป็น marker ได้ตรง ๆ |
| เอนจินลาก | `components/exam/matching-drag-input.tsx` | pointer events ไม่ใช่ HTML5 DnD (touch ใช้ไม่ได้) · มี tap-to-place เป็นทางสำรอง · **`place()` รองรับ bank ยาวกว่าช่องอยู่แล้ว** ชิปที่ถูกเบียดออกกลับลงคลังเอง = ตัวลวงใช้ได้ |
| เส้นโยง | `components/exam/matching-line-input.tsx` | SVG overlay + ResizeObserver พร้อม · **ที่นี่ง่ายกว่าเดิม** เพราะปลายเส้นข้างหนึ่งคำนวณจาก % บนรูป ไม่ต้องวัด DOM |
| อัปโหลดรูป | `QuestionImageUpload` + `lib/image-downscale.ts` | ใช้ซ้ำได้ ย่อรูปให้อัตโนมัติอยู่แล้ว |
| กวาดไฟล์กำพร้า | `lib/storage-release.ts` | **ได้ฟรี** — มันอ่าน `JSON.stringify(row)` ทั้งแถว จึงเห็น URL ที่อยู่ใน `extra_data` |
| content fingerprint | `lib/question-content-match.ts` | **ได้ฟรี** — `canonical(q.extra_data)` เป็น generic |

**ที่ต้องเขียนใหม่จริง ๆ มีแค่: รูป + พิกัด + เส้นโยง + เลย์เอาต์มือถือ + ฟอร์มวางจุด**

## การตัดสินใจที่อนุมัติแล้ว (17 กันยายน 2026)

| เรื่อง | ที่เลือก | ย้อนกลับได้ไหม |
|---|---|---|
| ชื่อ type | `image_label` | **ไม่ได้** — Postgres ลบค่า enum ไม่ได้ |
| prefix เฉลย | `IMGL:` | **ไม่ได้** — ตรึงลง `submission_answers.correct_answer` |
| ป้ายไทย | `TYPE_LABEL` = "ติดป้ายบนรูป" · `TYPE_SHORT` = "ป้ายบนรูป" | ได้ เป็นแค่ label |
| คะแนน | **จุดละ 1 คะแนน ได้คะแนนบางส่วน** — กติกาเดียวกับ `CLS:`/`COMP:`/`FILL:` | ได้ |
| ครูวางอะไร | **รุ่นแรกวาง "จุด" อย่างเดียว กล่องจัดอัตโนมัติริมซ้าย/ขวาเรียงตาม y** | ได้ — `box?` เป็น optional อยู่แล้ว เพิ่มการลากกล่องทีหลังไม่ทำลายโจทย์เก่า |
| โหมดตอบ | **ต่อข้อ ไม่ใช่ต่อจุด** — `typed` / `dropdown` / `drag` | ได้ |
| สลับลำดับคลังคำ | **ไม่สลับ** | ได้ |
| โหมดครูตรวจเอง | **ไม่มีในรุ่นแรก — ตรวจอัตโนมัติล้วน** `is_correct` ไม่เคยเป็น null | ได้ |
| หน่วยข้อย่อย | `subQuestionUnit` = "จุด" | ได้ |

**ป้ายไทย "ติดป้ายบนรูป" ยังเป็นคำที่ agent เลือกเอง ไม่ได้มาจากคำที่ครูใช้จริง**
เสนอให้เปลี่ยนแล้วสองครั้ง (17 กันยายน 2026) เจ้าของผลิตภัณฑ์ไม่ได้เสนอคำอื่น จึงใช้คำนี้ต่อไป
**ยังเปลี่ยนได้ฟรีจนถึงเฟส 6** — ตอนนี้มันอยู่แค่ในคอมเมนต์และเอกสาร
พอเฟส 6 ขึ้นมันจะไปอยู่ใน `TYPE_LABEL`, `TYPE_SHORT`, การ์ดเลือกประเภท, ชื่อ route และ metadata พร้อมกัน
(ต่างจาก `image_label` กับ `IMGL:` ที่ตรึงถาวรไปแล้ว)

**เหตุผลของสองข้อที่ไม่ชัดในตัวเอง:**

- **ไม่สลับคลังคำ** — `option_order` ในตาราง attempt ผูกกับ index ของ `mcq_options`
  (ดู `buildAttemptQuestion` ใน `lib/assignment-attempt.ts`) เอามาใช้ซ้ำกับคลังคำที่อยู่ใน `extra_data`
  คือ overload ความหมายของคอลัมน์ · และคลังคำในใบงานกระดาษเป็นกริดตายตัวอยู่แล้ว
  ถ้าจะสลับทีหลังต้องคิดเรื่องคอลัมน์ที่เก็บลำดับใหม่ ไม่ใช่ยัดลงของเดิม
- **ไม่มีโหมดครูตรวจเอง** — เหมือน `classify` ที่ตัดสถานะ "รอครูตรวจ" ทิ้งทั้งสาย
  ทำให้ไม่ต้องคิดเคส `is_correct = null` ในหน้าตรวจ หน้าผลสอบ และ `answer-feedback` เลย

## รูปร่างข้อมูล

`lib/types.ts` — `ImageLabelConfig` เก็บใน `questions.extra_data`

```ts
export type ImageLabelAnswerMode = 'typed' | 'dropdown' | 'drag'

export interface ImageLabelMarker {
  id: string
  /** ชื่อสั้นของจุด ใช้เรียกจุดนี้บนหน้าตรวจและหน้าผลสอบ — ไม่ใช่เฉลย และนักเรียนไม่เห็น */
  label?: string
  /** % ของความกว้าง/สูงรูป (0–100) ไม่ใช่ px */
  point: { x: number; y: number }
  /** undefined = จัดอัตโนมัติริมซ้าย/ขวา */
  box?: { x: number; y: number }
  /** เฉลยที่ยอมรับ — โครงเดียวกับ FillBlankItem.answers */
  answers: string[]
  case_sensitive: boolean
  /** เฉพาะโหมด dropdown; ไม่ใส่ = ใช้ bank ของข้อ */
  options?: string[]
}

export interface ImageLabelConfig {
  image_url: string
  answer_mode: ImageLabelAnswerMode
  /** เฉพาะโหมด drag — ยาวกว่าจำนวนจุดได้ ส่วนที่เกินคือตัวลวง */
  bank?: string[]
  markers: ImageLabelMarker[]
}
```

### สามจุดที่ตั้งใจเลือกแบบนี้ ห้ามแก้โดยไม่อ่าน

1. **`image_url` แยกจาก `questions.image_urls`**
   `components/exam/exam-client.tsx` พิมพ์ `image_urls` ออกมาเหนือช่องตอบ**โดยไม่ดูชนิดโจทย์เลย**
   (ดูราวบรรทัด 1021) เก็บรูปไดอะแกรมไว้ตรงนั้นแล้วนักเรียนจะเห็นรูปซ้ำสองใบ
   ใบหนึ่งเป็นภาพประกอบ อีกใบเป็นพื้นที่ตอบ

2. **`point` เป็น % ไม่ใช่ px**
   รูปกว้าง 1600px บนจอ 375px คือคนละสเกล เก็บ px แล้วจุดจะหลุดออกนอกรูปทันทีบนมือถือ
   `lib/image-downscale.ts` ย่อรูปทุกใบเหลือด้านยาวสุด 1600px อยู่แล้ว แต่ขนาดที่**แสดง**ยังต่างกันทุกจอ

3. **สามโหมดส่งคำตอบเป็น "ข้อความของจุดนั้น" เหมือนกันหมด**
   `["จมูก", "", "ปอด", …]` เรียงตามลำดับ marker · ตรวจด้วยกติกาเดียว เฉลยตรึงชุดเดียว
   ครูสลับโหมดทีหลังได้โดยไม่ทำให้คำตอบที่นักเรียนส่งไปแล้วใช้ไม่ได้
   เจตนาเดียวกับ `MatchingAnswerMode` ที่ `slots`/`lines` เป็นแค่การนำเสนอ

### เฉลยที่ตรึงไว้

```
IMGL:[{"answers":["จมูก"],"exact":false},{"answers":["โพรงจมูก"],"exact":false}, …]
```

หนึ่งรายการต่อ **ทุก** marker เรียงตามลำดับ marker — รวมจุดที่ครูไม่ได้ใส่เฉลยด้วย ซึ่งได้ `"answers":[]`
(ตัดออกไม่ได้ เพราะคำตอบนักเรียนเป็นลิสต์เรียงตามตำแหน่ง ตัดตัวหนึ่งแล้วที่เหลือเลื่อนไปตรวจกับจุดผิดหมด)

`exact` คำนวณครั้งเดียวตอนตรึง จากโหมดของข้อและ `case_sensitive` ของจุดนั้น
คำที่เลือกจากดรอปดาวน์หรือลากมาจากคลังเทียบแบบเป๊ะเสมอ เพราะนักเรียนไม่ได้พิมพ์เอง

**เฉลยที่ตรึงต้องพอให้ตรวจได้เองทั้งหมด ห้ามให้สาขาตรวจไปอ่าน `extra_data` สด**
ต่างจากสาขา `FILL:` ที่อ่าน `getBlankType`/`case_sensitive`/`naturalMaxScore` จาก `extra_data` ปัจจุบัน —
นั่นแปลว่าครูแก้โจทย์หลังนักเรียนส่งแล้ว กติกาตรวจจะเปลี่ยนย้อนหลัง
ที่นี่ทำแบบ `COMP:` ซึ่งตรึง `{ type, correct, blankType, caseSensitive, score }` ลงไปทั้งชุด
และแบบ `CLS:` ที่**เอาตัวหารมาจากเฉลยที่ตรึง ไม่ใช่จาก config ปัจจุบัน**

## กติกาที่ต้องไม่แก้โดยไม่อ่านก่อน

ทั้งหมดอยู่ที่ `lib/image-label.ts` ที่เดียว เพราะ **เฉลยที่ตรึง · คะแนนเต็ม · จำนวนข้อย่อยบนการ์ด ต้องเป็นเลขเดียวกัน**

1. **จุดที่ครูวางแต่ไม่ได้ใส่เฉลย ไม่นับเป็นคะแนนเต็ม และไม่ถูกตรวจ**
   เคยพลาดมาแล้วกับข้อย่อยเติมคำของ `composite` — `naturalMaxScore` นับข้อย่อยที่ตัวเรนเดอร์ไม่มีช่องให้กรอก
   นักเรียนเสียคะแนนให้ช่องที่ครูไม่เคยให้มา (ดู `docs/FEATURE_STATUS.md`)
   `imageLabelMarkerCount` ต้องนับเฉพาะจุดที่ตอบได้และตรวจได้

2. **โหมด `dropdown` ที่จุดนั้นไม่มี option ตรงกับเฉลยเลย ถือเป็นจุดที่ไม่ได้ใส่เฉลย**
   เกิดจากการนำเข้าไฟล์ หรือครูแก้ตัวเลือกทีหลัง ปล่อยไว้จะกลายเป็นจุดที่ไม่มีใครตอบถูกได้
   ตรงกับกฎข้อ 2 ของ `classify` ที่เฉลยชี้เลยจำนวนตัวเลือกแล้วถือว่าไม่ได้ใส่เฉลย

3. **โหมด `drag` ที่เฉลยของจุดไม่มีอยู่ใน `bank` ถือเป็นจุดที่ไม่ได้ใส่เฉลย**
   เหตุผลเดียวกับข้อ 2 — ลากอะไรมาใส่ก็ไม่มีวันถูก

4. **ตัวหารตอนให้คะแนนมาจากเฉลยที่ตรึงไว้ ไม่ใช่ `extra_data` ปัจจุบัน**
   ครูลบจุดทิ้งหลังนักเรียนตอบไปแล้ว ตัวหารสดจะหดลงขณะที่ `earned` ยังมาจากชุดเดิมที่ใหญ่กว่า
   แล้ว `scaleScore` จะจ่ายเกินคะแนนที่โจทย์มี — ต้องมีเทสต์คุมเหมือนที่ `classify` มี

5. **`image_label` ไม่มีสถานะ "รอครูตรวจ"** — `is_correct` ไม่เคยเป็น null

6. **ห้ามสลับลำดับ marker** — คำตอบนักเรียนเป็นลิสต์เรียงตามลำดับ marker เทียบกับเฉลยที่ตรึงจาก config เดียวกัน
   สับลำดับเมื่อไหร่ทุกจุดเลื่อนหมด (ปรนัยสับได้เพราะ attempt เก็บ `option_order` ไว้แมปกลับ ที่นี่ไม่มี)

## แผน 9 เฟส และสถานะ

โครงมาจาก `classify` ที่ทำสำเร็จมาแล้ว 7 เฟส **แต่เพิ่มอีก 2** เพราะงานนี้มีสองอย่างที่ `classify` ไม่มี:
ฟอร์มวางพิกัดบนรูป (พื้นผิวใหม่ทั้งอัน) และเลย์เอาต์มือถือที่เป็น**คนละเลย์เอาต์** ไม่ใช่แค่ตารางไหลใหม่

| เฟส | งาน | ด่านที่ต้องผ่าน | สถานะ |
|---|---|---|---|
| 0 | ตัดสินใจ · ตรวจ `supabase migration list` · แตกเบรนช์ · เขียนเอกสารนี้ | local = remote ครบ | ✅ เสร็จ |
| 1 | types + คะแนน + เทสต์ (TypeScript ล้วน ไม่แตะ DB ไม่แตะ UI) | `tsc` ✓ `npm test` ✓ | ✅ เสร็จ |

### breakpoint คือ `xl` ไม่ใช่ `lg` — และวัดมาก่อนค่อยเลือก

เอกสารเฟส 0 เขียนไว้ว่า "อย่าลอกตัวเลขของ `classify` มาเฉย ๆ" ซึ่งถูกต้อง เพราะผลออกมาคนละทาง

| viewport | รูป | กล่อง | ป้ายที่ถูกตัด |
|---|---|---|---|
| 1200 | 367px | 204px | 0 |
| 1024 | 284px | 158px | 1 ("แอมมิเตอร์") |
| 812 | 184px | 102px | 5 (ทุกกล่อง) |

### สองต้นไม้ ไม่ใช่ต้นเดียวไหลใหม่

ต่างจาก `classify` ที่ตารางเดียวเปลี่ยน CSS — ที่นี่เป็นคนละความคิด:
กว้าง = กล่องอยู่ริมสองข้าง มีเส้นโยงเข้ารูป · แคบ = รูปเต็มความกว้าง คำตอบเป็นรายการใต้รูป

**ลำดับต่างกันด้วย** ต้นไม้กว้างเรียงซ้าย-แล้ว-ขวา (2,1 แล้ว 3,4,5) ส่วนต้นไม้แคบเรียงตามลำดับ marker (1,2,3,4,5)
ซึ่งเป็นลำดับที่คนอ่านไล่กับเลขบนรูป · ทำด้วย CSS อย่างเดียวไม่ได้ จึงเรนเดอร์สองชุดแล้วซ่อนด้วย `hidden xl:block` / `xl:hidden`

**`display:none` คือสิ่งที่ทำให้ปลอดภัย**: `elementFromPoint` ไม่คืน element ที่ซ่อน (การลากจึงไม่สับสน) และ
accessibility tree ไม่เห็นมัน (ไม่มีปุ่มซ้ำให้ screen reader อ่าน) · `boxRefs`/`dotRefs` ผูกกับต้นไม้กว้างเท่านั้น
ผ่านพารามิเตอร์ `measured` ไม่งั้นต้นไม้แคบจะเขียนทับ ref แล้วเส้นโยงจะวัดจาก element ที่ไม่มีขนาด

**ราคาที่จ่าย**: มี `<img>` สองตัวใน DOM (URL เดียวกัน เบราว์เซอร์ขอครั้งเดียว) และ JSX ซ้ำบางส่วน

### เลิกตัดข้อความ ให้ขึ้นบรรทัดใหม่แทน

`truncate` → `whitespace-normal break-words` · กล่องในริมกว้าง ~160px ที่ปลายล่างของเลย์เอาต์กว้าง
และ "แอมมิเตอร์" ไม่พอ · การตัดข้อความซ่อน**คำตอบที่อยู่ในกล่อง** ซึ่งเป็นสิ่งเดียวที่กล่องนั้นมีไว้แสดง

### สองด่านที่กันข้อมูลเสียก่อนถึงฐาน
