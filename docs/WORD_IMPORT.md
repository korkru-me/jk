# นำเข้าโจทย์จากไฟล์ Word (.docx)

อัปเดตล่าสุด: 18 กันยายน 2026 · สถานะ: **เฟส 0–3 เสร็จ · รอไฟล์ตัวอย่างจริงเพื่อเริ่มเฟส 4** · เบรนช์ `feat/word-import-by-type`

เอกสารนี้คือช่องทาง handoff ของงานนี้ตาม `AGENTS.md` แชตและ memory ของ agent ไม่ใช่ช่องทาง handoff
ใครมาทำต่อ (Claude Code หรือ Codex เครื่องไหนก็ตาม) ให้เริ่มจากไฟล์นี้

## ปัญหาที่งานนี้แก้

ครูส่วนใหญ่มีไฟล์ข้อสอบและแบบฝึกหัดอยู่แล้วใน Word การจะใช้ KorKru แปลว่าต้องพิมพ์ทุกอย่างใหม่อีกรอบ
ซึ่งเป็นเหตุผลที่คนไม่เริ่มใช้ ถ้าเอาไฟล์เดิมเข้าคลังได้ — แม้ต้องจัดหน้าเพิ่มนิดหน่อย — ต้นทุนการเริ่มใช้จะเหลือเท่ากับ
"จัดไฟล์ตามตัวอย่างหนึ่งครั้ง" แทนที่จะเป็น "พิมพ์คลังทั้งคลังใหม่"

ผลที่ตามมาคือ **หน้าอธิบายรูปแบบไฟล์กับไฟล์ตัวอย่างคือฟีเจอร์ ไม่ใช่เอกสารประกอบ** ครูที่จัดไฟล์ไม่ถูก
แล้วได้ข้อความว่า "อ่านไฟล์ไม่สำเร็จ" เฉย ๆ คือครูที่เลิกใช้ไปเลย

## สถานะรายประเภท

| โปรไฟล์ | ประเภทในระบบ | สถานะการนำเข้า |
|---|---|---|
| อ่านอัตโนมัติ (`auto`) | mcq · written · essay | ✅ ใช้งานได้ — ทางที่มีอยู่เดิม เดาชนิดให้ทีละข้อ |
| ปรนัย (`mcq`) | `mcq` | ✅ อ่านโจทย์ ตัวเลือก รูป สมการ และ**เฉลยที่ทำเครื่องหมายสี**ได้ครบ |
| บรรยาย (`essay`) | `essay` | ✅ ครบ (ไม่ต้องมีเฉลย ครูตรวจเอง) เป็นชนิดสำรองของข้อที่อ่านเฉลยไม่ได้ |
| เติมคำตอบตัวเลข (`random`) | `written` | ⚠️ ครึ่งเดียว — อ่านตัวโจทย์และข้อย่อยได้ แต่**อ่านเฉลยไม่ได้** ครูต้องพิมพ์สูตรเองทุกข้อ |
| เติมคำในช่องว่าง (`fill-blank`) | `fill_blank` | ⬜ ยังไม่รองรับ |
| ถูก-ผิด (`true-false`) | `true_false` | ⬜ ยังไม่รองรับ |
| จับคู่ (`matching`) | `matching` | ⬜ ยังไม่รองรับ |
| เรียงลำดับ (`ordering`) | `ordering` | ⬜ ยังไม่รองรับ |
| ตารางจำแนก (`classify`) | `classify` | ⬜ ยังไม่รองรับ |
| ติดป้ายบนรูป (`image-label`) | `image_label` | ⬜ ยังไม่รองรับ — นำเข้าได้แค่บางส่วนเสมอ (ดู "สิ่งที่ Word บอกไม่ได้") |
| โจทย์ผสม (`composite`) | `composite` | ⬜ ยังไม่รองรับ |
| ส่งไฟล์งาน (`file-upload`) | `file_upload` | ⬜ ยังไม่รองรับ |

`slug` ของโปรไฟล์สะกดตรงกับเส้นทางในหน้า "สร้างโจทย์ใหม่" (`/questions/new/<slug>`) โดยตั้งใจ
ครูจะได้เห็นชื่อและไอคอนชุดเดียวกันทั้งตอนสร้างเองและตอนนำเข้า

## การตัดสินใจที่เจ้าของผลิตภัณฑ์เคาะแล้ว (18 กันยายน 2026)

| เรื่อง | ที่เลือก | เหตุผล |
|---|---|---|
| ไฟล์ที่มีหลายประเภทปนกัน | **เก็บโปรไฟล์ "อ่านอัตโนมัติ" ไว้** และหน้าตรวจร่างยังสลับชนิดรายข้อได้ | ข้อสอบจริงมักเป็น "ตอนที่ 1 ปรนัย / ตอนที่ 2 อัตนัย" การบังคับเลือกประเภทเดียวจะไล่ครูกลุ่มนี้ให้ไปแยกไฟล์ก่อน ซึ่งค้านกับเหตุผลที่ฟีเจอร์นี้มีอยู่ |
| ประเภทที่ยังทำไม่เสร็จ | **แสดงบนหน้าเลือกแบบจาง + ป้าย "เร็ว ๆ นี้"** กดเข้าไปอ่านรูปแบบไฟล์ได้ แต่อัปโหลดไม่ได้ | ครูเห็นทิศทางว่าเว็บกำลังจะรองรับอะไร และจัดไฟล์รอไว้ได้ · ห้ามทำให้ดูเหมือนใช้ได้แล้ว (`AGENTS.md` — ห้ามแสดง UI ที่ยังไม่เสร็จเป็นของจริง) |
| ไฟล์ตัวอย่าง `.docx` | **สร้างด้วยโค้ด** (แพ็กเกจ `docx` ตัวเดียวกับ IOC export) + เทสต์ที่ป้อนไฟล์กลับเข้า parser | ไฟล์นิ่งจะเพี้ยนจากตัวอ่านเงียบ ๆ เมื่อ parser เปลี่ยน แล้วครูจะได้ไฟล์ตัวอย่างที่นำเข้าไม่ได้ |
| ประเภทถัดไปหลังโครงเสร็จ | **เติมคำตอบตัวเลข (`written`) ให้อ่านเฉลยจากไฟล์ได้** | เป็นประเภทที่ทำค้างไว้ครึ่งทาง ปัจจุบันครูต้องพิมพ์เฉลยเองทุกข้อ ซึ่งกินเวลาพอ ๆ กับสร้างใหม่ |

|---|---|

| `/questions/import/word` | **หน้าเลือกประเภทโจทย์** — การ์ดทุกประเภท ใช้ไอคอน/สี/ชื่อชุดเดียวกับหน้าสร้างโจทย์ |

ทั้งคู่ส่ง `withBackHref` มาด้วย ปุ่มย้อนกลับจึงพากลับไปที่เดิมที่ครูจากมา ไม่ใช่หน้าแม่ตาม URL

## กติกาที่ต้องไม่แก้โดยไม่อ่านก่อน

1. **`PROFILE_BY_TYPE` เป็น `Record<QuestionType, ImportProfile>` โดยตั้งใจ**
   เพิ่มค่าใหม่ใน `QuestionType` แล้ว `tsc` จะพังจนกว่าจะมาเติมโปรไฟล์ที่นี่ — เป็นตัวบังคับกฎใน `AGENTS.md`
   ("ประเภทโจทย์ยังไม่เสร็จจนกว่าการนำเข้าจะรองรับ") ด้วยตัวคอมไพเลอร์ ไม่ใช่ด้วยความจำของใคร
   อย่าเปลี่ยนเป็น `Partial<>` หรือ map ธรรมดาเพื่อให้ผ่าน

2. **เครื่องหมายเฉลยเป็นชุดเดียวกันทุกประเภท** — ข้อความสีแดง · ปากกาเน้นข้อความ · ตัวหนา
   ครูเรียนครั้งเดียวต้องใช้ได้กับทุกแบบ ประเภทใหม่ห้ามคิดกติกาเฉลยของตัวเองขึ้นมาใหม่

3. **ทุกกฎในหน้าอธิบายมี `id` และข้อความแจ้งเตือนต้องอ้าง `id` เดียวกัน**
   ครูที่อ่านว่า "กฎข้อ 2 ไม่ผ่าน" ต้องเลื่อนขึ้นไปเจอกฎข้อ 2 ที่เขียนไว้ตรงนั้น ไม่ใช่คำอธิบายคนละชุด

4. **ไฟล์ตัวอย่างต้องสร้างจากโค้ด และต้องมีเทสต์ที่อ่านมันกลับเข้า `parseDocx`**
   ไฟล์ตัวอย่างที่ระบบเองอ่านไม่ออกคือความเสียหายที่ตรวจไม่เจอจนกว่าครูจะเจอ

5. **ข้อที่ไม่มีเฉลยห้ามเข้าคลังในชนิดที่ระบบต้องตรวจเอง**
   ปรนัยที่ไม่มีข้อถูก และอัตนัยที่ไม่มีสูตร จะตรึงคำตอบที่ใช้ไม่ได้ลงทุก attempt แล้วให้ 0 คะแนนเงียบ ๆ
   กติกาเดิมคือบล็อกไม่ให้นำเข้า หรือให้เข้ามาเป็น `essay` ให้ครูตรวจเอง — ประเภทใหม่ต้องทำแบบเดียวกัน

6. **ไฟล์ Word ไม่เคยถูกอัปโหลด** ทั้งการอ่านเกิดในเบราว์เซอร์ของครู มีเฉพาะรูปที่ถูกอัปขึ้น storage
   เป็นคุณสมบัติด้านความเป็นส่วนตัวที่ตั้งใจ (ข้อสอบก่อนสอบคือไฟล์ที่ครูกล้าฝากคนอื่นน้อยที่สุด)
   และเป็นเหตุผลที่ฟีเจอร์นี้ไม่มีค่าใช้จ่ายต่อไฟล์ ห้ามย้ายการอ่านไปฝั่ง server เพื่อความสะดวก

## รูปแบบไฟล์ต่อประเภท

### ยืนยันแล้ว — ใช้จริงในโค้ด

**ทุกประเภท**
- เลขข้อต้องมาจาก**ปุ่มรายการลำดับเลขของ Word** ไม่ใช่เลขที่พิมพ์เอง (Word เก็บเลขไว้ใน `numbering.xml`
  ไม่ได้อยู่ในข้อความ การตัดข้อจึงใช้ระดับนอกสุดของรายการนั้น) · มีทางสำรองสำหรับไฟล์ที่พิมพ์เลขเอง
  แต่รับเฉพาะเมื่อเลขไล่จาก 1 จริง
- สมการที่พิมพ์ด้วยตัวแทรกสมการของ Word แปลงเป็น TeX ให้ และติดคำเตือนให้ครูตรวจทุกข้อ
  (ถ้าดึงเป็นตัวอักษรตรง ๆ "15√2" จะกลายเป็น "152" คือเลขที่ผิดโดยไม่มีอะไรฟ้อง)
- รูปที่ Word เก็บเป็น EMF/WMF แสดงบนเว็บไม่ได้ ต้องแนบใหม่เอง

**ปรนัย**
- ตัวเลือกขึ้นต้นด้วย `1)` `2)` `3)` `4)` อยู่ในตารางหรือคนละบรรทัดก็ได้
- เฉลยทำเครื่องหมายด้วยสีแดง ปากกาเน้นข้อความ หรือตัวหนา
- ตัวเลือกถูกเก็บเป็น**ข้อความล้วน** ตัวยก/ตัวห้อยแปลงเป็นอักขระ Unicode (`m/s²`, `m₁`)

**อัตนัย (บรรยาย)**
- ไม่ต้องมีอะไรเพิ่ม ข้อที่อ่านเฉลยไม่ได้จะลงมาเป็นชนิดนี้เอง

### ร่าง — รอไฟล์ตัวอย่างจริงจากครูก่อนเขียน parser

รูปแบบข้างล่างนี้ยังไม่ตายตัว เป็นข้อเสนอที่แสดงบนหน้าเว็บให้ครูเห็นเพื่อขอความเห็น
`AGENTS.md` ห้ามเขียน parser ตามกติกาที่เดาเอง — กติกาที่เดาผิดคือกติกาที่ครูต้องจัดไฟล์เดิมใหม่ทั้งคลังเพื่อหนี

| ประเภท | ร่างรูปแบบ |
|---|---|
| เติมคำในช่องว่าง | ช่องว่างเขียนเป็นขีดล่างติดกัน (`______`) และ**คำตอบใส่ไว้ในช่องว่างนั้นด้วยตัวอักษรสีแดง** |
| ถูก-ผิด | ข้อความย่อยบรรทัดละข้อ ข้อที่ถูกทำเครื่องหมายสี ที่เหลือถือว่าผิด |
| จับคู่ | ตาราง 2 คอลัมน์ — ซ้ายคือโจทย์ ขวาคือคู่ที่ถูกต้อง เรียงให้ตรงแถวกัน |
| เรียงลำดับ | รายการที่เรียง**ถูกลำดับอยู่แล้ว**ในไฟล์ ระบบสลับให้นักเรียนเอง |
| ตารางจำแนก | ตารางเดียว หัวคอลัมน์คือมิติการจำแนก ช่องใช้ `☑`/`☐` (รูปแบบนี้มาจากใบงานจริงใน `docs/CLASSIFY_QUESTION_TYPE.md`) |
| ติดป้ายบนรูป | รูป 1 รูป + รายการป้าย ครูไปวางจุดบนรูปเองในเว็บ |
| โจทย์ผสม | โจทย์หลัก 1 ย่อหน้า แล้วข้อย่อย ก) ข) ค) ที่แต่ละข้อเป็นคนละชนิดกันได้ |
| ส่งไฟล์งาน | คำสั่งงาน 1 ย่อหน้า ไม่มีเฉลย |

## สิ่งที่ Word บอกไม่ได้ — ต้องบอกครูตรง ๆ ไม่ใช่นำเข้าแบบขาด ๆ

- **ติดป้ายบนรูป** — พิกัดของจุดบนรูปไม่มีทางอยู่ในไฟล์ Word นำเข้าได้อย่างมากแค่รูปกับรายการป้าย
  แล้วครูต้องคลิกวางจุดเองในเว็บ ห้ามทำเป็น "นำเข้าสำเร็จ" ทั้งที่ยังไม่มีจุดสักจุด
- **ส่งไฟล์งาน** — แทบไม่มีอะไรให้อ่านนอกจากคำสั่ง ประหยัดเวลาครูได้น้อยมาก
- **การสุ่มตัวเลข** — โจทย์ที่สุ่มค่าต้องมีสูตรและช่วงของตัวแปร ซึ่งเป็นสิ่งที่ใบงานกระดาษไม่มี
  นำเข้าได้เฉพาะแบบกำหนดคำตอบตายตัว แล้วครูค่อยเปิดโหมดสุ่มทีหลัง

## แผนเฟสและสถานะ

| เฟส | งาน | สถานะ |
|---|---|---|
| 0 | เอกสารนี้ + กฎใน `AGENTS.md` + แตกเบรนช์ | ✅ เสร็จ |
| 1 | หน้าเลือกประเภท · เส้นทางต่อประเภท · ทะเบียนโปรไฟล์ · หน้าอธิบายรูปแบบไฟล์ | ✅ เสร็จ |
| 2 | ตัวสร้างไฟล์ตัวอย่าง `.docx` + เทสต์ที่ป้อนกลับเข้า parser | ✅ เสร็จ |
| 3 | หน้าสรุปผลการอ่าน — บอกว่ากฎข้อไหนไม่ผ่าน แทนข้อความล้มเหลวบรรทัดเดียว | ✅ เสร็จ |
| 4 | เติมคำตอบตัวเลข (`written`) อ่านเฉลยจากไฟล์ได้ | 🔜 **รอไฟล์ตัวอย่างจากเจ้าของผลิตภัณฑ์** |
| 5+ | ทีละประเภท: `fill_blank` → `true_false` → `matching` → `ordering` → `classify` → `image_label` → `composite`/`file_upload` | ⬜ รอไฟล์ตัวอย่างทีละประเภท |

แต่ละเฟสของประเภทใหม่จบในตัว: ตกลงกติกาจากไฟล์จริง → parser + เทสต์ → ไฟล์ตัวอย่าง →
ข้อความแจ้งเตือน → เปลี่ยนสถานะโปรไฟล์เป็น `ready` แล้วป้าย "เร็ว ๆ นี้" จะหายไปเอง

### เฟส 2 — เสร็จ 18 กันยายน 2026

- `lib/docx-import/sample-docx.ts` (ใหม่ · server-only) สร้าง `.docx` จาก `profile.sample` ด้วยแพ็กเกจ `docx`
  หัวข้อจัดกึ่งกลางตัวหนา · ข้อและข้อย่อยใช้ list จริง (decimal + thaiLetters) ให้ Word วาดเลขเอง ·
  ตัวเลือกพิมพ์ `1)` ลงในข้อความเพราะ parser อ่านจากข้อความ · เฉลยเป็นสีแดง `C00000` + ตัวหนา
- `/api/questions/import-sample/[slug]` — ต้องล็อกอิน · ประเภทที่ยังเป็นร่างตอบ 404 (ไฟล์ที่เขียนตามกติกาที่ยังไม่นิ่ง
  จะทำให้ครูต้องจัดไฟล์ใหม่สองรอบ) · ชื่อไฟล์ไทยส่งด้วย `filename*=UTF-8''`
- `sample-docx.test.ts` (ใหม่ 13 เทสต์) — **สร้างไฟล์ตัวอย่างแล้วป้อนกลับเข้า `parseDocx` ทันที** ตรวจจำนวนข้อ
  ตัวเลือก เฉลยที่อ่านได้ ป้ายข้อย่อย ก) ข) และหัวข้อที่ต้องไม่หลุดเข้าไปในโจทย์
- ปุ่ม "ดาวน์โหลดไฟล์ตัวอย่าง .docx" อยู่ใต้ภาพตัวอย่างในหน้าอธิบาย เฉพาะประเภทที่พร้อมแล้ว

**เทสต์ตัวนี้จับบั๊กจริงได้ทันทีที่เขียนเสร็จ** — ไฟล์ตัวอย่างของโปรไฟล์ "อ่านอัตโนมัติ" มีหัวข้อ "ตอนที่ 2 แสดงวิธีทำ"
คั่นกลาง แล้วบรรทัดนั้นไปเกาะท้ายโจทย์ข้อก่อนหน้า ทั้งในเนื้อโจทย์และในชื่อโจทย์
ข้อสอบไทยที่แบ่ง "ตอนที่ 1 ปรนัย / ตอนที่ 2 อัตนัย" เป็นรูปแบบปกติที่สุด และเป็นเหตุผลที่โปรไฟล์อ่านอัตโนมัติมีอยู่
จึงแก้ที่ตัวอ่าน ไม่ใช่แก้ไฟล์ตัวอย่างให้เลี่ยงปัญหา:

- `docx.ts` อ่าน `w:jc` เพิ่มเป็น `DocxParagraph.centered`
- `draft.ts` — `isSectionHeading()` ตัดหัวข้อของตอนถัดไปออกจาก**ท้าย**เนื้อโจทย์ (ตำแหน่งเดียวที่หัวข้อของตอนถัดไปอยู่ได้)
  เงื่อนไขแคบไว้: บรรทัดสั้น (≤ 80 ตัวอักษร) ที่เป็น Word heading style หรือ **จัดกึ่งกลาง + ตัวหนาทั้งบรรทัด**
  และไม่ขึ้นต้นด้วย `1)` (นั่นคือตัวเลือก)
- **ไม่ทิ้งข้อความ** บรรทัดที่ถูกตัดไปรวมกับ `preamble` ซึ่งหน้านำเข้าแสดงอยู่แล้วว่า "ข้ามส่วนหัวเอกสาร: …"
  ถ้าตัดผิดครูจะเห็นว่าอะไรถูกยกออกไป
- `draft.test.ts` เพิ่ม 4 เทสต์: หัวข้อกึ่งกลาง · Word heading style · บรรทัดตัวหนาที่ชิดซ้าย (ต้องอยู่ในโจทย์ต่อไป)
  · ตัวเลือกที่จัดกึ่งกลาง (ต้องไม่ถูกตัด)

### เฟส 3 — เสร็จ 18 กันยายน 2026

- `lib/docx-import/preflight.ts` (ใหม่ · pure) เทียบผลการอ่านกับรูปแบบที่ครูเลือก แล้วคืนผลเป็นรายข้อของ**กฎ**
  ทุกผลตรวจอ้าง `ImportRule.id` ตัวเดียวกับที่หน้าอธิบายแสดง หน้าจอจึงพูดว่า "กฎข้อ 2 ไม่ผ่าน" ได้โดยที่ครูเลื่อนขึ้นไปอ่านกฎข้อ 2 ได้จริง
- `draft.ts` คืน `numbering: 'list' | 'typed' | 'none'` เพิ่ม — ไฟล์ที่พิมพ์เลขข้อเองอ่านได้ก็จริง แต่จะเตือนว่าแทรกข้อกลางไฟล์ทีหลังแล้วเลขจะเพี้ยน
- **ตรวจเฉพาะกฎที่โปรไฟล์นั้นมีจริง** — บรรยายไม่มีตัวเลือกและไม่มีเฉลย รายงานจึงไม่ตรวจสองข้อนั้นให้ ไม่อย่างนั้นคือการสร้างความผิดที่ไม่มีอยู่
- โจทย์ที่ไม่มีตัวเลือกถือเป็น **fail** เมื่อครูเลือกโปรไฟล์ปรนัย แต่เป็น **pass** บนโปรไฟล์อ่านอัตโนมัติ (ไฟล์ผสมคือสิ่งที่โปรไฟล์นั้นมีไว้รับ)
- หน้าจอ: ไฟล์ที่ไม่มีโจทย์เลยขึ้นการ์ดแดงพร้อมเช็กลิสต์ + ปุ่มดาวน์โหลดไฟล์ตัวอย่างมาเทียบ (สถานะใหม่ `rejected`
  ไม่อัปโหลดรูปใด ๆ เพราะยังไม่มีโจทย์ให้แขวนรูป) · ไฟล์ที่อ่านได้บางส่วนขึ้นรายการเฉพาะข้อที่ไม่ผ่านไว้บนหัวหน้าตรวจร่าง
  (ผ่านหมดจะไม่ขึ้นอะไรเลย เพราะแถวติ๊กถูกสีเขียวยาว ๆ มีแต่ดันโจทย์ให้ลงไปอยู่ล่างจอ)
- `preflight.test.ts` (ใหม่ 7 เทสต์) รวมข้อที่สำคัญที่สุด: **ไฟล์ตัวอย่างที่แอปแจกต้องผ่านทุกกฎและไม่มีข้อที่ต้องตรวจเลย**
  (เทสต์ตัวนี้จับได้ว่าไฟล์ตัวอย่างของโปรไฟล์อ่านอัตโนมัติมีตัวเลือกแค่ 3 ข้อ ซึ่งตัวอ่านเตือนว่าอาจเป็นข้อย่อย จึงเพิ่มเป็น 4)
