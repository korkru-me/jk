# Scope และลำดับการพัฒนา

อัปเดตล่าสุด: 3 กันยายน 2026

## เป้าหมายของระยะปัจจุบัน

ทำให้ครูสามารถเดินทางครบเส้นทางตั้งแต่สร้างโจทย์ ไปจนถึงมอบหมาย นักเรียนส่งคำตอบ ระบบตรวจคะแนน และครูติดตามภาพรวม โดยไม่มีขั้นตอนหลักที่เป็นข้อมูลจำลอง

เจ้าของผลิตภัณฑ์ได้จัดลำดับ “วิจัยการศึกษา” ขึ้นมาพัฒนาเป็นงานต่อยอดแบบแยกระยะ โดยระยะที่ 1 อนุมัติ UX/spec แล้ว และระยะที่ 2 เริ่มทำเส้นทางจริงจาก schema, RLS และเมนู ก่อนเพิ่มการสร้างโครงการ คะแนน และผลสถิติทีละจุดตรวจ งานนี้ยังต้องรักษาหลักข้อมูลจริง สิทธิ์ห้องเรียน และ Definition of done เดียวกับฟีเจอร์หลัก

## In scope: ต้องทำให้เสร็จก่อน

### 1. คลังโจทย์

- สร้าง แก้ไข ทำสำเนา ลบ ค้นหา และจัดหมวดหมู่โจทย์
- รองรับประเภทโจทย์ที่โค้ดประกาศไว้โดยไม่ทำลายโจทย์เก่า
- เก็บภาพ ไฟล์ เฉลย สูตร ตัวแปร หน่วย tolerance และคะแนนอย่างถูกต้อง
- สร้างตัวเลือกหลอกสำหรับโจทย์ปรนัยแบบคำนวณ
- สุ่มตัวเลข ตรวจความสมเหตุสมผลของชุดตัวเลข และคำนวณคำตอบตาม attempt
- สร้างแฟ้มโจทย์และแบ่งปันตามขอบเขตสิทธิ์

### 2. ห้องเรียนรายวิชา

- ครูสร้าง จัดเก็บถาวร กู้คืน และลบห้องเรียนตาม lifecycle
- นักเรียนเข้าร่วม/ออกจากห้องด้วยรหัส
- ครูจัดการ roster และมองเห็นงานของห้อง
- ครูผู้สอนร่วมเข้าร่วมผ่านคำเชิญและได้รับสิทธิ์ `admin`, `manage` หรือ `view`
- โพสต์ ประกาศ ความคิดเห็น และการแจ้งเตือนทำงานตามสิทธิ์

### 3. งานและข้อสอบ

- ครูเลือกโจทย์หรือแฟ้มโจทย์ และมอบหมายให้หนึ่งหรือหลายห้อง
- รองรับ draft, published และ closed
- รองรับงาน (`exercise`) และข้อสอบ (`exam`)
- รองรับช่วงเวลา จำกัดเวลา access code จำนวนครั้ง กลยุทธ์คะแนน และเกณฑ์ผ่าน
- รองรับสลับลำดับข้อและตัวเลือกโดยไม่ทำให้เฉลยผิด
- ใช้โจทย์ที่เลือกไว้เป็น “คลังของงาน” แล้วสุ่มจ่ายให้นักเรียนคนละไม่กี่ข้อได้ (`random_question_count`) ทั้งงานและข้อสอบที่เป็นโหมดออนไลน์ ชุดที่สุ่มได้ถูกตรึงต่อ attempt และรอบใหม่สุ่มชุดใหม่ · โหมดพิมพ์สุ่มรายคนไม่ได้
- งานออนไลน์เปิด/ปิดเครื่องคิดเลขวิทยาศาสตร์และกระดาษทดเป็นรายงานได้ โดยแป้นคณิตศาสตร์ยังเป็น input accessibility ของช่องตัวเลขเสมอ
- ครูแก้ไข ทำสำเนา พิมพ์ และดูผลได้ตามสิทธิ์

### 4. การส่งคำตอบและตรวจคะแนน

- สร้าง attempt อย่างปลอดภัยและไม่เกินข้อจำกัด
- ตรึงค่าตัวแปรสุ่ม เฉลย ลำดับข้อ และลำดับตัวเลือกต่อ attempt
- บันทึกคำตอบระหว่างทำและบังคับเวลาฝั่ง server
- ตรวจอัตโนมัติในชนิดที่รองรับ
- รองรับคำตอบที่ต้องให้ครูตรวจ เช่น essay, free text หรือไฟล์
- รองรับกระดาษทดแบบ local-only, การเลือกแนบเป็นวิธีทำที่แก้ต่อได้ก่อนส่ง และรูปถ่ายเป็น fallback โดยไม่อัปโหลดสิ่งที่นักเรียนทดเฉย ๆ
- ครูดูคำตอบ ให้ feedback และแก้คะแนนได้พร้อม audit ที่เพียงพอ
- สรุปคะแนนแบบ best, average หรือ latest โดยไม่สูญเสีย attempt เดิม

### 5. ห้องโฮมรูม

- โฮมรูมไม่มีงานรายวิชาของตัวเอง แต่รวมงานจากห้องรายวิชาที่นักเรียนสังกัด
- ครูประจำชั้นเห็นงานที่เสร็จ งานค้าง ปฏิทิน และภาพรวมรายคน
- นักเรียนเห็นภาพรวมงานของตัวเองในโฮมรูม
- รองรับข้อมูลพื้นฐานนักเรียนและบันทึกส่วนตัวของครูประจำชั้นตามสิทธิ์
- ห้ามเปิดข้อมูลสุขภาพ ครอบครัว ที่อยู่ หรือผู้ปกครองแก่สมาชิกองค์กรทั่วไป

## Later: หลังแกนหลักเสร็จ

- แบบสำรวจความเครียด ความถนัด หรือแบบสำรวจอื่น
- ระบบงานวิจัยการศึกษา — เจ้าของผลิตภัณฑ์จัดลำดับขึ้นมาทำแล้วตามแผน `docs/EDUCATION_RESEARCH.md`; ยังไม่ถือว่าพร้อมใช้จริงจนกว่าจะครบทุกระยะและ Definition of done
- ระบบจ่ายเงินจริง invoice cancellation และ entitlement enforcement
- parent portal ที่ใช้งานจริง
- learning paths แบบมีเงื่อนไข
- dashboard เชิงพยากรณ์หรือ insight ขั้นสูง
- audit trail ที่เชื่อมกับเหตุการณ์จริงทั้งระบบ

## Out of scope ในระยะนี้

- การยืนยันมาตรฐานหรือ compliance ที่ยังไม่มีหลักฐาน
- การประกาศ SLA, SSO, custom domain หรือโควตาแพ็กเกจเป็นบริการจริง
- การใช้ข้อมูลนักเรียนเพื่อวิจัยหรือวิเคราะห์ข้ามวัตถุประสงค์โดยไม่มี consent
- การ refactor ใหญ่เพื่อความสวยงามที่ไม่ช่วยเส้นทาง MVP

## Definition of done สำหรับฟีเจอร์ MVP

ฟีเจอร์จะไม่ถือว่า “เสร็จ” เพียงเพราะมีหน้า UI ต้องมีครบดังนี้:

- เส้นทางครูและนักเรียนทำงานได้ด้วยข้อมูลจริง
- authorization ฝั่ง server และ RLS สอดคล้องกัน
- loading, empty, error และ permission-denied states ใช้งานได้
- ข้อมูลไม่ข้าม organization/classroom โดยไม่ได้รับอนุญาต
- TypeScript และ production build ผ่าน
- มีการทดสอบกรณีปกติ ขอบ และการโจมตีสิทธิ์ที่เกี่ยวข้อง
- ข้อจำกัดหรือส่วน manual ถูกบอกผู้ใช้อย่างตรงไปตรงมา
- `docs/FEATURE_STATUS.md` ถูกอัปเดต

## การเปลี่ยนขอบเขต

หากงานใหม่ไม่อยู่ใน In scope ให้ AI แจ้งว่าเป็น Later/Out of scope และถามเจ้าของผลิตภัณฑ์ก่อนขยายงาน เว้นแต่คำสั่งล่าสุดของเจ้าของผลิตภัณฑ์ระบุการเปลี่ยนลำดับอย่างชัดเจน

เจ้าของผลิตภัณฑ์จัดลำดับเครื่องมือคณิตศาสตร์ กระดาษทด การแนบวิธีทำ และกระดานสอนเข้าระยะปัจจุบันเมื่อ 3 กันยายน 2026 ขอบเขต การตัดสินใจ และลำดับเฟสอยู่ใน `docs/STUDENT_MATH_TOOLS.md`
