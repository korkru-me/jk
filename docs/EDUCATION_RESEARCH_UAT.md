# UAT วิจัยการศึกษา ระยะที่ 3

อัปเดตล่าสุด: 4 กันยายน 2569

## สรุปสถานะ

ระยะ 3.1 ด้านความพร้อมทางเทคนิคและการทดสอบแบบไม่เขียนข้อมูลลง production **ผ่านแล้ว** บน branch `feat/education-research-uat` โดยใช้ข้อมูลจริงเฉพาะการอ่านหน้ารวม ห้องเรียน และตัวเลือกในหน้าสร้างโครงการ ส่วน fixture ใช้เฉพาะ automated test

ระยะ 3.2 การยอมรับด้วยโครงการและคะแนนของห้องจริง **ยังไม่เริ่ม** เพราะบัญชีที่ใช้ตรวจยังไม่มีโครงการวิจัย และไม่มีโครงการ QA ที่ยืนยันว่าแยกจากนักเรียนจริง การสร้างโครงการชื่อทดสอบหรือคะแนนสมมติลงฐานข้อมูลจริงจะขัดกับหลัก “production แสดงข้อมูลจริง” จึงหยุดก่อนการกด “สร้างโครงการวิจัย”

## สิ่งที่ตรวจผ่าน

### เส้นทางครูด้วยบัญชีจริง

- `/research` อ่านฐานข้อมูลจริงและแสดง 0 โครงการ, 0 กำลังดำเนินการ, 0 พร้อมวิเคราะห์ พร้อม empty state ที่ถูกต้อง
- เมนู “วิจัยการศึกษา” แสดงสำหรับบัญชีครู/แอดมินที่ใช้ตรวจ
- `/research/new` อ่านห้องเรียนรายวิชาและจำนวนสมาชิกจริง ไม่เติมห้องหรือจำนวนนักเรียนตัวอย่าง
- เดิน wizard แบบไม่บันทึกจากข้อมูลโครงการ → กรอกคะแนนบนเว็บ → Excel → หน้าตรวจสอบได้
- validation กันการไปขั้นถัดไปเมื่อยังไม่ระบุคะแนนเต็ม และคงคะแนนเต็มก่อน–หลังให้ตรงกัน
- ไม่พบ console error หรือ warning ระหว่างเส้นทางที่ตรวจ

### ความถูกต้องของสถิติ

- ตรวจ `n`, ค่าเฉลี่ย, sample S.D., S.D. ของผลต่าง, standard error, `df`, `t` และ two-sided `p`
- paired t-test ให้ผลตรงกับตัวอย่าง Program 3 ของ NIST Dataplot: `n = 15`, ผลต่างเฉลี่ย `8.00000`, S.D. ผลต่าง `11.02594`, `t(14) = 2.81008`, `p = .01390`
- ตรวจกรณีคะแนน 0, คะแนนขาด, ข้อมูลน้อยกว่า 2 คน, ความแปรปรวนเป็นศูนย์, คะแนนเต็มก่อน–หลังไม่เท่ากัน และห้ามแสดง `p = .000`
- one-sample criterion t-test ใช้คะแนนเกณฑ์จริงที่ไม่ปัดเศษก่อนคำนวณ

แหล่งอ้างอิง oracle: [NIST Dataplot — T TEST, Program 3](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/t_test.htm)

### คะแนนและ Excel

- แม่แบบ `.xlsx` แยกเลข 0 ออกจากช่องว่าง และ round-trip โครงการ/template/แถวได้
- ปฏิเสธสูตรในช่องคะแนน ไฟล์ที่ไม่ใช่แม่แบบ KorKru และนามสกุลที่ไม่ใช่ `.xlsx`
- ไม่อ่าน workbook ก่อนยืนยัน session และสิทธิ์จัดการโครงการ
- ปฏิเสธไฟล์จากคนละโครงการและตรวจรุ่น template ก่อนสร้าง preview batch
- ทดสอบขอบเขตที่รองรับ 2,000 คนครบถึงแถวสุดท้าย

### การส่งออกและความเป็นส่วนตัว

- anonymous export ไม่ query ชื่อหรือรหัสนักเรียน ไม่ใส่ UUID/เลขที่ และสุ่มลำดับก่อนกำหนด `P001…`
- identified export ใส่ชื่อ/รหัสเฉพาะเมื่อเลือกโหมดนี้
- ทดสอบข้ามขีดจำกัด response 1,000 แถวแล้วได้ครบ 1,001 คนในไฟล์และ audit
- ถ้าบันทึก append-only export audit ไม่สำเร็จ ระบบไม่ส่ง workbook
- route ปฏิเสธผู้ไม่มี session หรือมีสิทธิ์ `view` อย่างเดียวก่อนอ่านข้อมูลรายบุคคล

### Schema และ RLS

- `supabase migration list` แสดง migration ในเครื่องและ remote ตรงกันถึง `20260904133949`
- `supabase db lint --linked` ไม่มี error
- มี warning เดิม 3 รายการ: `generate_class_code` 1 กลุ่ม และฟังก์ชันงานวิจัย 2 รายการ (`remap_education_research_sections`, `create_education_research_import_batch`) ยังไม่พบผลลัพธ์ผิดจาก regression test และไม่ได้แก้ schema ในระยะนี้

## ข้อบกพร่องที่แก้ใน UAT

พบว่า PostgREST จำกัด response ครั้งละ 1,000 แถว แต่บางเส้นทางยังอ่านครั้งเดียว ทำให้ห้องใหญ่มีโอกาสแสดงหรือส่งออกข้อมูลไม่ครบโดยไม่แจ้ง จึงเปลี่ยนให้แบ่งหน้าและเรียงลำดับแบบคงที่ใน:

- ภาพรวมโครงการและจำนวนคู่คะแนน
- หน้าข้อมูลคะแนนและประวัติ 2,000 เหตุการณ์ล่าสุด
- หน้ากรอกคะแนนและฉบับร่าง
- หน้า preview การนำเข้า Excel
- route ดาวน์โหลดแม่แบบ Excel

การค้น profile/ชื่อผู้แก้คะแนนเปลี่ยนเป็น query แบบแบ่งชุดเพื่อลดความยาว filter และหน้าข้อมูลคะแนนเลิก query email ที่ไม่ได้ใช้

## สิ่งที่ยังต้องใช้ข้อมูลจริงจึงตรวจได้

รายการต่อไปนี้เป็น release gate ของระยะ 3.2 ห้ามบันทึกว่า “ผ่าน” จนกว่าจะมีโครงการจริง:

1. สร้างโครงการจริงจากห้องจริงและตรวจว่า cohort ถูกตรึงตรง roster
2. ทำข้อสอบก่อน–หลังด้วยบัญชีนักเรียนจริงอย่างน้อย 2 คน หรือใช้คะแนนจริงผ่าน manual/Excel
3. ตรวจการ sync submission และการ re-grade จากข้อสอบ KorKru
4. เทียบผลสถิติของชุดคะแนนจริงกับโปรแกรมสถิติอีกชุดหนึ่ง
5. ดาวน์โหลด anonymous/identified workbook แล้วตรวจแถว คะแนน และข้อมูลระบุตัวบุคคลด้วยตา
6. ลอง owner, co-teacher `manage`, co-teacher `view` และ student ด้วยบัญชีแยกกัน

## ข้อสังเกตด้านข้อความบนหน้าเว็บ

หน้าตรวจสอบของ wizard แสดงข้อความเกี่ยวกับ “สร้างงานในห้องเรียน”, “ข้อสอบทำได้ 1 ครั้ง” และ “สำเนาข้อสอบพร้อมตรึง” แม้เลือก manual + Excel ทั้งสองรอบ ฟังก์ชันสร้างโครงการทำงานตาม source จริง แต่ข้อความอาจทำให้ครูเข้าใจว่าจะมี assignment ออนไลน์ จึงเก็บเป็นงาน UI ที่ต้องทำภาพร่างให้เจ้าของผลิตภัณฑ์อนุมัติก่อนแก้ตามข้อตกลงเดิม
