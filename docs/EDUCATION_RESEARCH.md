# วิจัยการศึกษา

สถานะ: ระยะที่ 2.4 เสร็จแล้ว — มีหน้าผลวิเคราะห์จากคะแนนจริง แยก paired-samples t-test ก่อน–หลังออกจาก one-sample t-test เทียบเกณฑ์ และมีแท็บตรวจข้อมูลที่ใช้แบบแบ่งหน้าแล้ว ระยะนี้ไม่มี migration ใหม่

อัปเดตล่าสุด: 24 สิงหาคม 2569

## สถานะการพักงานและจุดกลับมา

- เจ้าของผลิตภัณฑ์ขอพักการพัฒนางานวิจัยไว้หลังระยะ 2.4 เพื่อไปพัฒนาระบบป้องกันการโกงสอบของนักเรียนในแชทอื่นก่อน งานดังกล่าวเป็นคนละขอบเขตกับแชทงานวิจัยนี้และไม่ควรนำมาปะปนโดยอัตโนมัติ
- เมื่อกลับมาทำงานวิจัย ให้เริ่มจาก fetch และตรวจ commit ล่าสุดจาก Git ก่อน เพราะงานในแชทระบบป้องกันการโกงอาจเปลี่ยนโค้ด assignment/exam ที่เกี่ยวข้อง
- จุดทำงานถัดไปของงานวิจัยคือให้เจ้าของผลิตภัณฑ์ตรวจระยะ 2.4 ด้วยคะแนนจริง แล้วทำภาพกล่องเลือกส่งออกข้อมูลรายบุคคลแบบ “ไม่ระบุตัวตน”/“มีชื่อและรหัส” เพื่ออนุมัติก่อนเขียนโค้ด
- หน้าคุมสอบสดยังคงพักไว้ตามเดิม และต้องเตือนเจ้าของผลิตภัณฑ์อีกครั้งเมื่อทุกเฟสของงานวิจัยรวมงานส่งออกเสร็จแล้ว

## เป้าหมายรุ่นแรก

ช่วยครูทำวิจัยพัฒนาผู้เรียนแบบกลุ่มเดียว โดยนำคะแนนสอบก่อนเรียนและหลังเรียนของนักเรียนกลุ่มเดิมมาวิเคราะห์ เว็บรับผิดชอบเฉพาะการรวบรวม ตรวจความพร้อม วิเคราะห์ และนำเสนอข้อมูลคะแนน ไม่ครอบคลุมการเขียนรายงานวิจัยทั้งฉบับ

## สถานะการพัฒนาระยะ 2.4

- `/research/new` ใช้ข้อมูลห้องเรียน รายชื่อนักเรียน โจทย์ และแฟ้มจริง ครูเลือกแหล่งคะแนนได้จากข้อสอบ KorKru, กรอกบนเว็บ หรือ Excel และระบบไม่สร้างข้อมูลตัวอย่าง
- การสร้างโครงการออนไลน์ทำแบบ atomic ในฐานข้อมูล: ตรึง cohort จาก roster, คัดลอกโจทย์ที่เลือกเป็นสำเนาส่วนตัวซึ่งแก้/ลบไม่ได้, สร้าง assignment ก่อน–หลัง และบันทึก measurement ที่เชื่อมกัน หากขั้นใดผิดพลาดจะไม่เหลือโครงการครึ่งชุด
- สำเนาข้อสอบวิจัยถูกซ่อนจากคลังโจทย์ การค้นหา ตัวนับ และหน้าผู้ดูแล แต่ assignment ของโครงการยังอ่านสำเนาเหล่านี้เพื่อสอบ พรีวิว พิมพ์ และตรวจคำตอบได้
- `/research/[id]` แสดงสถานะ ห้องเรียน cohort ความคืบหน้าคะแนน และคู่คะแนนจากข้อมูลจริง พร้อมพรีวิวมุมมองนักเรียน แก้ข้อมูลพื้นฐาน และจัดกำหนดการ/รหัสเข้าของข้อสอบทั้งสองรอบ
- รหัสเข้าของข้อสอบวิจัยไม่สนตัวพิมพ์เล็ก–ใหญ่ และยังอยู่ภายใต้การล็อกอิน สมาชิกห้อง ช่วงเวลา และข้อจำกัดหนึ่งครั้งของ assignment เดิม
- `/research/[id]/data` อ่าน cohort คะแนน แหล่งคะแนน และประวัติจากข้อมูลจริง ผู้มีสิทธิ์ `view` ยังเห็นได้เฉพาะ metadata ส่วนข้อมูลรายคนต้องเป็นเจ้าของห้องหรือ co-teacher `admin/manage`
- คะแนนของ measurement แบบข้อสอบ KorKru ซิงก์จาก submission ที่ส่ง/ตรวจแล้วและอัปเดตตามการ re-grade โดยจับคู่ด้วย `student_id` ใน cohort ไม่ใช้ชื่อ
- `/research/[id]/data/manual` แยกช่องว่างออกจาก 0 ตรวจคะแนนกับคะแนนเต็ม เก็บฉบับร่างรายครู และขอเหตุผลเมื่อเปลี่ยนคะแนนเดิมก่อนบันทึกจริง
- `/research/[id]/data/import` สร้างแม่แบบ `.xlsx` จาก cohort และคะแนนปัจจุบันจริง ล็อกข้อมูลระบุตัวนักเรียน ใช้ row token ที่ซ่อน และรับเฉพาะแม่แบบของโครงการ/รุ่นที่ตรงกัน
- `/research/[id]/data/import/[batchId]` แสดง preview พร้อมค่าเดิม→ค่าใหม่ แยกพร้อม/คำเตือน/ข้อผิดพลาด และยืนยันแบบ all-or-nothing โดยตรวจคะแนนปัจจุบันซ้ำเพื่อกันข้อมูลเปลี่ยนคั่นระหว่างตรวจ
- ไฟล์ต้นฉบับอ่านในหน่วยความจำ ไม่อัปโหลดเข้า Storage และไม่สร้าง public URL; server ตรวจนามสกุล MIME ขนาด โครงสร้าง ZIP อัตราการบีบอัด macro สูตรในช่องคะแนน และจำนวนแถวก่อนอ่าน
- `/research/[id]/results` คำนวณจากคะแนนจริงล่าสุดทุกครั้งโดยไม่เก็บผลสรุปซ้ำในฐานข้อมูล แท็บก่อน–หลังใช้เฉพาะคู่คะแนนสมบูรณ์ ส่วนแท็บเทียบเกณฑ์ใช้ทุกคนที่มีคะแนนหลังเรียน จึงมี `n` ต่างกันได้
- ผลทั้งสองแบบแสดง `n`, ค่าเฉลี่ย, sample S.D., ผลต่างเฉลี่ย, ช่วงเชื่อมั่น 95%, `t(df)`, two-sided `p` และขนาดอิทธิพล โดยรายงาน `p < .001` แทน `p = .000`
- แกนคำนวณตรวจข้อมูลน้อยกว่า 2 คน คะแนนเต็มก่อน–หลังไม่เท่ากัน ค่าเกณฑ์ไม่ถูกต้อง และ S.D. ของผลต่างเป็นศูนย์; กรณีเหล่านี้แสดง “ยังคำนวณไม่ได้” พร้อมเหตุผลโดยไม่ส่ง `NaN` หรือ infinity ไปหน้าเว็บ
- แท็บ “ข้อมูลที่ใช้” อ่านอย่างเดียว มีค้นหา/กรอง/pagination ประวัติคะแนน และสถานะใช้/ไม่ใช้/ผ่าน/ไม่ผ่าน โดยส่งรายละเอียดรายคนไป browser เฉพาะหน้าปัจจุบันและจำกัดสิทธิ์เจ้าของห้องหรือ co-teacher `admin/manage`
- กราฟใช้แกน 0 ถึงคะแนนเต็ม ระบุ error bar เป็น S.D. และผลสรุปสำหรับรายงานแยกผลระดับกลุ่มออกจากจำนวนผู้ผ่านเกณฑ์รายบุคคล พร้อมคำเตือนเรื่องข้อจำกัดเชิงเหตุผลของแบบแผนกลุ่มเดียว
- ครูคัดลอกข้อความรายงานและดาวน์โหลดตารางสรุป `.csv` ที่มีเฉพาะค่าสถิติรวมได้ ไฟล์สรุปนี้ไม่ใส่ชื่อ รหัส หรือคะแนนรายบุคคล
- หน้าคุมสอบสดยังคงเลื่อนไปหลังงานวิจัยทุกเฟสเสร็จตามที่ยืนยันไว้

## ขอบเขตที่ยืนยันแล้วจากคำขอ

- รองรับเฉพาะงานวิจัยพัฒนาผู้เรียนแบบก่อนเรียน–หลังเรียนในรุ่นแรก
- ครูสร้างหรือเลือกข้อสอบจากระบบ Korkru แล้วมอบหมายให้นักเรียนในห้องเรียนทำ
- ระบบจับคู่คะแนนก่อนเรียนและหลังเรียนเป็นรายคนก่อนวิเคราะห์
- ครูเพิ่มคะแนนได้ทั้งจากข้อสอบออนไลน์ใน Korkru, กรอกคะแนนบนเว็บ และอัปโหลดแม่แบบ Excel ที่ดาวน์โหลดจากโครงการ
- ผู้เข้าร่วมทุกคนต้องสมัครบัญชี Korkru และเป็นสมาชิก roster ของห้องเรียนก่อน ระบบรุ่นแรกไม่รองรับรายชื่อนักเรียนภายนอกที่ไม่มีบัญชี
- หนึ่งโครงการวิจัยผูกกับหนึ่งห้องเรียนเท่านั้นในรุ่นแรก เพื่อให้ roster การจับคู่คะแนน แม่แบบ Excel และสิทธิ์เข้าถึงมีแหล่งอ้างอิงเดียว
- ผลลัพธ์ต้องสรุปได้อย่างน้อย `n`, ค่าเฉลี่ย, `S.D.`, `t` และ `p` ตามตัวอย่างที่ผู้ใช้แนบ
- เมนูฝั่งครูและผู้ดูแลระบบเพิ่มรายการ “วิจัยการศึกษา” นักเรียนยังเข้าทำข้อสอบผ่านห้องเรียนตามปกติ
- ก่อนพัฒนาหน้าเว็บจริง ต้องทำภาพร่างให้เจ้าของผลิตภัณฑ์ตรวจและอนุมัติทีละหน้า
- ข้อมูล ตัวเลข สถานะ และผลวิเคราะห์บนเว็บจริงต้องมาจากข้อมูลจริงของผู้ใช้ ห้ามฝังข้อมูลตัวอย่างไว้ในหน้าที่ใช้งานจริง

## หลักการใช้ข้อมูลจริง

- ตัวเลขในภาพร่างเป็นข้อมูลสมมติเพื่อสื่อสารรูปแบบหน้าจอเท่านั้น
- หน้าใช้งานจริงต้องอ่านโครงการ ห้องเรียน รายชื่อนักเรียน แบบทดสอบ การส่งคำตอบ และคะแนนจากฐานข้อมูลตามสิทธิ์ของครูผู้ใช้งาน
- จำนวน “โครงการทั้งหมด”, “กำลังเก็บข้อมูล”, “พร้อมวิเคราะห์” และความคืบหน้าแต่ละขั้นต้องคำนวณจากข้อมูลจริงทุกครั้ง
- เมื่อยังไม่มีข้อมูล ให้แสดง empty state พร้อมคำแนะนำหรือปุ่มเริ่มต้น ห้ามนำข้อมูลสมมติมาเติมให้หน้าดูเต็ม
- ระหว่างพัฒนาอาจใช้ fixture เฉพาะใน test หรือ Storybook ได้ แต่ต้องแยกจาก production data path อย่างชัดเจน

## ช่องทางนำเข้าคะแนน

รุ่นแรกต้องรองรับข้อมูลจริงสามช่องทาง โดยบันทึกแหล่งที่มาของคะแนนและใช้กฎตรวจสอบชุดเดียวกัน

1. คะแนนจากข้อสอบออนไลน์ใน Korkru
   - เชื่อมจาก submission ของนักเรียนโดยตรง
   - เมื่อเลือกข้อสอบ ระบบสร้าง assignment ในห้องที่ผูกกับโครงการให้อัตโนมัติ
   - แบบทดสอบที่ใช้เป็นคะแนนวิจัยทำได้ 1 ครั้ง
   - เมื่อเริ่มมีคะแนนแล้ว ระบบล็อกแหล่งคะแนนของรอบนั้น แต่ครูยังแก้คะแนนรายคนได้โดยต้องเก็บประวัติการแก้ไข
2. กรอกคะแนนบนเว็บ
   - แสดงรายชื่อนักเรียนจริงจาก roster ของห้อง ครูกรอกคะแนนก่อนเรียนและหลังเรียนในแถวของนักเรียนแต่ละคน
   - รองรับการเว้นช่องว่างสำหรับนักเรียนที่ยังไม่มีคะแนน และตรวจว่าคะแนนเป็นตัวเลขตั้งแต่ 0 ถึงคะแนนเต็ม
   - ไม่อนุญาตให้พิมพ์เพิ่มรายชื่อนักเรียนอิสระจากหน้านี้ หากยังไม่มีรายชื่อต้องให้นักเรียนสมัครและเข้าร่วมห้องก่อน
3. อัปโหลด Excel
   - ครูต้องดาวน์โหลดแม่แบบจากหน้าโครงการนั้น ไม่รับไฟล์ที่มีโครงสร้างอิสระในรุ่นแรก
   - แม่แบบสร้างจาก roster จริงและผูกกับโครงการ ห้องเรียน และรุ่นของแม่แบบ
   - ไม่รับแถวที่เพิ่มนักเรียนซึ่งไม่มีบัญชีหรือไม่ได้เป็นสมาชิกห้องเรียน
   - คอลัมน์ที่แสดงแต่ห้ามแก้: เลขที่ รหัสนักเรียน ชื่อ–นามสกุล
   - คอลัมน์ที่แก้ได้: คะแนนก่อนเรียน คะแนนหลังเรียน และหมายเหตุ
   - ระบบใช้รหัสแถวสุ่มแบบทึบที่ไม่ซ้ำและตรวจกลับกับ template/project/participant ฝั่ง server รหัสถูกซ่อน/ป้องกันในไฟล์ ห้ามจับคู่คะแนนด้วยชื่อเพียงอย่างเดียว

ก่อนยืนยันการนำเข้า ระบบต้องแสดงหน้า preview แยกแถวที่พร้อมนำเข้า คำเตือน และข้อผิดพลาด โดยตรวจอย่างน้อย:

- แม่แบบมาจากโครงการและห้องเรียนที่ถูกต้องและเป็นรุ่นที่ยังรองรับ
- ไม่มีรหัสแถวซ้ำ รหัสที่ไม่รู้จัก หรือการแก้ไขข้อมูลระบุตัวนักเรียน
- คะแนนเป็นตัวเลข อยู่ในช่วง 0 ถึงคะแนนเต็ม และช่องว่างไม่ถูกแปลงเป็นศูนย์
- หากมีคะแนนเดิม ต้องแสดงค่าปัจจุบันเทียบกับค่าใหม่ และขอให้ครูยืนยันก่อนเขียนทับ
- การสลับลำดับแถวทำได้ เพราะระบบจับคู่ด้วยรหัสแถว ไม่ใช่ตำแหน่งหรือชื่อ

ไฟล์ที่ดาวน์โหลดมีข้อมูลส่วนบุคคลของนักเรียน จึงต้องให้ดาวน์โหลดได้เฉพาะครูที่มีสิทธิ์ในห้องและแสดงคำเตือนเรื่องการเก็บรักษาไฟล์

## การเผยแพร่ข้อสอบออนไลน์

- ครูตั้งค่าและแก้วัน–เวลาเผยแพร่ข้อสอบก่อนและหลังเรียนจากหน้าโครงการวิจัย ซึ่งเป็นแหล่งควบคุมหลัก
- ระบบสร้าง assignment ที่เชื่อมกับโครงการในห้องเรียน นักเรียนเห็นและทำข้อสอบผ่านห้องเรียนตามปกติ
- หน้าห้องเรียนแสดงสถานะของงานที่เชื่อมกับงานวิจัย แต่การแก้กำหนดการหรือค่าที่มีผลต่อการวิเคราะห์ต้องพากลับไปจัดการในโครงการวิจัย
- การสร้างโครงการไม่ปล่อยข้อสอบโดยไม่มีคำยืนยันจากครู
- ก่อนเรียนเลือกได้ระหว่างเผยแพร่ทันทีหรือกำหนดเวลาเปิด–ปิด
- หลังเรียนใช้ “ฉบับร่าง” เป็นค่าเริ่มต้น ครูอาจตั้งเวลาไว้ล่วงหน้าหรือกลับมาเผยแพร่หลังสอนเสร็จ
- สถานะที่ผู้ใช้เห็นอย่างน้อยประกอบด้วย “ฉบับร่าง”, “ตั้งเวลาแล้ว”, “กำลังเปิด” และ “ปิดแล้ว”
- กติกานี้ใช้กับแหล่งคะแนน “ข้อสอบออนไลน์ Korkru” เท่านั้น การกรอกบนเว็บและ Excel ไม่มี assignment สำหรับเผยแพร่

### รหัสเข้าทำข้อสอบ

- ข้อสอบออนไลน์ก่อนเรียนและหลังเรียนมีรหัสเข้าแยกกัน ครูเปิดหรือปิดการใช้รหัสได้จากหน้าต่าง “จัดการกำหนดการและรหัสเข้า”
- ในหน้าภาพรวม ปุ่มของข้อสอบทั้งสองรอบใช้ชื่อเดียวกันว่า “จัดการกำหนดการ” แม้ข้อสอบหลังเรียนยังเป็นฉบับร่าง เพราะหน้าต่างเดียวใช้ตั้งเวลา เผยแพร่ และจัดการรหัส
- รุ่นแรกแนะนำให้เปิดใช้รหัสสำหรับข้อสอบวิจัย แต่รหัสเป็นชั้นควบคุมเพิ่มเติม ไม่ใช่สิทธิ์ลัด นักเรียนยังต้องล็อกอิน มีบัญชี Korkru อยู่ในห้อง/โครงการ อยู่ในช่วงเวลาที่เปิด และยังไม่เคยส่งข้อสอบรอบนั้น
- ครูตั้งรหัสเองหรือให้ระบบสร้างรหัสสุ่มได้ รหัสตัวอย่างยาว 4–12 ตัวอักษร ใช้อักษรละติน ตัวเลข และขีดกลางโดยไม่สนตัวพิมพ์เล็ก–ใหญ่ ห้ามใช้ข้อมูลส่วนบุคคลของนักเรียนเป็นรหัส
- ครูที่มีสิทธิ์ในโครงการดู คัดลอก และเปลี่ยนรหัสได้ หากรหัสถูกบันทึกหรือเผยแพร่แล้ว การเปลี่ยนต้องแสดงคำเตือนว่ารหัสเดิมจะใช้ไม่ได้
- การเปลี่ยนรหัสมีผลเฉพาะการเข้าใหม่ นักเรียนที่ผ่านหน้ากรอกรหัสและกำลังทำข้อสอบอยู่ทำต่อได้ เพื่อไม่ตัดการสอบกลางคัน
- สำหรับนักเรียนที่ขาด ครูปิดรอบปกติแล้วเปิดช่วงเวลาเก็บตกพร้อมรหัสใหม่ได้ ผู้ที่ส่งข้อสอบครบแล้วเข้าใหม่ไม่ได้เพราะข้อสอบวิจัยทำได้หนึ่งครั้ง
- รหัสช่วยลดการเข้าสอบนอกห้อง แต่ไม่รับประกันการอยู่ในห้องจริงหากนักเรียนส่งต่อรหัส จึงต้องใช้ร่วมกับช่วงเวลา บัญชี ห้องเรียน และการกำกับของครู
- ระบบต้องจำกัดความถี่การลองรหัสผิดและบันทึกเหตุการณ์สำคัญ เช่น เปลี่ยนรหัส เปิดรอบ และเข้าแบบทดสอบ โดยประวัติห้ามเก็บค่ารหัสเดิมแบบอ่านได้
- การเปลี่ยนกำหนดการหรือรหัสต้องไม่สร้างสำเนาข้อสอบใหม่และไม่เปลี่ยนคะแนนที่มีอยู่ เพราะเป็นการควบคุมการเข้าถึง ไม่ใช่การแก้เครื่องมือวัด

### การติดตามการสอบสด

- เลื่อนการออกแบบและพัฒนาหน้าคุมสอบสดไว้หลังงานวิจัยทุกเฟสเสร็จ เจ้าของผลิตภัณฑ์ขอให้เตือนอีกครั้งเมื่อถึงจุดนั้น ห้ามแทรกงานคุมสอบสดเข้ามาระหว่างระยะ 2.x ของงานวิจัย
- หน้าติดตามแบบเรียลไทม์อยู่ใน “ห้องเรียน > งานข้อสอบ” เพราะเป็นเครื่องมือคุมสอบที่ใช้ร่วมกันได้กับข้อสอบทั่วไปและข้อสอบวิจัย โดย assignment ในห้องเรียนเป็นแหล่งข้อมูลหลัก
- เมื่อหน้าคุมสอบสดในห้องเรียนพร้อมแล้ว หน้าโครงการวิจัยและหน้า “ข้อมูลคะแนน” จึงแสดงปุ่ม “ดูสถานะสอบสด” ซึ่งพาไปยัง assignment ที่เชื่อมอยู่ ห้ามสร้างระบบสถานะสดซ้ำอีกชุดในโมดูลวิจัย ระหว่างที่ปลายทางยังไม่มีให้ซ่อนปุ่มนี้ ไม่แสดงทางลัดที่กดแล้วใช้งานไม่ได้
- สถานะรายคนที่เสนอประกอบด้วย “ยังไม่เข้า”, “ผ่านรหัสแล้ว”, “กำลังทำ”, “ส่งแล้ว” และ “ขาดการเชื่อมต่อ” พร้อมเวลาที่อัปเดตล่าสุด คำว่า “ขาดการเชื่อมต่อ” เป็นสถานะทางเทคนิค ไม่ใช่ข้อสรุปเรื่องการทุจริต
- หากครูทำเครื่องหมายการเข้าเรียนว่า “ขาดเรียน” แล้วบัญชีนั้นผ่านรหัสหรือเริ่มทำข้อสอบ ให้แจ้งเตือนครูทันทีว่า “นักเรียนที่ทำเครื่องหมายว่าขาดกำลังเข้าสอบ” แต่ไม่กล่าวหาว่าโกงโดยอัตโนมัติ
- ถ้ายังไม่มีข้อมูลการเข้าเรียน ระบบแสดงได้เพียงว่าใครเข้าหรือยังไม่เข้า ห้ามอนุมานเองว่าเป็นนักเรียนขาด
- นักเรียนที่รู้รหัสยังต้องผ่านเงื่อนไขบัญชี ห้องเรียน ช่วงเวลา และหนึ่งครั้งตามเดิม ครูอาจปิดการเข้าใหม่หรือเปลี่ยนรหัสจากงานข้อสอบได้โดยไม่ตัดผู้ที่กำลังทำอยู่
- หลังจบรอบสอบ หน้า “ข้อมูลคะแนน” อ่านเวลาเข้า เริ่มทำ ส่งคำตอบ รอบสอบ และสถานะการแก้ไขจากประวัติ assignment เพื่อช่วยตรวจสอบย้อนหลัง
- การติดตามสดเปิดได้เฉพาะครูหรือผู้ดูแลห้องที่มีสิทธิ์ ไม่แสดง IP, GPS หรือข้อมูลเฝ้าระวังที่ไม่จำเป็นต่อการคุมสอบในรุ่นแรก

## การเลือกและดูตัวอย่างข้อสอบ

- เมื่อเลือกแหล่งคะแนน “ข้อสอบออนไลน์ Korkru” ครูเลือกข้อสอบก่อนเรียนในขั้นที่ 2 และข้อสอบหลังเรียนในขั้นที่ 3
- ปุ่ม “เลือกจากคลังข้อสอบ” เปิดหน้าต่างที่รวมการค้นหา เลือก และดู “มุมมองนักเรียน” ไว้ในจุดเดียว โดยไม่ออกจาก wizard
- ครูเลือกได้สองวิธี: ใช้ชุดข้อสอบสำเร็จรูปหนึ่งชุด หรือประกอบข้อสอบด้วยการเลือกข้อคำถามจากคลังทีละข้อ
- โหมดเลือกทีละข้อต้องแสดงแฟ้มและแฟ้มย่อยเป็นโครงสร้างต้นไม้ ครูเปิดแต่ละแฟ้มเพื่อดูข้อคำถามภายในและเลือกข้ามหลายแฟ้มได้ โดยจำนวนข้อและคะแนนรวมที่เลือกต้องคงอยู่ขณะเปลี่ยนแฟ้ม
- การคลิกชื่อแฟ้มหรือแฟ้มย่อยเป็นเพียงการเปิดดูเนื้อหา ไม่เลือกข้อคำถามให้อัตโนมัติ ปุ่ม “เลือกทั้งหมดในแฟ้มนี้” จึงต้องเป็นการกระทำแยกและระบุจำนวนข้อที่จะเพิ่มอย่างชัดเจน
- “เลือกทั้งหมดในแฟ้มนี้” เลือกเฉพาะข้อที่อยู่ในแฟ้มปัจจุบัน ไม่รวมแฟ้มย่อยโดยปริยาย เพื่อลดการเลือกเกินโดยไม่ตั้งใจ ครูยังเปิดแฟ้มย่อยแล้วเลือกทั้งหมดหรือเลือกเป็นรายข้อได้
- หากข้อเดียวกันถูกอ้างอิงจากหลายแฟ้ม ระบบต้องนับเพียงครั้งเดียวและแจ้งว่าข้อนั้นเลือกอยู่แล้ว
- เมื่อเลือกทีละข้อ ระบบสร้างชุดข้อสอบของโครงการจากรายการที่เลือก แสดงจำนวนข้อและคะแนนเต็มจริงก่อนยืนยัน และเก็บเป็น snapshot เช่นเดียวกับการเลือกชุดข้อสอบสำเร็จรูป
- การสลับระหว่าง “เลือกชุดข้อสอบ” กับ “เลือกข้อทีละข้อ” ต้องไม่ผสมสองวิธีโดยไม่ตั้งใจ หากอีกโหมดมีรายการเลือกอยู่ให้ขอคำยืนยันก่อนล้างรายการเดิม
- ครูเปิดตัวอย่างเต็มจอได้ก่อนยืนยัน และพรีวิวโจทย์สุ่มค่าต้องระบุว่าเป็นค่าตัวอย่างซึ่งนักเรียนแต่ละคนอาจได้รับต่างกัน
- ถ้ายังไม่มีข้อสอบ ครูกด “สร้างข้อสอบใหม่” แล้วกลับมาที่ wizard เดิมโดยข้อมูลโครงการที่กรอกไว้ต้องไม่หาย
- หลังสร้างโครงการ ครูเปิดมุมมองนักเรียนได้จากหน้าภาพรวมโครงการ และหน้าห้องเรียนมีทางลัดเปิดตัวอย่างชุดเดียวกัน
- นักเรียนจริงไม่เห็นเมนูวิจัยและทำข้อสอบจากห้องเรียนเท่านั้น
- เมื่อสร้างโครงการ ระบบต้องเก็บ snapshot ข้อสอบที่ใช้วิจัย การแก้ต้นฉบับในคลังภายหลังต้องไม่เปลี่ยนข้อสอบของโครงการย้อนหลัง
- ก่อนเผยแพร่และก่อนมีคะแนน ครูอาจเปลี่ยนข้อสอบได้โดยสร้าง snapshot ใหม่ เมื่อเริ่มมีคะแนนแล้วให้ล็อกข้อสอบของรอบนั้น

## คำอธิบาย “สำเนาข้อสอบที่ตรึงไว้”

- ข้อความที่ครูเห็นใน UI ใช้คำว่า “สำเนาข้อสอบที่ตรึงไว้” หรือ “สำเนาข้อสอบ” แทนการแสดงคำว่า `snapshot` เพียงอย่างเดียว
- จุดที่แสดงสถานะสำเนาข้อสอบต้องมีปุ่มวงกลม `?` ขนาดเล็ก ครูเปิดคำอธิบายได้ด้วยการวางเมาส์ โฟกัสด้วยคีย์บอร์ด หรือคลิก ส่วนอุปกรณ์สัมผัสใช้การแตะ
- เมื่อเปิดด้วยการคลิกหรือแตะ กล่องคำอธิบายค้างอยู่จนกด `X`, กด `Escape` หรือกดนอกกล่อง การเลื่อนเมาส์จากปุ่มเข้าไปในกล่องต้องไม่ทำให้กล่องหายทันที
- ปุ่มต้องรับโฟกัสได้และมีชื่อสำหรับโปรแกรมอ่านหน้าจอว่า “อธิบายสำเนาข้อสอบที่ตรึงไว้” ห้ามสื่อความหมายด้วยสีเพียงอย่างเดียว
- เนื้อหาในกล่องอธิบาย:
  - “ระบบเก็บข้อสอบฉบับที่ใช้ในโครงการแยกจากต้นฉบับ การแก้ข้อสอบในคลังภายหลังจะไม่เปลี่ยนข้อสอบหรือคะแนนของโครงการ”
  - ประโยชน์ต่องานวิจัยคือใช้เครื่องมือวัดฉบับที่กำหนดไว้อย่างสม่ำเสมอ และตรวจสอบย้อนหลังได้ว่าคะแนนมาจากข้อสอบฉบับใด
- หลักการนี้ใช้ทุกหน้าที่แสดงคำเกี่ยวกับสำเนาข้อสอบ ไม่จำกัดเฉพาะขั้นตรวจสอบ เพื่อให้คำอธิบายสอดคล้องกันทั้งระบบ

## สถิติที่เสนอสำหรับรุ่นแรก

ระบบต้องแยกคำถามทางสถิติออกเป็นสองกรณี ไม่รวมเป็นตารางเดียวจนเกิดความหมายคลาดเคลื่อน

1. คะแนนของนักเรียนกลุ่มเดิมดีขึ้นหรือไม่
   - ใช้ paired-samples t-test
   - แสดงจำนวนคู่คะแนนสมบูรณ์ ค่าเฉลี่ยและ S.D. ก่อน–หลังเรียน ผลต่างเฉลี่ย `t`, `df`, `p`, ช่วงความเชื่อมั่น 95% และ Cohen's dz
2. คะแนนหลังเรียนสูงกว่าเกณฑ์ที่ครูกำหนดหรือไม่ เช่น ร้อยละ 70
   - ใช้ one-sample t-test เปรียบเทียบคะแนนหลังเรียนกับคะแนนเกณฑ์
   - แสดง `n`, คะแนนเกณฑ์, ค่าเฉลี่ย, S.D., ผลต่างเฉลี่ย, ช่วงความเชื่อมั่น 95%, `t`, `df`, `p`, Cohen's d และจำนวนผู้ผ่านเกณฑ์

หลักการรายงาน: แสดง `p < .001` แทน `p = .000` และใช้ถ้อยคำว่า “คะแนนเพิ่มขึ้นหลังเรียน” โดยไม่สรุปเชิงเหตุว่าแผนการสอนเป็นสาเหตุจากการออกแบบกลุ่มเดียว

## คำเรียกประเภทและแบบแผนวิจัย

- “วิจัยพัฒนาผู้เรียน” คือประเภทหรือเป้าหมายของงานวิจัยในขอบเขตรุ่นแรก
- “กลุ่มเดียว วัดก่อน–หลังเรียน” คือชื่อแบบแผนวิจัยที่แสดงใน UI
- คำอธิบายใน UI คือ “ติดตามพัฒนาการของนักเรียนกลุ่มเดิมหลังใช้แผนการจัดการเรียนรู้”
- การใช้ข้อสอบชุดเดิมหรือข้อสอบคู่ขนาน A/B เป็นรูปแบบเครื่องมือวัด ไม่ใช่แบบแผนวิจัยคนละประเภท
- การวิเคราะห์คะแนนหลังเรียนเทียบเกณฑ์เป็นคำถามทางสถิติภายในแบบแผนนี้ ไม่ใช่แบบแผนวิจัยใหม่
- แบบมีกลุ่มเปรียบเทียบ แบบสุ่ม และแบบหลายกลุ่มอยู่นอกขอบเขตรุ่นแรก

## โครงสร้างหน้าที่เสนอ

1. `/research` — รายการโครงการ สถานะเก็บข้อมูล และปุ่มสร้างโครงการ
2. `/research/new` — ขั้นตอนสร้างโครงการ เลือกห้องเรียน ข้อสอบก่อนเรียน ข้อสอบหลังเรียน และเกณฑ์คะแนน
3. `/research/[id]` — ภาพรวมโครงการและทางลัดไปยังงานที่ต้องทำ
4. `/research/[id]/data` — ตรวจรายชื่อ จับคู่คะแนน และแจ้งข้อมูลที่ยังไม่พร้อม
5. `/research/[id]/results` — ตารางสถิติ คำแปลผล และการส่งออก

### ขั้นตอนสร้างโครงการ `/research/new`

1. ข้อมูลโครงการ — ชื่อ เรื่อง/หน่วยการเรียนรู้ ห้องเรียนหนึ่งห้อง และเกณฑ์ผ่านหลังเรียน
2. ก่อนเรียน — เลือกแหล่งคะแนนจากข้อสอบ Korkru, กรอกบนเว็บ หรือแม่แบบ Excel
3. หลังเรียน — เลือกแหล่งคะแนนและแบบทดสอบหลังเรียน
4. ตรวจสอบ — สรุปการตั้งค่า จำนวนสมาชิกห้อง และสิ่งที่ต้องทำต่อก่อนสร้างโครงการ

### หน้าภาพรวมโครงการ `/research/[id]`

- เป็นหน้าหลักที่ครูกลับมาใช้หลังสร้างโครงการ โดยต้องบอกสถานะปัจจุบัน สิ่งที่ต้องทำต่อ และความคืบหน้าการเก็บคะแนนโดยไม่ต้องเปิดหลายหน้า
- แถบนำทางภายในโครงการประกอบด้วย “ภาพรวม”, “ข้อมูลคะแนน” และ “ผลวิเคราะห์” เพื่อเชื่อมไปยัง `/research/[id]`, `/research/[id]/data` และ `/research/[id]/results`
- การ์ดความคืบหน้าแสดงจำนวนผู้มีคะแนนก่อนเรียน จำนวนผู้มีคะแนนหลังเรียน และจำนวนคู่คะแนนที่เป็นนักเรียนคนเดียวกัน ตัวตั้งและตัวหารต้องคำนวณจากผู้เข้าร่วมและคะแนนจริงของโครงการ
- “สิ่งที่ต้องทำต่อ” ต้องอนุมานจากสถานะจริง เช่น รอคะแนนก่อนเรียน, สอนตามแผน, ต้องเผยแพร่หลังเรียน, คะแนนยังไม่ครบ หรือพร้อมวิเคราะห์ ห้ามฝังข้อความขั้นตอนเดียวไว้ทุกโครงการ
- เมื่อข้อสอบหลังเรียนยังเป็นฉบับร่าง หน้าภาพรวมเปิด “จัดการกำหนดการ” เพื่อตั้งเวลา เผยแพร่ หรือแก้รหัสได้ แต่ยังยึดโครงการวิจัยเป็นแหล่งควบคุมการเผยแพร่หลัก
- การ์ดข้อสอบก่อน–หลังแสดงจำนวนข้อ คะแนนเต็ม เวลา จำนวนครั้ง แหล่งที่มา สถานะสำเนาข้อสอบ และปุ่มดูมุมมองนักเรียน โดยใช้ปุ่ม `?` อธิบายสำเนาข้อสอบตามกติกากลาง
- ทางลัดอย่างน้อยประกอบด้วย “ตรวจรายชื่อและคะแนน”, “เปิดห้องเรียน” และ “จัดการโครงการ”
- ปุ่ม “ดูผลวิเคราะห์” แสดงสถานะยังไม่พร้อมเมื่อไม่มีคู่คะแนน และต้องไม่แสดงค่าเฉลี่ย, S.D., t, p หรือผลวิจัยที่คำนวณไม่ได้
- ตัวเลขและสถานะทั้งหมดในหน้า production ต้องมาจากโครงการ roster งานในห้องเรียน submission และคะแนนจริง ภาพร่างเท่านั้นที่ใช้ตัวเลขตัวอย่างเพื่อสื่อสารสถานะ

### หน้าข้อมูลคะแนน `/research/[id]/data`

- แสดงผู้เข้าร่วมจากโครงการและจับคู่คะแนนด้วยรหัสบัญชี/รหัสผู้เข้าร่วมที่ไม่ซ้ำ ห้ามจับคู่ด้วยชื่อหรือลำดับแถว
- การ์ดสรุปแสดงจำนวนผู้เข้าร่วม จำนวนคะแนนก่อนเรียน จำนวนคะแนนหลังเรียน และจำนวนคู่คะแนนที่นักเรียนคนเดียวกันมีครบทั้งสองรอบ
- คะแนนที่ยังไม่มีต้องเป็นค่าว่างและแสดง “—” ห้ามแปลงเป็นศูนย์ เพราะจะทำให้ค่าเฉลี่ยและผลการทดสอบคลาดเคลื่อน
- ตารางแสดงอย่างน้อย เลขที่ นักเรียน คะแนนก่อนเรียน คะแนนหลังเรียน สถานะคู่คะแนน แหล่งที่มา และทางเปิดรายละเอียด/ประวัติ
- ตัวกรองประกอบด้วยทั้งหมด พร้อมวิเคราะห์ คะแนนขาด และแหล่งคะแนน พร้อมช่องค้นหานักเรียนจากชื่อหรือรหัส
- ครูเข้าถึงการกรอก/แก้ไขคะแนน ดาวน์โหลดแม่แบบ Excel และอัปโหลด Excel จากหน้านี้ โดยทุกช่องทางใช้กฎตรวจสอบและประวัติการแก้ไขชุดเดียวกัน
- คะแนนที่แก้โดยครูต้องมีป้าย “แก้ไขโดยครู” และเปิดดูค่าก่อนแก้ ค่าหลังแก้ ผู้แก้ เหตุผล และเวลาได้
- เมื่อมีคู่คะแนนบางส่วน ระบบบอกจำนวน `n` ที่พร้อมวิเคราะห์และจำนวนที่ยังขาด ครูตรวจความพร้อมได้โดยผู้มีคะแนนไม่ครบจะไม่ถูกรวมในการวิเคราะห์จนกว่าจะมีข้อมูลครบคู่
- ปุ่ม “ดูสถานะสอบสด” เป็นส่วนเชื่อมต่อในอนาคต เมื่อหน้าคุมสอบของห้องเรียนยังไม่พร้อมต้องซ่อนไว้; หลังพัฒนาแล้วจึงแสดงเมื่อมี assignment ออนไลน์ที่กำลังเปิด และเมื่อปิดรอบแล้วเปลี่ยนเป็นทางดูประวัติการสอบ
- ตัวเลข ชื่อ คะแนน สถานะ และแหล่งที่มาบน production ต้องมาจากข้อมูลจริง ภาพร่างใช้ข้อมูลสมมติเฉพาะเพื่อแสดงสถานะหน้าจอ

### หน้ากรอกคะแนนบนเว็บ `/research/[id]/data/manual`

- ใช้เมื่อแหล่งคะแนนของรอบก่อนเรียนหรือหลังเรียนเป็น “กรอกบนเว็บ” โดยดึงรายชื่อนักเรียนจาก roster ของห้องที่ผูกกับโครงการ รายชื่อ รหัสนักเรียน และลำดับเป็นข้อมูลอ่านอย่างเดียวในหน้านี้
- ช่องคะแนนรองรับตัวเลขตั้งแต่ 0 ถึงคะแนนเต็มและค่าทศนิยมตามที่แบบทดสอบรองรับ ช่องว่างหมายถึง “ยังไม่มีคะแนน” และต้องไม่ถูกแปลงเป็น 0
- ตารางต้องแก้ด้วยคีย์บอร์ดได้สะดวก เช่น `Enter` หรือปุ่มลูกศรย้ายไปช่องถัดไป พร้อมตัวกรอง “ขาดก่อนเรียน”, “ขาดหลังเรียน” และ “มีข้อผิดพลาด”
- ตรวจข้อผิดพลาดในแถวทันที เช่น ไม่ใช่ตัวเลข ค่าติดลบ หรือเกินคะแนนเต็ม โดยระบุปัญหาใกล้ช่องที่ผิด ห้ามบันทึกจริงขณะที่ยังมีข้อผิดพลาด
- การออกจากหน้าโดยยังไม่บันทึกต้องเตือนว่ามีการเปลี่ยนแปลงค้างอยู่ ปุ่ม “บันทึกฉบับร่าง” เก็บข้อมูลที่ผ่านการตรวจไว้ก่อน และปุ่ม “ตรวจสอบและยืนยัน” พาไปตรวจจำนวนคะแนนครบ/ขาดและค่าที่จะเปลี่ยนก่อนเขียนเป็นคะแนนจริง
- หากคะแนนของนักเรียนมาจากข้อสอบ Korkru หรือ Excel แล้ว ไม่ให้โหมดกรอกจำนวนมากเขียนทับเงียบ ๆ การแก้ไขต้องเปิดเป็นการแก้รายคน แสดงค่าเดิม–ค่าใหม่ ขอเหตุผล และเก็บผู้แก้กับเวลาในประวัติ
- ตัวเลข ชื่อ และรหัสที่ปรากฏในภาพร่างเป็นข้อมูลสมมติเท่านั้น หน้า production ต้องใช้ roster และคะแนนจริงตามสิทธิ์ของครู

### ขั้นดาวน์โหลดแม่แบบและอัปโหลด Excel `/research/[id]/data/import`

- เส้นทางแบ่งเป็น 3 ขั้นที่ครูเห็นชัดเจน ได้แก่ “ดาวน์โหลดแม่แบบ”, “อัปโหลดไฟล์” และ “ตรวจสอบและยืนยัน” โดยขั้นอัปโหลดไม่มีสิทธิ์เขียนคะแนนลงโครงการทันที
- แม่แบบต้องสร้างจากโครงการและ roster ปัจจุบันทุกครั้ง พร้อมระบุห้อง จำนวนผู้เข้าร่วม คะแนนเต็ม และรุ่นแม่แบบ ครูต้องใช้แม่แบบของโครงการนั้น ไม่รับสมุดงาน Excel โครงสร้างอิสระในรุ่นแรก
- คอลัมน์เลขที่ รหัสนักเรียน และชื่อ–นามสกุลเป็นข้อมูลอ่านอย่างเดียว ส่วนคะแนนก่อนเรียน คะแนนหลังเรียน และหมายเหตุเป็นช่องที่กรอกได้ การป้องกันเซลล์ใน Excel ช่วยลดความผิดพลาดแต่ไม่ใช่ขอบเขตความปลอดภัย ฝั่ง server ต้องตรวจทุกค่าอีกครั้ง
- แต่ละแถวมีรหัสสุ่มแบบทึบที่ไม่ซ้ำและตรวจกลับกับโครงการ ผู้เข้าร่วม และรุ่นแม่แบบในฐานข้อมูล โดยซ่อน/ป้องกันไว้ในไฟล์ ระบบจับคู่ด้วยรหัสนี้ ไม่ใช้ชื่อ รหัสนักเรียนที่ครูเห็น หรือลำดับแถว
- รองรับไฟล์ `.xlsx` ของแม่แบบ Korkru เท่านั้น ไม่รับ `.xlsm`, macro หรือสูตรในช่องคะแนน คะแนนต้องเป็นค่าตัวเลขจริงหรือช่องว่าง และต้องผ่านการตรวจชนิดไฟล์ โครงสร้าง และขนาดฝั่ง server ก่อนอ่าน
- หลังเลือกไฟล์ ปุ่มใช้คำว่า “ตรวจสอบข้อมูล” พร้อมข้อความว่า “ยังไม่บันทึกคะแนน” ระบบพาไปหน้า preview ซึ่งแยกข้อมูลพร้อมนำเข้า คำเตือน ข้อผิดพลาด และคะแนนเดิมที่จะถูกแทนที่ก่อนให้ครูยืนยัน
- หาก roster เปลี่ยนหลังดาวน์โหลดแม่แบบ หน้า preview ต้องแจ้งนักเรียนที่เพิ่มเข้ามา นักเรียนที่ออกจากห้อง หรือแถวที่ใช้กับโครงการปัจจุบันไม่ได้ ห้ามเดาหรือย้ายคะแนนให้คนอื่น
- ไฟล์มีข้อมูลส่วนบุคคลของนักเรียน ต้องตรวจสิทธิ์ดาวน์โหลดและอัปโหลดตามโครงการ/ห้องเรียน ไม่ใช้ public URL ไม่บันทึกเนื้อหาไฟล์หรือคะแนนลง log และลบไฟล์ชั่วคราวตามอายุที่กำหนดหลังประมวลผล

### ขั้นตรวจสอบและยืนยัน Excel `/research/[id]/data/import/[batchId]`

- หน้า preview แสดงไฟล์ที่กำลังตรวจ จำนวนแถวทั้งหมด พร้อมนำเข้า คำเตือน และข้อผิดพลาด พร้อมตัวกรองเพื่อให้ครูหาปัญหาได้ทันที
- การนำเข้าหนึ่งไฟล์เป็นแบบสำเร็จทั้งหมดหรือไม่บันทึกเลย (`all-or-nothing`) หากมีข้อผิดพลาดแม้หนึ่งแถว ปุ่มยืนยันต้องปิดใช้งานและไม่มีคะแนนแถวใดถูกเขียน ครูต้องแก้ไฟล์แล้วอัปโหลดใหม่
- สถานะ “พร้อมนำเข้า” คือข้อมูลระบุตัวนักเรียนและคะแนนผ่านครบ; “คำเตือน” คือข้อมูลนำเข้าได้แต่ต้องให้ครูตัดสินใจ เช่น คะแนนเดิมจะถูกแทนที่; “ข้อผิดพลาด” คือข้อมูลที่ห้ามนำเข้า เช่น เกินคะแนนเต็ม รหัสแถวไม่ถูกต้อง ข้อมูลตัวตนถูกแก้ หรือสมาชิกไม่อยู่ในโครงการแล้ว
- ตารางเปรียบเทียบค่าปัจจุบันกับค่าจากไฟล์แยกก่อนเรียนและหลังเรียน พร้อมบอกจำนวนค่าที่เพิ่ม เปลี่ยน หรือไม่เปลี่ยน ห้ามแสดงเพียงคะแนนใหม่จนมองไม่เห็นผลกระทบ
- ช่องว่างในไฟล์หมายถึงไม่มีค่าใหม่ หากระบบมีคะแนนเดิมให้คงคะแนนเดิมไว้ ช่องว่างห้ามใช้ลบคะแนน การลบหรือแก้ย้อนหลังต้องทำรายคน ระบุเหตุผล และเก็บประวัติ
- คะแนนเดิมที่จะถูกแทนที่ต้องสรุปจำนวนรายการและให้ครูติ๊ก “ฉันตรวจสอบคะแนนเดิมและคะแนนใหม่แล้ว” ก่อนเปิดปุ่มยืนยัน เมื่อยังมีข้อผิดพลาด checkbox และปุ่มยืนยันต้องปิดใช้งาน
- หาก roster มีนักเรียนเพิ่มหลังสร้างแม่แบบ ให้แจ้งว่าไฟล์ไม่มีแถวของนักเรียนคนนั้นและคะแนนจะยังขาด; หากแถวในไฟล์ไม่ใช่ผู้เข้าร่วมปัจจุบันให้เป็นข้อผิดพลาด ห้ามย้ายคะแนนไปหาแถวที่ชื่อคล้ายกัน

- ปุ่ม “ดูรายละเอียดการนำเข้าครั้งนี้” เปิด side sheet แบบอ่านอย่างเดียวซึ่งนำตารางเปรียบเทียบจาก preview มาใช้ซ้ำและอ่านจาก audit batch จึงไม่ต้องสร้างหน้าใหม่หรือเก็บไฟล์ Excel ต้นฉบับเป็นหน้าประวัติ
- ไฟล์ต้นฉบับต้องไม่เป็น public URL และต้องถูกลบตามอายุไฟล์ชั่วคราวที่กำหนด ส่วนประวัติการนำเข้าเก็บเป็นข้อมูลโครงสร้างตามสิทธิ์ ครูยังแก้คะแนนภายหลังได้เป็นรายคนพร้อมเหตุผลและ audit ใหม่

### หน้าผลวิเคราะห์ก่อน–หลังเรียน `/research/[id]/results`

- หน้า “ผลวิเคราะห์” แบ่งแท็บย่อยเป็น “ก่อน–หลังเรียน”, “เทียบเกณฑ์ 70%” และ “ข้อมูลที่ใช้” โดยเปิดแท็บก่อน–หลังเรียนเป็นค่าเริ่มต้น และห้ามรวมผล paired-samples t-test กับผลเทียบเกณฑ์ไว้ในตารางเดียวจนตีความสับสน
- ผลก่อน–หลังใช้เฉพาะนักเรียนคนเดิมที่มีคะแนนครบทั้งสองครั้ง ระบบต้องแสดงจำนวน “คู่คะแนนสมบูรณ์” และจำนวนผู้ถูกตัดออกเพราะคะแนนไม่ครบอย่างชัดเจน ช่องว่างห้ามแทนด้วยศูนย์หรือเติมค่าโดยอัตโนมัติ
- ปุ่ม `?` ข้างคำว่า “คู่คะแนนสมบูรณ์” อธิบายว่าเป็นนักเรียนคนเดียวกันซึ่งมีทั้งคะแนนก่อนและหลังเรียน และเป็นข้อมูลที่ใช้ใน paired-samples t-test โดยต้องเปิดได้ด้วย hover, keyboard focus, click และการแตะ
- การ์ดสรุปแสดงค่าเฉลี่ยกับ S.D. ก่อนเรียน ค่าเฉลี่ยกับ S.D. หลังเรียน ผลต่างเฉลี่ย และขนาดอิทธิพล `Cohen’s dz` ส่วนตารางหลักแสดง `n`, ค่าเฉลี่ย และ S.D. แยกตามช่วงการวัด
- แถบผลทดสอบแสดงผลต่างเฉลี่ย ช่วงเชื่อมั่น 95%, `t(df)`, `p` และ `Cohen’s dz` ซึ่งคำนวณจากข้อมูลคู่ชุดเดียวกันทั้งหมด โดย `df = n - 1` และรายงาน `p < .001` แทน `p = .000`
- กราฟเปรียบเทียบต้องใช้สเกลที่ไม่ขยายความแตกต่างเกินจริง ในตัวอย่างคะแนนเต็ม 25 แกนเริ่มที่ 0 และเส้นกำกับความแปรปรวนต้องระบุชัดว่าเป็น S.D. ไม่ปล่อยให้ตีความเป็นช่วงเชื่อมั่นโดยไม่ตั้งใจ
- “สรุปผลสำหรับรายงาน” สร้างจากผลคำนวณชุดเดียวกับตารางและคัดลอกได้ โดยใช้ถ้อยคำว่า “คะแนนหลังเรียนสูงกว่าก่อนเรียน” และรายงานค่า `t`, `p`, ขนาดอิทธิพล ห้ามกล่าวว่าแผนการสอนเป็นสาเหตุเพียงอย่างเดียว
- แสดงข้อควรระวังถาวรว่างานวิจัยแบบกลุ่มเดียวบอกการเปลี่ยนแปลงของคะแนนหลังเรียนได้ แต่ยังตัดคำอธิบายอื่นหรือยืนยันเหตุและผลไม่ได้
- ปุ่ม “ข้อมูลที่ใช้” เปิดรายการคู่คะแนนที่นำมาคำนวณและผู้ที่คะแนนไม่ครบตามสิทธิ์ของครู เพื่อให้ตรวจย้อนกลับได้ แต่การคัดลอกผลหรือดาวน์โหลดตารางสรุปต้องไม่รวมชื่อ รหัส หรือข้อมูลส่วนบุคคลโดยไม่จำเป็น
- เมื่อคะแนนต้นทางถูกเพิ่ม แก้ หรือลบ ผลวิเคราะห์ต้องคำนวณใหม่จากข้อมูลล่าสุดและแสดงเวลาอัปเดต ห้ามเก็บผลเก่าเป็นค่าปัจจุบันโดยไม่มีการระบุรุ่นข้อมูล
- หากคู่คะแนนน้อยเกินไป ค่าทุกคู่เท่ากันจนส่วนเบี่ยงเบนของผลต่างเป็นศูนย์ หรือคำนวณไม่ได้ด้วยเหตุอื่น ให้แสดง “ยังคำนวณไม่ได้” พร้อมเหตุผลและสิ่งที่ครูต้องแก้ ห้ามแสดง `NaN`, infinity, `0.000` หรือสรุปนัยสำคัญแทน
- paired-samples t-test อาศัยการกระจายของ “คะแนนผลต่าง” ไม่ใช่คะแนนก่อนหรือหลังแยกกัน รุ่นแรกต้องมีทางให้ครูเปิดดูข้อมูลที่ใช้และคำอธิบายข้อจำกัด โดยไม่กล่าวว่าข้อมูลผ่านข้อตกลงเบื้องต้นโดยอัตโนมัติ

### หน้าผลวิเคราะห์เทียบเกณฑ์ `/research/[id]/results`

- แท็บ “เทียบเกณฑ์ 70%” ใช้คะแนนหลังเรียนที่ผ่านการตรวจทั้งหมด ไม่ต้องมีคะแนนก่อนเรียน จึงอาจมี `n` มากกว่าหน้าก่อน–หลัง ระบบต้องบอกเหตุผลเมื่อ `n` ของสองแท็บต่างกันและห้ามบังคับตัดนักเรียนที่มีคะแนนหลังเรียนสมบูรณ์ออกเพียงเพราะขาดคะแนนก่อนเรียน
- คะแนนเกณฑ์คำนวณจากคะแนนเต็มของสำเนาข้อสอบหลังเรียนคูณร้อยละที่กำหนด เช่น 25 × 70% = 17.50 และใช้ค่าไม่ปัดเศษนี้ในการทดสอบทางสถิติ สำหรับผลผ่านรายบุคคลใช้กฎ `คะแนนหลังเรียน >= คะแนนเกณฑ์`; หากข้อสอบให้ได้เฉพาะจำนวนเต็ม เกณฑ์ 17.50 จึงหมายถึงคะแนนจริงขั้นต่ำ 18 โดยไม่เปลี่ยนเกณฑ์สถิติเป็น 18
- การ์ดสรุปแสดงคะแนนเกณฑ์ ค่าเฉลี่ยกับ S.D. หลังเรียน ผลต่างเฉลี่ยระหว่างค่าเฉลี่ยกลุ่มกับเกณฑ์ และจำนวน/ร้อยละผู้ผ่านเกณฑ์ โดยต้องแยก “ผลระดับกลุ่ม” ออกจาก “ผลรายบุคคล” อย่างชัดเจน
- one-sample t-test รุ่นแรกใช้การทดสอบสองด้านที่ระดับนัยสำคัญ .05 เป็นค่าเริ่มต้นและแสดงคำว่า “สองด้าน” ใน UI เพื่อรายงานอย่างระมัดระวัง ห้ามเปลี่ยนเป็นด้านเดียวหลังเห็นคะแนน; หากอนาคตรองรับสมมติฐานด้านเดียว ต้องกำหนดและบันทึกไว้ก่อนเปิดดูผล
- แถบผลทดสอบแสดงผลต่างเฉลี่ย ช่วงเชื่อมั่น 95% ของผลต่าง, `t(df)`, `p` และ `Cohen’s d` โดย `df = n - 1` และ `Cohen’s d = (ค่าเฉลี่ยหลังเรียน - คะแนนเกณฑ์) / S.D. หลังเรียน`
- กราฟแสดงค่าเฉลี่ยหลังเรียนพร้อม S.D. และเส้นคะแนนเกณฑ์บนแกนเดียวกัน แกนต้องเริ่มที่ 0 และสิ้นสุดที่คะแนนเต็มเพื่อไม่ขยายช่องว่างเกินจริง พร้อมระบุชัดว่าเส้นใดคือเกณฑ์และเส้นกำกับใดคือ S.D.
- “สรุปผลสำหรับรายงาน” สร้างจากผลคำนวณชุดเดียวกับตารางและใช้ถ้อยคำว่า “ค่าเฉลี่ยคะแนนหลังเรียนสูงกว่าเกณฑ์” เมื่อค่าเฉลี่ยและช่วงเชื่อมั่นอยู่เหนือเกณฑ์ ห้ามแปลว่าผู้เรียนทุกคนผ่าน
- จำนวนผู้ผ่าน เช่น 29/35 คน (82.9%) เป็นสถิติเชิงพรรณนารายบุคคล ไม่ใช่ผลของ t-test กล่องคำอธิบายต้องย้ำว่าค่าเฉลี่ยกลุ่มสูงกว่าเกณฑ์ได้แม้ยังมีนักเรียนบางคนไม่ผ่าน
- เกณฑ์ควรถูกกำหนดก่อนดูผลคะแนนและผูกกับรุ่นการวิเคราะห์ เมื่อมีคะแนนหลังเรียนแล้ว การแก้เกณฑ์ต้องแสดงค่าเดิม–ค่าใหม่ ขอเหตุผล ยืนยันผลกระทบ เก็บประวัติ และคำนวณผลใหม่ ห้ามแก้เงียบ ๆ เพื่อให้ผลผ่าน
- คะแนนหลังเรียนที่ว่างไม่ใช่ศูนย์และไม่ถูกรวมใน `n`; หน้า “ข้อมูลที่ใช้” ต้องแสดงผู้ที่รวม/ไม่รวมและเหตุผลตามสิทธิ์ครู โดยไฟล์สรุปสถิติไม่ใส่ชื่อหรือรหัสนักเรียนโดยไม่จำเป็น
- หากมีข้อมูลน้อยเกินไป S.D. เป็นศูนย์ เกณฑ์หรือคะแนนเต็มไม่ถูกต้อง หรือคำนวณไม่ได้ ให้แสดง “ยังคำนวณไม่ได้” พร้อมสาเหตุและสิ่งที่ครูต้องแก้ ห้ามแสดง `NaN`, infinity หรือสรุปนัยสำคัญแทน

- สถานะ “ใช้”, “ไม่ใช้”, “ผ่าน” และ “ไม่ผ่าน” ต้องมีไอคอนหรือข้อความกำกับ ไม่ใช้สีเป็นช่องทางสื่อความหมายเพียงอย่างเดียว และแถวที่มีข้อมูลไม่ครบอาจใช้พื้นเตือนเพื่อช่วยหาแต่ยังต้องอ่านเหตุผลได้โดยไม่อาศัยสี
- ตัวกรองอย่างน้อยประกอบด้วยทั้งหมด ใช้ก่อน–หลัง ใช้เทียบเกณฑ์ และข้อมูลไม่ครบ พร้อมค้นหาชื่อ/รหัสและตัวกรอง “ดูเฉพาะที่ไม่ถูกรวม” จำนวนบนตัวกรองต้องสัมพันธ์กับผลจริงและสิทธิ์ของครู
- ลิงก์ “ดูประวัติ” เปิดค่าก่อนแก้–หลังแก้ แหล่งคะแนน ผู้แก้ เหตุผล และเวลาโดยอ่านจาก audit ที่มีสิทธิ์ ห้ามแสดง token ภายใน รหัสแถว Excel หรือข้อมูลลับสำหรับตรวจลายเซ็น
- ภาพร่างใช้ชื่อและรหัสสมมติเท่านั้น หน้า production ต้องอ่านข้อมูลจริงตามโครงการและห้องเรียน และต้องไม่ส่งรายชื่อหรือคะแนนไปยัง analytics, log หรือ prompt ภายนอก
- ปุ่ม “ดาวน์โหลดข้อมูลที่ใช้” เป็น export ข้อมูลระดับบุคคลซึ่งต่างจากตารางสรุปสถิติ ต้องตรวจ session สิทธิ์โครงการ ห้องเรียน และทุกแถวฝั่ง server; ไฟล์ไม่ใช้ public URL ตั้งชื่อไม่เปิดเผยข้อมูลเกินจำเป็น และแสดงคำเตือนก่อนดาวน์โหลดว่ามีข้อมูลส่วนบุคคล
- เมื่อออกแบบขั้นดาวน์โหลดโดยละเอียด ให้ค่าเริ่มต้นเป็นไฟล์ไม่ระบุตัวตนและให้ครูเลือกไฟล์ที่มีชื่อ/รหัสเฉพาะเมื่อจำเป็น พร้อมบันทึกเหตุการณ์ส่งออกโดยไม่เก็บคะแนนหรือชื่อใน application log; ต้องทำภาพกล่องเลือกชนิดไฟล์ให้อนุมัติก่อนพัฒนา

## เรื่องที่รอเจ้าของผลิตภัณฑ์ยืนยัน

1. ข้อสอบก่อนและหลังเรียนอนุญาตทั้งชุดเดิมและชุดคู่ขนาน A/B หรือไม่ (ข้อเสนอ: รองรับทั้งสองแบบ โดยค่าเริ่มต้นใช้ชุดเดิมและสุ่มค่าใหม่เมื่อรองรับ; A/B ต้องให้ครูยืนยันความใกล้เคียง)

## ขั้นถัดไป

พักงานวิจัยไว้ ณ ระยะ 2.4 ระหว่างที่เจ้าของผลิตภัณฑ์พัฒนาระบบป้องกันการโกงสอบในแชทอื่น เมื่อกลับมาให้เริ่มจากตรวจงานที่ merge/push ล่าสุด ทดสอบระยะ 2.4 ด้วยโครงการที่มีคะแนนจริง แล้วทำภาพกล่องเลือกดาวน์โหลดข้อมูลแบบ “ไม่ระบุตัวตน”/“มีชื่อและรหัส” เพื่ออนุมัติก่อนพัฒนาการส่งออกจริง
