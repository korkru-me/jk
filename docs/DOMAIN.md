# Domain model และคำศัพท์

อัปเดตล่าสุด: 18 สิงหาคม 2026

## บทบาทผู้ใช้

### ครู (`teacher`)

สร้างและจัดการโจทย์ ห้องเรียน งาน ข้อสอบ และผลการเรียนตาม organization/classroom ที่มีสิทธิ์

### นักเรียน (`student`)

เข้าร่วมห้อง ดูงาน ทำ attempt ส่งคำตอบ และดูผลตามนโยบายของ assignment

### ครูประจำชั้น

ไม่ใช่ global user role แต่เป็นครูเจ้าของหรือผู้มีสิทธิ์จัดการ classroom ชนิด `homeroom` มีหน้าที่ติดตามภาระงานข้ามรายวิชาและข้อมูลดูแลนักเรียน

### ครูผู้สอนร่วม

ไม่ใช่ global user role แต่เป็นสมาชิก `classroom_co_teachers` ของห้องใดห้องหนึ่ง:

- `admin` — ระดับสูงในห้องเรียน ตามขอบเขตที่ server/RLS อนุญาต
- `manage` — จัดการงานและข้อมูลปฏิบัติการที่กำหนด
- `view` — ดูข้อมูลโดยไม่แก้ไข

ห้ามตีความชื่อ `admin` ของ co-teacher ว่าเป็น system admin

### แอดมิน

ผลิตภัณฑ์กำหนดว่ามีแอดมินใน MVP แต่โค้ดปัจจุบันมีหลายแนวคิด:

- `users.role = admin`
- `organization_members.org_role = owner/admin`
- `super_admins` ในฐานข้อมูล

ต้องตัดสินใจ authority matrix ขั้นสุดท้ายก่อน production ห้ามรวมสิทธิ์เหล่านี้เข้าด้วยกันโดยปริยาย

## Organization และขอบเขตข้อมูล

- `organization` คือ tenant หรือ workspace ที่ถือครองทรัพยากร
- organization อาจเป็น personal, team หรือ school ตามข้อมูลปัจจุบัน
- `org_id` เป็น security boundary ไม่ใช่เพียง field สำหรับ filter
- การแชร์โจทย์/แฟ้มโจทย์ข้ามทีมต้องใช้ visibility และ share relations ที่กำหนด

## ห้องเรียน

### Subject classroom

ห้องรายวิชาที่มี assignment/exam ของตัวเอง นักเรียนเข้าร่วมผ่าน class code

### Homeroom classroom

ห้องดูแลนักเรียนที่รวมงานจาก subject classrooms อื่น ไม่มี assignment รายวิชาของตัวเองตามโมเดลปัจจุบัน

Lifecycle ของห้องเรียน:

- `active` — ใช้งานอยู่
- `archived` — เก็บออกจากรายการหลักและกู้คืนได้
- `deleted` — soft-deleted/trash ก่อนลบถาวร

## โจทย์

`Question` คือหน่วยเนื้อหาและการตรวจคำตอบที่นำกลับมาใช้ซ้ำได้ ประเภทที่ application types รองรับ:

- `written` — คำตอบตัวเลข/สูตร รวมทั้งค่าคงที่หรือค่าที่สุ่ม
- `mcq` — ปรนัย เลือกได้หนึ่งหรือหลายคำตอบตามข้อมูลตัวเลือก
- `true_false` — ถูก/ผิดแบบเดี่ยว แบบหลายข้อความ หรือเลือกข้อความที่ตรงเงื่อนไข
- `fill_blank` — ช่องว่างชนิด free text, fixed answer หรือ dropdown
- `ordering` — เรียงลำดับ
- `matching` — จับคู่
- `essay` — คำตอบบรรยาย ให้ครูตรวจ
- `file_upload` — ส่งไฟล์/รูป/PDF ตามคำสั่ง
- `composite` — รวมคำถามย่อยหลายชนิดใต้โจทย์หลักเดียว

บางรูปแบบพิเศษใช้ `parent_question_id`, `group_id` และ `order_in_group` เพื่อรักษากลุ่ม/ลำดับ ห้ามเปลี่ยน semantics โดยไม่ตรวจหน้า create, edit, preview, exam และ grading พร้อมกัน

## โจทย์สุ่มตัวเลข

- `variables` กำหนดช่วง ค่า step ค่าคงที่ หรือการอ้างอิงคำตอบก่อนหน้า
- `logic_rules` จำกัดความสัมพันธ์ของตัวแปร
- `answer_formula` หรือ `answer_parts` ใช้คำนวณคำตอบ
- ค่าที่สุ่มต้องถูกสร้างเมื่อเริ่ม attempt และเก็บใน `submission_answers.random_values`
- attempt เดิมต้องได้ค่าและเฉลยเดิมเมื่อกลับมาทำต่อ
- ห้ามสุ่มใหม่ระหว่าง render, save หรือ grade

## ตัวเลือกหลอก

MCQ แบบคำนวณสามารถสร้างสูตรคำตอบที่ถูกและสูตรตัวเลือกหลอก ตัวเลือกหลอกควรสะท้อนความเข้าใจผิดที่เป็นไปได้ ไม่ใช่เพียงเลขสุ่ม และต้องไม่ชนกับคำตอบถูกหลังแทนค่าตัวแปร

## แฟ้มโจทย์ งาน และข้อสอบ

- `QuestionSet` คือแฟ้มโจทย์ที่นำกลับมาใช้ซ้ำได้
- **แฟ้มย่อย** (`question_sets.sections` — โค้ดและฐานข้อมูลยังใช้คำว่า section) คือการจัดกลุ่มชั้นเดียวภายในแฟ้ม เช่น แฟ้ม "การเคลื่อนที่สองมิติ" มีแฟ้มย่อย "โปรเจกไทล์" และ "วงกลม" — ไม่มีแฟ้มย่อยซ้อนแฟ้มย่อย
- โจทย์หนึ่งข้ออยู่ได้**หลายแฟ้มย่อยพร้อมกัน** เช่นข้อที่ถามทั้งงานและพลังงานอยู่ได้ทั้งสองแฟ้มย่อย ครูจึงมอบหมายแฟ้มย่อยไหนก็ได้แล้วยังได้ข้อนั้น — ผลตามมาคือลำดับเลขข้อไม่ผูกกับลำดับแฟ้มย่อย (ข้อที่อยู่สองที่ไม่มีตำแหน่งเดียว) และหน้าที่แสดงชื่อแฟ้มย่อยได้ป้ายเดียวต่อข้อ (ใบพิมพ์ ตารางนำทาง) จะใช้แฟ้มย่อยแรกที่ข้อนั้นสังกัด
- แฟ้มย่อยต่างจากแท็ก: แฟ้มย่อยคือโครงสร้างและลำดับภายในแฟ้มเดียว ส่วนแท็กใช้ค้นหาข้ามแฟ้ม
- ครูมอบหมายเฉพาะบางแฟ้มย่อยได้ (`/assignments/new?set=<id>&sections=<id>`) และงานที่ได้จะเก็บ snapshot ของแฟ้มย่อยไว้เอง
- `Assignment` คือการมอบหมายจริงและอาจเป็น `exercise` หรือ `exam`
- งานหนึ่งชิ้นเชื่อมหลาย classroom ผ่าน `assignment_classrooms`
- สถานะ assignment: `draft`, `published`, `closed`
- mode ปัจจุบัน: `online`, `print`

## Attempt, submission และ answer

- หนึ่ง `Submission` คือหนึ่ง attempt ของนักเรียนต่อ assignment
- `in_progress` — เริ่มแล้ว ยังไม่ส่ง
- `submitted` — ส่งแล้ว แต่อาจยังมีส่วนรอครูตรวจ
- `graded` — การให้คะแนนเสร็จตาม workflow
- `SubmissionAnswer` เก็บ snapshot ที่จำเป็นต่อความยุติธรรม เช่น random values, correct answer และ option order

## การให้คะแนน

- คะแนนโครงสร้างมาจากชนิดโจทย์และส่วนย่อย
- `question_points` override คะแนนรายข้อของ assignment
- `display_max_score` rescale คะแนนตอนอ่านและอาจเปลี่ยนภาพอดีตโดยไม่แก้ raw score
- หลาย attempt สรุปได้ด้วย `best`, `average` หรือ `latest`
- ครูแก้คะแนนรายคำตอบได้และต้องเก็บผู้แก้/เวลาที่แก้
- เกณฑ์ผ่านอาจเป็นคะแนนหรือเปอร์เซ็นต์ และเป็น optional

โจทย์ essay, free-text บางชนิด และไฟล์อัปโหลดไม่ควรถูกประกาศว่าตรวจอัตโนมัติทั้งหมด

## ข้อมูลนักเรียน

ข้อมูลชื่อ ห้อง เลขที่ และคะแนนเป็นข้อมูลส่วนบุคคล ข้อมูลผู้ปกครอง ที่อยู่ เบอร์โทร สุขภาพ โรคประจำตัว ครอบครัว และบันทึกพฤติกรรมเป็นข้อมูลอ่อนไหวกว่า ต้องจำกัดเฉพาะเจ้าของข้อมูลและครูประจำชั้น/ผู้ได้รับอนุญาตตามวัตถุประสงค์
