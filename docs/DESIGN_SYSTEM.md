# Brand, language และ UI rules

## Picker card interaction and density — 15 October 2026

In picker mode, the card frame/content/title toggles selection and only the eye action opens preview. Nested controls and their overlays act independently; the title button exposes its selected state for keyboard use. The plain picker uses gap-2; select-all uses min-h-6 on desktop and min-h-11 for coarse pointers, avoiding a tall empty band above the questions.

## Folder picker controls — 15 October 2026

The add-from-bank dialog omits its selection helper sentence and add-tag button while retaining existing tag chips. Its select-all checkbox sits above the list and operates on current search/difficulty results, preserving hidden picks, showing partial selection, and disabling itself for empty results. Confirmation still applies the staged selection. Bank cards retain add-tag controls.

## แถบด้านบนคลังฝึกแบบกระชับ — 15 ตุลาคม 2026

ช่องค้นหาใช้ placeholder “ค้นหาชื่อหรือเนื้อหาโจทย์” และ “ค้นหาแท็ก” พร้อม aria-label เดียวกัน ไม่มี label หรือคำแนะนำจำนวนแท็กซ้ำด้านนอก ปุ่มค้นหา/ดูข้อที่ปักไว้/สร้างแบบฝึกหัดใช้ size sm และแถบเลือกใช้ min-h-7 บน desktop; pointer-coarse คงพื้นที่กด 44px. ข้อความวิธีสร้างและวิธีนับความคืบหน้าอยู่ใน Tooltip ของหัวข้อ “แบบฝึกหัดของฉัน” พร้อมไอคอน CircleHelp เล็ก เปิดด้วย hover/focus และเชื่อม aria-describedby เฉพาะเมื่อเปิด ไม่มีแถว “พบ … ข้อ” ว่างเพิ่มก่อนการ์ด; ปุ่มล้างตัวกรอง/ดูโจทย์ทั้งหมดแสดงเฉพาะเมื่อจำเป็นตามเดิม

## การ์ดเลือกโจทย์จากคลัง — 15 ตุลาคม 2026

`QuestionPicker` ใช้ `QuestionCard` เดียวกับคลังโจทย์ พร้อมช่องติ๊กและป้าย/ชื่อ/ข้อความย่อ ดูตัวอย่างและสถานะเฉลย แต่ซ่อนชุดแชร์ รายงาน ทำสำเนา แก้ไข ลบในโหมดเลือก ป้ายแฟ้มไม่เป็นลิงก์ออกจากร่าง; สถานะจะเพิ่ม/เอาออกยังแสดงด้วยสีและข้อความเดิม และการเปิดตัวอย่างไม่เปลี่ยนการเลือก การ์ดใช้ padding เดิมและไม่กำหนดความสูงขั้นต่ำ บนจอแคบ checkbox อยู่ซ้าย metadata ส่วนปุ่มอยู่แถวเต็มความกว้างและตัดบรรทัดได้เพื่อไม่ล้นกรอบ


## คลังฝึกสองคอลัมน์และปุ่มขนาดคลังโจทย์ — 15 ตุลาคม 2026

รายการโจทย์คลังฝึกใช้สองคอลัมน์เมื่อพื้นที่เนื้อหากว้างอย่างน้อย 44rem และหนึ่งคอลัมน์บนจอแคบ ใช้ความกว้าง main เต็มโดยไม่จำกัด 1200px. ตามคำขอเจ้าของ ปุ่มดูตัวอย่าง/เฉลยใช้ size sm และปักหมุดใช้ icon-sm เหมือนคลังโจทย์บน desktop; เฉพาะ pointer-coarse ยังคงพื้นที่ปุ่ม/label อย่างน้อย 44px. ช่องติ๊กแต่ละข้อและเลือกทั้งหน้าใช้ขนาด native เหมือนคลังโจทย์ ไม่ขยายด้วย size-5. การ์ดวางปุ่มข้างเนื้อหาเมื่อกว้างพอและย้ายลงด้านล่างบนจอแคบ กฎนี้แทนขนาด controls เดิมเฉพาะส่วนรายการโจทย์คลังฝึก

## คลังฝึกในสรุปงานนักเรียน — 14 ตุลาคม 2026

คลังฝึกใช้ WorkRow/Card และสี/ไอคอนประจำวิชาเหมือนงานอื่น เพื่อให้รู้ว่าเป็นงานของห้องใด แต่ป้ายรูปหนังสือ “คลังฝึก” ต้องมองเห็นข้างชื่อ มีจำนวนโจทย์กับ “ฝึกได้เรื่อย ๆ · ไม่มีคะแนน” ในแถว metadata ไม่ใช้สีอย่างเดียวเพื่อบอกประเภท ไม่แสดงวันส่ง ระยะเวลาทำ คะแนน หรือ “ส่งแล้ว” ให้คลังฝึก

งานที่ทำครบเงื่อนไขเดิมอยู่ท้ายรายการเสมอ ไม่สลับขึ้นบนเมื่อกลับทิศตัวกรอง; งานที่ยังไม่เสร็จและคลังฝึกอยู่กลุ่มแรกตามตัวกรอง คงจำนวนคลังแยกจากจำนวนงานที่ต้องทำ. Header ใช้ py-2, ตัวกรอง size xs + min-h-11 เพื่อกดสะดวกและอยู่แถวเดียวบน 320px ไม่มี helper/กรอบว่างเพิ่มโดยไม่จำเป็น


## กฎถาวร: ใช้พื้นที่แกน Y อย่างประหยัด — 14 ตุลาคม 2026

ทุกหน้าและทุก UI ใหม่/ที่แก้ต้องเริ่มจาก layout กระชับ ใช้ความสูงเท่าที่เนื้อหาต้องใช้ ลด padding/gap และพื้นที่ว่างที่ไม่มีหน้าที่ โดยยังคงลำดับข้อมูล อ่านง่าย กดสะดวก และสวยงาม ไม่รอให้เจ้าของขอย่อเป็นรายหน้า รายละเอียดการทำงานอยู่ `.cursor/rules/vertical-space.mdc` ซึ่ง alwaysApply และ `AGENTS.md`

วางหัวข้อ ปุ่ม ตัวกรอง และจำนวนที่เกี่ยวข้องในแถวเดียวเมื่อพื้นที่พอ ใช้ container width เมื่อติด sidebar/split pane; บนจอแคบย้ายบรรทัดเฉพาะเมื่อจำเป็น คงพื้นที่กดอย่างน้อย 44px, label/error/focus และความเข้ากันได้กับคีย์บอร์ด ไม่ทำตัวอักษรเล็กจนอ่านยากเพื่อแลกพื้นที่ เริ่มกรอบจากแนวซ้ายมาตรฐานของ main ข้างเมนู ไม่เพิ่ม gutter กลางจอโดยไม่มีเหตุผล

คลังฝึกใช้การ์ด radius md, px-3/py-2 และ gap-2, สถานะตอบอยู่กับ metadata, title/excerpt หนึ่งบรรทัดเมื่อการ์ดกว้างและสองบรรทัดบนจอแคบพร้อมปุ่มอ่านโจทย์เต็ม; ปุ่มปักหมุดและแก้ชุดเป็นไอคอนมีชื่อและ title ชัดเจน ดูข้อที่ปักอยู่แถวหัวข้อชุดฝึก แถบเลือก px-3/py-1.5 และ controls 44px. ต้องวัดความสูงของส่วนที่แก้ก่อน/หลังและตรวจจอ desktop/แคบทุกครั้งที่เปลี่ยน layout มาก


## แก้ชุดฝึกและปักข้อในคลังฝึก

การ์ดชุดฝึกแยกลิงก์เปิดชุดออกจากปุ่ม “แก้ชื่อและโจทย์” เพื่อไม่ให้คลิกแก้ไขแล้วเปลี่ยนหน้า แถบแก้ไขมีชื่อ รายการสมาชิกที่เลื่อนภายใน ปุ่มเอาออก และเพิ่มโจทย์จากคลัง เมื่อบันทึกล้มเหลวต้องคงร่างและแสดง error; revision conflict มีปุ่มโหลดข้อมูลล่าสุดที่ยืนยันก่อนทิ้งร่าง ปุ่มปักใช้ข้อความพร้อม aria-pressed และพื้นที่สัมผัส 44px มีทางเปิดดูเฉพาะข้อที่ปักและ empty state สำหรับรายการว่าง

- ธงแสดงเป็นไอคอนแยกจากสีพื้นคำตอบ อธิบายด้วยภาษา “ปักธงเพื่อระบุข้อที่ต้องการกลับมาทบทวนก่อนส่งคำตอบ” ใน tooltip ของปุ่มและ legend; ปุ่มต้องมี aria-pressed และชื่อปักธง/ยกเลิกธงที่ตรงสถานะ

## Brand

- ชื่อหลัก: **ก่อครู**
- English mark: **KorKru**
- โลโก้หลักใช้รูปกวางสามเขาที่เจ้าของผลิตภัณฑ์เลือก 14 ตุลาคม 2026: เขาที่สามโค้งกางไปด้านซ้ายเหนือหู ผ่าน `components/brand-logo.tsx` ร่วมกันทั้ง header หน้าเว็บสาธารณะและหน้าบัญชี โดย UI ใช้ geometry จาก `public/brand/deer-mark.svg` เป็น CSS mask สีเดียว จึงคงขอบคมทุกระดับการซูมและไม่มี glow/blur/bitmap ฝังอยู่ · ตาม UI-063 กวางทั้งตัวและตัว `o` ในคำว่า `KorKru` ใช้ token `brand-accent` เดียวกัน ซึ่งอ้างอิง `primary` ของ preset ปัจจุบันและเปลี่ยนตาม light/dark mode ส่วนตัวอักษรอื่นใช้ `brand-foreground` กรมท่า `#002262` ในโหมดสว่าง/ขาวในโหมดมืด ไม่ใช้สีดำของ UI foreground · เก็บภาพต้นฉบับ โลโก้เต็มเดิมที่ `public/logo.png` และไอคอนเดิมที่ `public/brand/legacy-*.png` ไว้ ไม่ลบหรือเขียนทับ
- SVG และ `components/brand-mark-data.ts` สร้างจาก `public/brand/deer-mark-three-antlers-source.png` ด้วย `node scripts/vectorize-brand-mark.mjs`; `BrandLogo` ใช้อัตราส่วนจาก geometry นี้ ลายปกกวางใช้ path เดียวกัน และ favicon/Apple touch icon เป็นกวางม่วงบนวงกลมขาว มุมนอกวงกลมโปร่งใส สร้างใหม่ด้วย `node scripts/build-brand-icons.mjs`
- แนวคิดภาษา: **“ก่อ…โดยครู”**
- ขนาดภาพกวางใน `BrandLogo`: stacked `h-10`, horizontal `h-11` และ compact `h-8`; ทุก layout ต้องใช้กวางสีเดียวกับตัว `o` ผ่าน `brand-accent` ห้ามแยกสีเขาหรือฝังสี hex ใน component · ปุ่มสามขีดใน header ใช้ `pl-3` เพื่อให้ขอบพื้นปุ่มตรงกับขอบซ้ายของแถบเมนูหลักเมื่อแถบเต็ม

คำตรงกลางเป็นข้อความที่เปลี่ยนได้ตามบริบท ไม่ใช่คำที่หายหรือ error state ตัวอย่างเช่น “ก่อข้อสอบโดยครู” บนหน้าสร้างข้อสอบ และ “ก่อห้องเรียนโดยครู” บนหน้าห้องเรียน

หากทำ motion/rotation:

- ต้องอ่านประโยคได้เมื่อ animation ถูกปิด
- หลีกเลี่ยงการสลับเร็วหรือทำ layout shift
- ใช้คำที่เจ้าของผลิตภัณฑ์อนุมัติหรือคำที่ตรงกับบริบทจริง
- รักษา accessibility สำหรับ `prefers-reduced-motion`

## ภาษา

- Product copy, labels, validation และคำอธิบายสำหรับผู้ใช้เป็นภาษาไทย
- Code, filenames, routes, database fields และ standard technical terms เป็นอังกฤษ
- ใช้คำสั้นและเป็นภาษาครู ไม่ใช้ศัพท์เทคนิคเพื่อทำให้ผลิตภัณฑ์ดูซับซ้อน
- แยกคำว่า “งาน”, “แบบฝึกหัด” และ “ข้อสอบ” ตามพฤติกรรมจริง ไม่ใช้สลับกันเมื่อมีผลต่อเวลา attempt หรือผลคะแนน
- Error message ต้องบอกว่าผู้ใช้ทำอะไรต่อได้ ไม่แสดง raw database error เมื่อเป็น production

## Visual language ที่มีอยู่

- ตาม UI-118 ปฏิทินนักเรียนมีความกว้างไม่เกิน `14rem` และแสดงเพียงวันที่กับจุดสถานะในหน้า; รายละเอียดอยู่ใน Hover Card ที่เปิดด้วย hover/keyboard/แตะ และมีปุ่มขยายเดือนเป็น popup อ่านอย่างเดียวที่เลื่อนภายในได้ บน desktop แสดงชื่อห้องวิชา ชื่องาน และเวลาในช่องวัน ส่วนมือถือมีรายการทั้งเดือนเรียงตามวัน · หน้าหลักนักเรียนไม่มี Card สถิติ “ห้องเรียน / ส่งงานแล้ว / คะแนนเฉลี่ย” และวางปฏิทินข้างเนื้อหาหลักเพื่อประหยัดพื้นที่ โดยคงสามหน้าหลักแยกกันจนกว่าเจ้าของจะกำหนดรูปแบบรวม

ครูจัดแฟ้มจากหน้าคลังแฟ้มก่อน แล้วเลือกแฟ้มหรือโจทย์ที่มีอยู่มาใช้ในงาน ส่วน “คะแนนเต็มที่แสดงผล” ต้องอยู่ใน `Card` “ชุดโจทย์ที่นักเรียนได้รับ” เดียวกัน และเมื่อสุ่มต้องวางคู่กับจำนวนข้อที่ให้นักเรียนทำในแถวเดียวกันตั้งแต่จอ `sm` ขึ้นไปโดยไม่ใช้กรอบซ้อน และหัวข้อ “เลือกโจทย์” ต้องมี `*` สี `destructive` พร้อมข้อความ “จำเป็น” สำหรับ screen reader เพราะไม่อนุญาตให้สร้างงานที่ไม่มีโจทย์ ส่วน “เพิ่มจากแฟ้มโจทย์ที่มีอยู่” และ “เลือกโจทย์รายข้อ” ต้องพับเมื่อคลิกนอกกรอบ แต่ไม่พับจาก interaction ภายในหรือ dialog ตัวอย่าง และต้องสลับกรอบที่เปิดได้ในคลิกเดียว ส่วน “คะแนนแต่ละข้อ” ต้องมีปุ่ม “ดูโจทย์ทั้งหมด” เพื่อเปิดตัวอย่างครบตามลำดับปัจจุบันในหน้าต่างเดียว มีคำสั่งเล็ก “ทุกข้อ 1 คะแนน” และ “คะแนนตามข้อย่อย” สำหรับปรับคะแนนโจทย์ที่เลือกทั้งชุด; คำสั่งล่าสุดที่ใช้สำเร็จต้องคงพื้น `primary` และเครื่องหมายถูกพร้อม `aria-pressed`/live status จนกว่าจะเปลี่ยนคะแนนรายข้อหรือสมาชิกโจทย์ เพื่อยืนยันผลโดยไม่ทำให้ครูเข้าใจผิด และใช้การกดค้างลากบริเวณหมายเลข/ชื่อโจทย์เพื่อเรียงแทนลูกศรขึ้นลง โดยคงช่องเลขที่พิมพ์ตำแหน่งแล้วกด Enter ได้และไม่ให้ gesture ลากครอบปุ่มดูตัวอย่าง ช่องคะแนน หรือปุ่มลบ; ภายใน dialog ดูทั้งหมด เลขข้อของแต่ละการ์ดเป็นดรอปดาวน์สำหรับย้ายตรงไปยังตำแหน่งปลายทาง ต้องแสดงคำอธิบาย “เลือกเพื่อย้ายโจทย์ไปยังลำดับที่ต้องการ” เมื่อวางเมาส์หรือโฟกัสด้วยแป้นพิมพ์ และต้องอัปเดตลำดับจริงชุดเดียวกับรายการคะแนนโดยไม่โหลดเนื้อหาโจทย์ซ้ำ ส่วน preview จากแฟ้มยังเป็น read-only ไม่มีตัวควบคุมลำดับ เมื่อเลือกสุ่มให้ปิดช่อง/คำสั่งคะแนนรายข้อ แสดงทุกข้อเป็น 1 คะแนน และอธิบายว่าคะแนนดิบเท่ากับจำนวนข้อที่ตอบถูก ส่วนหน้าแก้ไขงานใช้กติกาเดียวกันแต่ยังรวมคะแนนรายข้อกับคะแนนเต็มแสดงผลไว้ใน `Card` “ตั้งค่าคะแนน” เดิม มีหัวข้อย่อยและ `Separator` แบ่งส่วน ไม่ใช้กรอบซ้อนหรือซ่อนความต่างของคะแนนจริงกับคะแนนที่แสดง; แถวคะแนนขึ้นหลายบรรทัดเมื่อจอเล็กเพื่อให้ชื่อโจทย์ ลำดับ ปุ่ม และช่องคะแนนไม่ถูกตัด และคงแถวเดียวตั้งแต่ `sm` ขึ้นไป

ตาม UI-010/011/020/082/UI-090/UI-092/UI-094 หลังเลือกโจทย์แล้ว หน้าสร้างงานวาง “ชุดโจทย์ที่นักเรียนได้รับ” เป็นกรอบถัดจาก Card รวม “โจทย์ คะแนน และเวลา” และรวม “คะแนนเต็มที่แสดงผล” ไว้ในกรอบเดียวกันก่อนเงื่อนไขจบงาน โดยไม่แสดงกรอบคะแนนแยกขณะยังไม่มีโจทย์: โหมดทำทุกข้อเว้นว่างเพื่อใช้ผลรวมจริง ส่วนโหมดสุ่มกำหนดทุกข้อเป็น 1 คะแนนและวางจำนวนข้อที่ให้นักเรียนทำกับคะแนนเต็มใน grid สองคอลัมน์เดียวกันตั้งแต่จอ `sm` ขึ้นไป โดยเว้นว่างคะแนนเต็มเพื่อใช้จำนวนข้อที่สุ่มเป็นค่าอัตโนมัติ หรือกรอกค่าบวกเพื่อปรับสเกลคะแนนรวมได้ หน้าแก้ไขยังวางกรอบชุดโจทย์ถัดจาก Card “ตั้งค่าคะแนน” ตามเดิม จำนวนข้อต่อหนึ่งหน้าอยู่ภายใน Card คะแนนทั้งสองหน้า; งานใหม่ที่ไม่ได้ทำสำเนาหรือใช้ชุดการตั้งค่าที่บันทึกไว้เริ่มต้นที่ 5 ข้อต่อหน้า ส่วนโหมด streak ยังคงแสดงคำอธิบายทีละ 1 ข้อแทนช่องตามเดิม

## Style presets

สไตล์ทั้งเว็บคุมด้วย CSS variable ใน `app/globals.css` ไม่ใช่ class ในแต่ละไฟล์ แกนที่หมุนได้:

- `--primary`, `--success`, `--warning`, `--flag`, `--destructive` และ token สีอื่น — ความหมาย ไม่ใช่การตกแต่ง
- `--radius` — ความมนทั้งเว็บ (Tailwind คำนวณ `rounded-*` จากค่านี้)
- `--spacing` — ความโปร่ง/แน่น (Tailwind คำนวณ `p-*`, `gap-*`, `m-*` จากค่านี้)
- `--elevation-sm|md|lg|xl` — เงา

เปลี่ยนสไตล์ทั้งเว็บด้วยการใส่ `data-style` บน `<html>` ใน `app/layout.tsx`:

```
<html lang="th" data-style="warm">
```

preset ที่มีให้:

| preset | ลักษณะ |
| --- | --- |
| `soft` | มน โปร่ง เงานุ่มฟุ้ง |
| `sharp` | เหลี่ยม แน่น ไม่มีเงา ใช้เส้นขอบแทน |
| `warm` | พื้นครีม primary terracotta |
| `minimal` | เกือบขาวดำ น้ำหนักตัวอักษรเบา เส้นขอบบาง |
| `playful` | หนา มนมาก เงาทึบแบบ offset |

ไม่ใส่ = ค่าเริ่มต้น (indigo, มนปานกลาง) — ปัจจุบันแอปตั้ง `data-style="playful"` ไว้

ทุก preset ผ่าน WCAG AA (ตัวอักษรบนปุ่ม primary ≥ 4.5:1) ทั้งโหมดสว่างและมืด ถ้าเพิ่ม preset ใหม่ต้องวัด contrast ก่อนใช้

สีแบ่งเป็น 2 ชนิด — อย่าสลับกัน:

- **สีที่มีความหมาย** (`--primary`, `--success`, `--warning`, `--flag`, `--destructive`) เปลี่ยนค่าได้ แต่ห้ามเปลี่ยนว่าอะไรหมายถึงอะไร
- **ฉากหลังทึบ** (`--overlay`) ใช้กับ modal และภาพที่ต้องหรี่ — preset ปรับความเข้ม/โทนได้
- **พื้นมืดกลับสี** (`--surface-inverse` + `-foreground` / `-muted` / `-border`) ใช้กับแบนเนอร์ การ์ดหัวเรื่อง และ chrome ของ super-admin ที่ตั้งใจให้มืดทั้งสองโหมด — preset ปรับโทนได้
- **สีตกแต่ง** (`--tint-1` … `--tint-4`) ใช้แยกแยะรายการเฉยๆ เช่น stat card, ไอคอน, ป้ายหมวดหมู่ — สลับได้อิสระ preset ควรปรับให้เข้ากับ primary ของตัวเอง (เช่น `playful` ใช้ primary ม่วงแดง จึงดัน tint-1 ไปทางน้ำเงินไม่ให้ดูเหมือนพลาด)

preset ปรับได้ 5 แกน: สี, `--radius`, `--spacing`, `--elevation-*` และ typography (`--font-weight-*`, `--text-*`, `--tracking-*`) — Tailwind v4 คำนวณ utility จากตัวแปรเหล่านี้อยู่แล้ว จึงไม่ต้องแก้ component

ดูผลของแต่ละ preset บนคอมโพเนนต์จริงได้ที่ `/style-preview` (เปิดเฉพาะตอน `next dev` — production จะ 404)

เพิ่ม preset ใหม่โดยคัดลอกบล็อก `[data-style="..."]` ท้าย `globals.css` แล้วแก้ค่า ไม่ต้องแก้ไฟล์อื่น

**preset เปลี่ยนได้เฉพาะการตกแต่ง** ห้ามเปลี่ยนว่าสีไหนหมายถึงอะไร — เขียวยังคงหมายถึงสำเร็จ ส้มยังคงหมายถึงโจทย์ที่ถูกรายงาน ในทุก preset

สิ่งที่ยังเป็นค่าคงที่โดยตั้งใจ: แถบสเกลเปอร์เซ็นไทล์ — เป็นเนื้อหาและความหมาย ไม่ใช่การตกแต่ง preset จึงไม่ควรเปลี่ยน

ชุดสีปกห้องเรียน (`COVER_PRESETS` ใน `app/(app)/classrooms/_components/classroom-meta.ts`) เคยเป็น hex ไล่เฉดคงที่ แต่เปลี่ยนมาเป็นสีพื้นเรียบที่อ้าง token ตามที่เจ้าของผลิตภัณฑ์สั่ง จึงเปลี่ยนตาม preset และโหมดสว่าง/มืดด้วย ผลที่ตามมาคือการสลับ preset จะเปลี่ยนโทนสีปกที่ครูเลือกไว้ — แลกกับการได้ contrast ที่ผ่าน AA ทั้งสองโหมดโดยไม่ต้องดูแลชุด hex เอง

ภาพปกห้องเรียนใช้ `ClassroomCoverPattern` และ stable key จาก `lib/classroom-cover-patterns.ts` จำนวน 11 แบบ ทุกรูปทรงใช้ `currentColor` สีเดียวหลายระดับ opacity โดยไม่มี hex หรือ palette ฝังในภาพ จึงเปลี่ยนตาม `COVER_PRESETS`, preset และ light/dark mode ได้ · ตาม UI-057 พื้นที่ภาพอยู่ในครึ่งสามเหลี่ยมขวาบนเหนือเส้นทแยงจากซ้ายบนไปขวาล่าง ส่วนซ้ายล่างต้องสงบเพื่อรองรับชื่อห้อง ภาพใช้รูปทรงทึบโปร่งแสงร่วมกับเส้นรายละเอียดได้ ไม่จำกัดเป็น line art และใช้ `placement="end"` กับ `meet` เพื่อรักษาตำแหน่งโดยไม่ crop · ชุดนี้เป็นองค์ประกอบต้นฉบับของ KorKru ไม่คัดลอกหรือเลียนแบบชุดปกของ Google Classroom และลายกวางต้องอิงเครื่องหมายแบรนด์ที่อนุมัติใน `public/brand/deer-mark.svg` ไม่ใช้กวางสต็อก · ตาม UI-083 ส่วนเลือกภาพปกแสดงหัวข้อ “ภาพปกห้องเรียน” แล้วตามด้วยตัวเลือกทันที ไม่แสดงข้อความอธิบายงานออกแบบหรือการเปลี่ยนสีตามธีม · ตัวเลือกปกต้องแสดงภาพอย่างเดียวโดยไม่มีชื่อวิชาหรือคำอธิบายชี้นำทั้ง caption และ tooltip ผู้ใช้เป็นผู้กำหนดความหมายเอง ส่วน accessible name ใช้เลขลำดับกลาง เช่น “ภาพปกแบบที่ 1” · หน้าเริ่มสร้างห้องต้องสุ่ม stable key หนึ่งครั้งต่อฟอร์มและคงค่านั้นจนบันทึก ไม่สุ่มใหม่จาก re-render; การทำสำเนาคงปกต้นฉบับและสุ่มเฉพาะห้องเก่าที่ไม่มี key · ห้องเก่าหรือ key ที่ไม่รู้จักในจุดแสดงผลยังใช้ลาย `classroom` และต้องไม่ render markup/URL ที่มาจาก metadata โดยตรง

ตัวอักษรบนหน้าปกต้องผสมกับ `--foreground` ด้วย `color-mix` เสมอ ห้ามวางสี token เต็มความเข้มบนพื้น `/10` เพราะวัดจริงแล้วได้เพียง 1.9–4.5:1 ซึ่งตกเกณฑ์ AA เกือบทุกสี

องค์ประกอบใหม่ต้องใช้ token และ primitive ใน `components/ui/` ไม่เขียน class สีหรือทรงเอง — `npm run lint:tokens` ตรวจข้อนี้ 4 อย่าง:

| ตรวจอะไร | ใช้อะไรแทน |
| --- | --- |
| สี palette ดิบ (`bg-gray-100`, `text-white`, `bg-black/50`) | token ใน `globals.css` |
| การ์ดเขียนมือ | `<Card>` |
| form control เขียนมือ | `<Input>` / `<Textarea>` / `<NativeSelect>` |
| ปุ่มเขียนมือ | `<Button>` / `<IconButton>` |
| class ผิดรูป (`bg-primary/10/40`) | — Tailwind ทิ้งเงียบๆ ต้องแก้ |

`<NativeSelect>` คือ `<select>` ธรรมดาที่จัดสไตล์ให้ตรงกับ `<Input>` ส่วน `<Select>` (base-ui) เป็น dropdown แบบเต็มรูปแบบสำหรับกรณีที่ต้องการมากกว่านั้น

## UI behavior

### คลังฝึกแบบกะทัดรัดและไม่สื่อเป็นคะแนน

- ใช้คำว่า **“คลังฝึก”** ในทางเข้าสร้างภายในห้องเรียน และไม่วางทางเข้าคลังฝึกใน sidebar หลัก เพราะคลังทุกชุดต้องผูกกับห้องเรียน; แสดง Badge “ไม่มีคะแนน” ภายในหน้าครู/นักเรียนที่อาจสับสนกับแบบฝึกหัด ห้ามใช้ “ส่งงาน”, “คะแนน”, “ผ่าน/ไม่ผ่าน”, “ความแม่นยำ” หรือคำที่สื่อการจัดอันดับกับ progress
- หน้าสร้างใช้ step indicator เดียวกับ assignment แต่เปลี่ยนเป็น “รายละเอียดและโจทย์ → ตั้งค่า → ตรวจสอบและสร้าง”; ส่วนเลือกโจทย์ใช้ disclosure “เพิ่มจากแฟ้มโจทย์ที่มีอยู่” และ “เลือกโจทย์รายข้อ” ร่วมกับ assignment และพับไว้เป็นค่าเริ่มต้น; ห้ามนำส่วนคะแนนรายข้อ เวลาทำ การจ่ายชุดโจทย์ หรือเงื่อนไขจบมาแสดง และ control ตั้งค่าต้องมี persisted behavior จริง ห้ามทำสวิตช์ตัวอย่างที่บันทึกไม่ได้
- การเลือกห้องใช้ `ClassroomPicker` ร่วมกับ assignment: flow ที่เข้าจากห้องเรียนตรึงห้องหลักและซ่อนห้องอื่นใต้ “มอบหมายให้ห้องเรียนอื่นด้วย” ในขั้นตั้งค่า ส่วน flow กลางเลือกหลายห้องในข้อมูลพื้นฐานได้; ต้องบอกเมื่อเลือกหลายห้องว่าแต่ละห้องมีคลังฝึกและความคืบหน้าแยกกัน ห้ามรวม roster หรือ progress ข้ามห้อง
- หลังเลือกโจทย์ให้แสดงทุกข้อใน compact scroll list ตาม pattern ของ assignment แต่ตัด preset คะแนน ช่องคะแนนรายข้อ และการจัดลำดับออก เหลือเลขลำดับสำหรับอ้างอิง ปุ่มดูตัวอย่าง และปุ่มเอาออก; ชื่อคลังฝึกและหัวข้อเลือกโจทย์ต้องแสดงเครื่องหมาย `*` ที่มองเห็นได้พร้อมข้อความสำหรับ screen reader
- หน้าตั้งค่าใช้แถว toggle ชุดเดียวกับ assignment เฉพาะการตรวจรายข้อ เฉลย รหัสผ่าน เครื่องคิดเลข กระดาษทด สับข้อ และสลับตัวเลือก; เมื่อเปิดรหัสผ่านต้องแสดง field บังคับทันที และกระดาษทดของคลังฝึกต้องไม่มี action แนบวิธีทำ
- นักเรียนต้องพบหน้ารอก่อนเข้ารายการโจทย์ หน้ารอใช้ภาษาชัดเจนว่าไม่สร้างรอบทำ ไม่จำกัดเวลา ไม่มีการส่งงานและไม่คิดคะแนน พร้อมแสดงคำชี้แจง จำนวนข้อ และปุ่มเข้าคลังฝึก โดยไม่โหลด question payload หรือสร้าง accepted-check event ก่อนนักเรียนเลือกข้อและกดตรวจ
- หน้า desktop ใช้หัวสูงประมาณ 72–88px, toolbar ค้นหา+แท็กไม่เกินประมาณ 96px, แถวโจทย์ 64–72px และแถว progress 44–48px; ใช้ `Card padding="md"` เฉพาะกลุ่มงานที่ต้องมีพื้นผิว ไม่ครอบทั้งหน้าหรือซ้อน Card
- search และ multi-tag AND อยู่ toolbar เดียว แท็กไม่เกินสองบรรทัดก่อนยุบเป็น “+N”; metadata ชื่อ/แท็ก/เคยตอบ/จำนวนครั้งอยู่แถวเดียวเมื่อพื้นที่พอ และเนื้อโจทย์ยาวเปิดรายละเอียดแยก
- หน้าความคืบหน้าใช้ table/list compact และลำดับ roster เป็นค่าเริ่มต้น ไม่เรียงจากจำนวนครั้ง ไม่ใช้กราฟ/สีแดงเขียว/กล่อง KPI สูงหลายใบ และใช้ถ้อยคำ “เคยตอบ X จาก Y ข้อ” แทนเปอร์เซ็นต์
- touch target ต้องอย่างน้อย 44×44px แม้พื้นผิวกะทัดรัด; ที่ 320px ห้ามล้นแนวนอน ที่ 1440×900 นักเรียนควรเห็นอย่างน้อย 5 แถวและครูเห็น roster อย่างน้อย 7 แถวเหนือ fold
- loading, empty, no-result, error และ permission-denied เป็นคนละ state; ห้ามเปลี่ยน authorization failure เป็นรายการว่าง และปุ่มย้อนกลับต้องคืน query/tag/page เดิมตามกติกา `lib/back-link.ts`
- navigation ทั้งหมดซ่อนเมื่อ server feature flag ปิด; mock/fixture ต้องมีป้ายตัวอย่างหรืออยู่หลัง local/Staging lab guard เท่านั้น

- ตาม UI-078 การ์ดแฟ้มย่อยใช้ทั้งกรอบเป็น click target เพื่อเปิดและเป็น sortable activator เพื่อสลับตำแหน่ง โดยเมาส์มี distance threshold, จอสัมผัสใช้ press delay เพื่อไม่ขัดการ scroll และคีย์บอร์ดใช้ Space + ลูกศร · เมนู ⋮ ต้องเหลือเพียง “ลบแฟ้มย่อย” และการลบต้องผ่าน `ConfirmDialog` ที่บอกผลต่อโจทย์ก่อนเสมอ
- ตาม UI-074 ป๊อปอัปตั้งค่าห้องเรียนไม่แสดงคำอธิบายซ้ำใต้หัว “ตั้งค่าห้องเรียน” หรือข้อความเตือนใต้ข้อมูล read-only; Card ประเภทห้องเรียนและรหัสห้องเรียนใช้ grid สองคอลัมน์กะทัดรัดที่สูงตามเนื้อหา โดยยังแสดงค่าทั้งสองครบและไม่เปลี่ยนให้แก้ไขได้
- ตาม UI-061 Topbar ของ app shell ใช้ความสูง `h-12` และโลโก้ KorKru แบบ horizontal ขนาด compact ให้รูปกวางกับชื่ออยู่บรรทัดเดียวกัน เพื่อลดพื้นที่เหนือเนื้อหา โดยคง hit area ของปุ่มเมนู การแจ้งเตือน ตัวสลับธีม และโปรไฟล์เดิม · mobile sidebar กับ backdrop ต้องเริ่มที่ `top-12` ตรงใต้ Topbar เสมอ ห้ามเหลือช่องว่างหรือซ้อนทับแถบหัว

- Mobile-first และใช้งานได้อย่างน้อยบน mobile/tablet/desktop

- **ปุ่มย้อนกลับหมายถึงหน้าที่ผู้ใช้เพิ่งมาจาก ไม่ใช่หน้าแม่ตามเส้นทาง URL** — หน้าเดียวเข้าถึงได้จากหลายที่ (เช่น หน้านำเข้าจาก Word เข้าได้ทั้งจากหน้าเลือกวิธีนำเข้าและจากปุ่มบนคลังโจทย์) หน้านั้นจึงตอบเองไม่ได้ว่าผู้ใช้มาจากไหน · ฝั่งที่ลิงก์เข้าไปต้องบอกด้วย `withBackHref(target, from)` แล้วปุ่มย้อนกลับอ่านคืนด้วย `resolveBackHref`/`backHrefFromSearchParams` (`lib/back-link.ts`)

  - **ค่าที่จำไว้มาจากเบราว์เซอร์ จึงไม่เชื่อ** `resolveBackHref` คืนเฉพาะ path ภายในแอป ปฏิเสธ URL ที่มี scheme และ `//host` / `/\host` ที่เบราว์เซอร์อ่านเป็น protocol-relative — ด้วยเหตุผลเดียวกับที่ `safeQuestionsRedirect` มีอยู่ ปุ่มย้อนกลับที่เชื่อค่าใน URL คือ open redirect
  - หน้าที่เป็นปลายทางของเมนูด้านซ้ายไม่ต้องมีปุ่มย้อนกลับ (เช่น `/questions/new`, `/questions/import`) เพราะไม่ได้มีหน้าก่อนหน้าที่แน่นอน
- อย่าซ่อน authorization error ด้วย empty state
- Form ต้องมี label ที่อ่านได้ด้วย assistive technology

## ข้อมูลจริงกับต้นแบบ

- Mock/prototype ต้องมีป้ายชัดหรือซ่อนจาก production navigation
- ห้ามใช้เลขสุ่มเป็น analytics โดยไม่ระบุว่าเป็นข้อมูลตัวอย่าง

## Content principles

- ยืนยันการทำงานด้วยข้อความที่ตรงกับผลจริง
- อธิบายการสุ่มและการตรวจคะแนนให้ครูเข้าใจและตรวจสอบได้
- บอกชัดว่าส่วนใดตรวจอัตโนมัติและส่วนใดต้องให้ครูตรวจ
- หลีกเลี่ยงข้อความที่ทำให้ครูเชื่อว่าระบบตัดสินนักเรียนแทนครู
- ข้อมูลสุขภาพ ครอบครัว และความเครียดไม่ควรปรากฏใน dashboard รวมโดยไม่จำเป็น

### พื้นที่เรียนรู้ของนักเรียนแบบรวม

- เมนู **พื้นที่เรียนรู้ของฉัน** รวมหน้าหลัก ห้องเรียน และสรุปงานของนักเรียนไว้ใน `/dashboard` เริ่มด้วยห้องเรียน ตามด้วยสรุปงานและประกาศ ปฏิทินย่อใช้พื้นที่ด้านข้างเมื่อจอกว้างพอ
- สรุปจำนวนงานอยู่แถวเดียวกับหัวข้อด้วย Badge ขนาดเล็ก และยอมให้ขึ้นบรรทัดใหม่บนจอแคบ รายการงานใช้ Card สั้น มีแถบสีและไอคอนจาก metadata ห้องเรียนที่มอบหมายงานจริง โดยอ่านจาก ID ห้องที่นักเรียนเข้าถึงได้ ประวัติการสอบเปิดดูผ่าน disclosure เพื่อประหยัดพื้นที่แนวตั้ง
- Grid ห้องเรียนและตำแหน่งฟอร์มเข้าร่วมต้องอิงความกว้าง container ของเนื้อหา แทนความกว้าง viewport อย่างเดียว เพื่อไม่ให้ sidebar กับปฏิทินบีบ Card และข้อมูลจนอ่านไม่ได้

### ห้องเรียนและงานของนักเรียนแบบกระชับ

- หัวห้องเรียนของนักเรียนต้องอ่านสีปก ไอคอน และลายตกแต่งที่ครูเลือกผ่าน helper และ `ClassroomCoverPattern` ชุดเดียวกัน ทั้งห้องวิชาและโฮมรูมใช้ `StudentClassroomHeader`; รักษาชื่อห้องและครูให้ชัดบนมือถือด้วยข้อความที่ขึ้นบรรทัดได้
- ตัวกรองสถานะใช้ ToggleGroup ต่อเนื่อง ประเภทงานใช้ Select และอยู่ในแถบเดียวเมื่อพื้นที่พอ หลีกเลี่ยงกรอบสถิติที่ซ้ำกับจำนวนในตัวกรอง ใช้ container query จัด grid ตามพื้นที่เนื้อหาจริง
- การ์ดงานนักเรียนกดได้ทั้งกรอบ ใช้ Link + Card พร้อม focus ring และชื่อ action ตามสถานะ ลดปุ่มเริ่มทำที่ซ้ำกับพื้นที่การ์ด เหลือชื่อ ข้อมูลโจทย์ เวลา เกณฑ์ และสถานะในแถวสั้น ใช้สีและไอคอนของธีมห้องเป็นจุดนำสายตา; คะแนนที่ครูซ่อนหรือยังไม่ถึงเวลาแสดงต้องไม่ปรากฏ รวมข้อความผ่าน/ไม่ผ่านที่อนุมานจากคะแนน

### ข้อมูลส่วนตัวนักเรียน

- หน้าโปรไฟล์นักเรียนไม่มี navigation card ซ้ำกับ sidebar หลัก ขอบซ้ายใช้ padding ของ main และบน desktop ขอบขวาใช้ notification anchor ของ shell; จอเล็กใช้ความกว้างเต็ม ช่องข้อมูลต้องอิง container query เพื่อไม่บีบฟอร์มเมื่อเปิด sidebar
- หัวข้อข้อมูลตัวตน การศึกษา และติดต่อใช้ป้าย “ดูได้: …” แทนคำอธิบายยาว ป้ายเป็นปุ่มเปิด HoverCard ที่ใช้ได้ทั้ง hover, keyboard และแตะ และรายละเอียดต้องตรงกับข้อมูลที่ server เปิดเผยจริง โดยไม่อ้างว่าทุกช่องในส่วนการศึกษาเปิดให้ครูประจำวิชาทั้งหมด
- การจัดรูปใช้ Dialog พร้อมกรอบลาก/ลูกศร ปุ่มซูมและเริ่มใหม่ ใช้ “ใช้รูปนี้” สำหรับตัวอย่างในหน้า ไม่แสดงข้อความว่าบันทึกถาวร เมื่อขอยกเลิก/คลิกนอก/Escape ใช้ ConfirmDialog ที่อยู่ใน context ของ Dialog เดิมแต่แยก popup เพื่อคงร่างและคืน focus ได้ถูกต้อง

### พื้นที่เรียนรู้และประกาศที่รับทราบ

- คอลัมน์เนื้อหาหน้ารวมใช้แนวกระดิ่งจาก shell และวางปฏิทินข้างนอกแนวนั้น ปฏิทิน sticky ภายใน main; จอแคบกลับเป็นคอลัมน์เดียว Grid ห้องเรียนรวม Homeroom ก่อนวิชาและใช้ 3 คอลัมน์เมื่อ container พอ งานในห้องเรียนใช้หลักเดียวกันและหัวหมวดมีพื้นสี/ไอคอน/ตัวหนาที่เด่นกว่าข้อมูลรอง
- สรุปงานใช้ Card ครอบจำนวน ตัวเรียง และรายการเลื่อนภายใน ไม่ใส่หัวข้อซ้ำ “งานที่ต้องทำ” ประวัติคะแนนเป็น disclosure สูงจำกัด เปิด/ปิดและ click-away/Escape ได้; ขนาดหัวข้อห้องเรียน สรุปงาน และประกาศล่าสุดต้องเท่ากัน ประกาศล่าสุดมีธีมของห้องที่ประกาศ
- Popup ประกาศใช้ธีมห้อง ชื่อวิชา ผู้ประกาศ เวลาสร้างและเวลาที่แจ้งซ้ำจริง ไฟล์/ลิงก์ใช้ renderer เดิม รับทราบสำเร็จแล้วค่อยเปลี่ยนคิว Error ต้องคงประกาศไว้ รูปขยายเป็น popup อ่านอย่างเดียว nested ในประกาศ เมื่อพักคิวไม่สร้าง receipt
- คำว่า “รับทราบแล้ว” ใช้กับ explicit receipt เท่านั้น ไม่เปลี่ยนชื่อข้อมูลการแสดงบนหน้าจอเป็นการรับทราบ ไอคอน BellRing แจ้งใหม่ต้องยืนยันผลว่าทุกคนต้องรับทราบรอบใหม่ และสถานะ/คำอธิบายต้องใช้ตัวเลขของรอบปัจจุบัน

### เครื่องมือระหว่างทำข้อสอบและแบบฝึกหัด

- แถบเครื่องมือใช้ Card ขนาดกะทัดรัดและ sticky ใน scrollport จริง สถานะตัดบรรทัดได้ ปุ่มหลักเป็นไอคอนบนจอแคบพร้อม accessible label และคงเป้าสัมผัสอย่างน้อย 44px; การเปลี่ยนข้อเผื่อความสูงแถบและ padding ของ scrollport เพื่อให้หัวโจทย์อยู่ใต้แถบ
- แผงขวาแบ่งเป็น Card เวลา/ความคืบหน้าและ Card เลขข้อ/คำอธิบาย/ส่งคำตอบ กรอบสูงพอดีเนื้อหาจนถึงขีดจำกัด ให้เฉพาะเลขข้อเลื่อนเมื่อมีข้อเยอะ โดยปุ่มส่งอยู่ท้ายแผง สถานะสีต้องมีคำอธิบายและชื่อเข้าถึงได้ ไม่ใช้การขยายปุ่มที่ทำให้ grid กระโดด
- ใช้สี primary กับข้อในหน้าปัจจุบัน, success กับข้อที่ตอบ/ตรวจถูก, destructive กับตรวจยังไม่ถูก และ flag กับปักธง ใช้ timer role พร้อม aria-live off เพื่อไม่ขัดการอ่านโจทย์ทุกวินาที โหมดโฟกัสคงเครื่องมืออยู่นอกพื้นที่เลื่อนของโจทย์

### ผลคะแนนและลายน้ำเฉลย — 14 ตุลาคม 2026

- `SubmissionScoreSummary` ใช้ Card กระชับ เปอร์เซ็นต์เป็น badge ข้างคะแนน/ผลผ่านและจำนวนข้อ วันเวลาขึ้นบรรทัดใหม่ใน container แคบ ไม่ใช้วงคะแนนใหญ่กับช่องว่างแนวตั้งหลายชั้น
- ตัวเลือกเฉลยบอก “คำตอบของคุณ” แม้ตรงกับเฉลย สีไม่เป็นตัวบอกสถานะเพียงอย่างเดียว คำตอบว่างใช้ “ไม่ได้ตอบข้อนี้” และตัวเลือกอ้างอิง index ของรอบสอบ
- ลายน้ำเฉลยเป็นข้อมูลตัวตนสามบรรทัดซ้ำทั่ว viewport ตามการเลื่อนหน้าและเหนือป๊อปอัป ไม่รับ pointer ไม่เข้าสู่ accessibility tree ไม่มีปุ่มปิด ใช้สี semantic โปร่งใสเพื่อให้อ่านโจทย์ได้ วันที่อ้างอิง server และ monotonic elapsed time
