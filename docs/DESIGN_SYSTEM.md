# Brand, language และ UI rules

## สถานะเปิดห้องเรียน — 18 ตุลาคม 2026

ระหว่างตรวจสิทธิ์เข้าห้องใช้ Skeleton และข้อความ “กำลังเปิดห้องเรียน…” แทนเมนูรายการห้องเรียนทั่วไป หลังตรวจสิทธิ์แล้วต้องแสดงชื่อ สี และเมนูของห้องจริงได้ก่อนข้อมูลส่วนอื่น โดยไม่แสดงจำนวนนักเรียน/คะแนนปลอมเป็นศูนย์ สถานะโหลดใช้ Card และ Skeleton มาตรฐานกะทัดรัด ไม่ใช้ตัวหมุนกลางพื้นที่ว่างสูงอีกชั้น การสลับแท็บแสดงสถานะรอเฉพาะเนื้อหาและคงเมนู/บริบทห้องเดิม

## หน้าตรวจให้คะแนน — 18 ตุลาคม 2026

ตัวกรองชั้น/ห้องและเรียงตามในหน้าตรวจรายข้อ/ตารางรายคนใช้ FieldLabel แยกจาก NativeSelect ค่าที่เลือกเป็น text-foreground และ font-medium ไม่รับสี muted จากป้ายกำกับ ปุ่มเรียงลำดับใช้ ArrowUpNarrowWide สำหรับน้อยไปมาก / ArrowDownWideNarrow สำหรับมากไปน้อยเหมือนหน้า “ศักยภาพผู้เรียน” พร้อมข้อความทิศทางและ aria-label/title บอกการสลับ ใช้ Button sm คู่กับ select h-7 คงพื้นที่กด 44px บน coarse pointer กลุ่มตัวกรองต้องได้ความกว้างจริงเมื่อเป็น inline-size container แต่ละ Field จำกัด max-w-full และพับแถวได้โดยไม่บีบ label หรือทำให้หน้าล้น

ปุ่มกลับตารางรายข้อ/รายคนอยู่เหนือกรอบสีม่วง ส่วนตั้งค่าปุ่มคะแนนเร็ว ให้คะแนนเท่ากันทั้งข้อ (เฉพาะรายข้อ) และลบร่างอยู่แถวเครื่องมือเดียวกันใต้กรอบ ลบร่างใช้ outline พร้อมไอคอนและเปิดคำยืนยันก่อนลบ สถานะร่างที่ยังไม่ส่งนักเรียนใช้ Badge สี statusWarning พร้อมข้อความและไอคอนในกรอบสีม่วง อัปเดตจากร่างของหน้าที่กำลังตรวจและไม่ทำให้ header ภาพรวมต้องพึ่ง provider การตรวจคะแนน

ตั้งค่าปุ่มคะแนนเร็วใช้ 6 ช่อง กางแผงกว้างเต็มเนื้อหาและจัด 2/3/6 คอลัมน์ตามความกว้าง container เพื่ออ่าน 100 และ 87.5 ได้ครบ Label แต่ละช่องอยู่บรรทัดเดียว แต่ละ disclosure มี root แยกและให้แผงกางเป็น full-width order-last ใน toolbar จึงคงตำแหน่งเครื่องมือเมื่อเปิด/ปิด และสลับส่วนที่กางได้ในคลิกเดียว บนจอแคบพับแถวเครื่องมือและเพิ่มความสูงป้ายเท่าข้อความจริง ไม่ตัดข้อความหรือเพิ่มขนาดปุ่มทั้งเว็บ

หน้าตรวจรายข้อใช้กรอบโจทย์โทนฟ้าอมเขียว tint-2 บนพื้น Card ทึบพร้อมขอบและเงาบาง ชื่อ/เลขข้อ ประเภท และเครื่องมืออยู่ในกรอบเดียวกันโดยไม่ซ้ำหัวข้อด้านนอก กรอบติดด้านบนของ main ที่เลื่อนจริงตลอดรายการคำตอบ ไม่เพิ่มความสูง topbar ซ้ำ และอยู่ใต้ชั้นเมนู/ป๊อปอัป ชดเชย padding 6 ของ shell ด้วย sticky -top-4 เพื่อเหลือช่องว่าง 2 หน่วยใต้ topbar

จำกัดความสูงกรอบประมาณ 40% ของ --app-height/visual viewport โดยไม่กำหนดความสูงขั้นต่ำ โจทย์ยาว ภาพ และสูตรเลื่อนอ่านใน region ที่มีชื่อ/คีย์บอร์ด/วงโฟกัสได้ หัวกรอบคงอยู่เมื่อเลื่อนเนื้อหาและยังพับซ่อนได้ ชื่อยาวแสดงไม่เกินสองบรรทัดโดยคงข้อความเต็มสำหรับ accessibility และ title การตั้งสัดส่วนคะแนนอยู่นอกส่วนที่ติดตามเพื่อไม่บังคำตอบ ช่องคะแนน ปุ่ม และลิงก์/กรอบไฟล์ในรายการมี scroll margin ด้านบนและล่างเฉพาะหน้ารายข้อ ป้องกันโฟกัสถูกโจทย์หรือแถบบันทึกบัง

ส่วนหัวใช้ Card สี primary อ่อนหนึ่งกรอบพร้อมกวาง KorKru ชื่อหน้า/งาน และสถิติส่งแล้ว คะแนนเฉลี่ย กำลังทำในบรรทัดเล็ก ไม่แยกสาม Card สูง แท็บรายข้อ/รายคนและตารางตามต่อทันที ใช้ปุ่ม `sm`/`icon-sm` และไอคอนขนาดปกติ โดยขยาย touch target เฉพาะ coarse pointer

รายข้อแสดงเลข/ปุ่มตา คำใบ้ชื่อกับ excerpt ตัวอักษรเท่านั้น มีคอลัมน์ “ประเภทข้อสอบ” ถัดจากโจทย์เป็นข้อความหนึ่งบรรทัด ตามด้วยสถานะสั้นและปุ่ม “ตรวจ/ดูคำตอบ” ไม่มีปุ่มส่งออก CSV บนกรอบสรุป รายละเอียดแสดงโจทย์พับได้ คำตอบ รูปวิธีทำ และเอกสารทันทีโดยไม่วางปุ่มเปิดเพิ่มก่อนตรวจ คะแนนคำตอบ/วิธีทำแยกช่อง มี 0 กับ “ยังไม่ตรวจ” สำหรับส่วนที่ pending ไม่ใช้ช่องว่างเป็นคะแนนศูนย์ การตั้งส่วนแบ่งวางเป็น disclosure กะทัดรัด ไม่เพิ่มกรอบสูงซ้อน ปุ่ม/หัวข้อที่เกี่ยวข้องอยู่แถวเดียวเมื่อมีพื้นที่ และจอแคบต้องไม่ตัดช่องคะแนนหรือปุ่มบันทึก

ตารางรายข้อสงวนความกว้างให้สถานะหลายป้ายพับแถวได้พอดีแทนการเรียงลงมาสูงเกินจำเป็น จอแคบใช้การเลื่อนภายในตารางโดยไม่ให้ทั้งหน้าล้นแนวนอน

หน้าตรวจคำตอบใช้ปุ่ม “บันทึกร่าง” และ “ส่งคะแนน” ขนาด sm ในแถบล่างที่เลื่อนติดขอบ ร่วมกับการแบ่งหน้าหรือเปลี่ยนคน แถวคำตอบไม่มีปุ่มบันทึกแยก ป๊อปอัป “ยังมีคะแนนที่ไม่ได้บันทึก” ใช้ข้อความสั้น จำนวนคำตอบที่แก้ และตัวเลือก “กลับไปตรวจต่อ”/“ออกโดยไม่บันทึก” โดยไม่ทิ้งร่างเมื่อคลิกฉากหลังหรือ Escape ระหว่างบันทึกล็อกช่องคะแนนและการเปลี่ยนหน้า สถานะข้อคำนวณที่รอรูปวิธีทำใช้ “รอตรวจวิธีทำ” และแสดงเรื่องสัดส่วนเฉพาะส่วนตั้งค่าที่เกี่ยวข้อง

## ป๊อปอัปแก้เฉลยและโมฆะ — 18 ตุลาคม 2026

ในหน้าตรวจรายข้อ แสดง “แก้เฉลย” เฉพาะโจทย์ที่มีส่วนตรวจอัตโนมัติ ซ่อนสำหรับบรรยาย ส่งไฟล์งาน เติมช่องตอบอิสระทั้งหมด และโจทย์ผสมที่ตรวจมือทั้งหมด โดยคงปุ่มโมฆะไว้ ข้อผสมที่มีเฉลยอัตโนมัติ, ถูก–ผิดพร้อมเหตุผล และตัวเลขแนบวิธีทำยังแสดงปุ่ม ไม่เพิ่มข้อความหรือพื้นที่ทดแทนปุ่มที่ซ่อน

ปุ่มแก้เฉลย/โมฆะ/ซ่อนหรือแสดงโจทย์ในหน้าตรวจอยู่แถวเดียวกับหัวข้อเมื่อพื้นที่พอ ใช้ Button ขนาด xs ให้ตัวหนังสือและไอคอนสัมพันธ์กับ metadata ส่วนปุ่มเปลี่ยนข้อ/คนด้านบนและล่างใช้ sm ทั้งสถานะกดได้และ disabled คงเป้าสัมผัส coarse pointer อย่างน้อย 44px ไม่แก้ขนาด Button ทั้งเว็บหรือปุ่มยืนยันใน Dialog เพื่อย่อเครื่องมือเฉพาะส่วนนี้ Dialog ความกว้าง lg, gap 3, ข้อความสั้นกับผลกระทบหนึ่งบรรทัด บนมือถือเรียงปุ่มได้โดยไม่ล้นจอ

คำเตือน “แก้เฉลยและตรวจคะแนนย้อนหลัง?” บอกผลทุกงานที่ใช้โจทย์และมีสิทธิ์จัดการ พร้อม checkbox “ฉันรับทราบผลกระทบต่อคะแนนนักเรียนแล้ว” ก่อนเปิดปุ่ม “ยืนยันแก้เฉลยและตรวจคะแนนใหม่” โมฆะถามเหตุผลและรับทราบคะแนน/คะแนนเต็ม ใช้ destructive เฉพาะโมฆะ ข้อโมฆะแสดงป้ายแทน score editor ไม่แสดงถูก/ผิด ทุกข้อไม่คิดคะแนนแสดงข้อความสั้นและเปอร์เซ็นต์ขีด ไม่ใช้ 0% หรือผ่าน

คลิกนอก/Escape เปิดคำยืนยันปิดแยกชั้น กลับมาแล้วคงร่าง checkbox และ focus; ปุ่มกลับออกไม่เปลี่ยนคะแนน ระหว่างโมฆะป้องกันปิด/กดซ้ำ ทิ้งผลเตรียมคำยืนยันของข้อเก่าเมื่อเปลี่ยนข้อ การเชื่อมต่อขัดข้องต้องคืนสถานะปุ่มให้ลองใหม่ได้

## เมนูบริบทหน้าตรวจให้คะแนน — 18 ตุลาคม 2026

หน้า `/assignments/[id]/results` ใช้ AssignmentContextNavigation เดียวกับหน้าภาพรวมและตั้งค่างาน แสดงกรอบชื่องาน สถานะ ประเภท และคำสั่งเดิมในแถบข้างของ shell โดยไฮไลต์ “ตรวจให้คะแนน” พร้อม `aria-current="page"` แทนเมนูหลัก จำนวนชิ้นรอตรวจนับ submission ที่มีคำตอบ `is_correct = null` จากข้อมูลรอบที่หน้าผลคะแนนใช้อยู่ รองรับแถบย่อและเมนูมือถือเดิม ไม่เพิ่มแถบหรือระยะแนวตั้งในเนื้อหาผลคะแนน

## กรอบเลือกวิธีนำเข้าโจทย์ — 18 ตุลาคม 2026 (Staging ผ่าน รอปล่อย Production · PR #60)

fixture วัดกรอบใหม่ 113.5px ที่ 320/390/768/1440px เทียบเดิมประมาณ 123–143px ไม่มี fixed card height หรือตัดคำ ชื่อและนามสกุลไฟล์ขึ้นบรรทัดได้ตามพื้นที่ ขั้นตอนนำเข้า Word, native chooser, ตรวจซ้ำและ batch import ของ KorKru ใช้ตัวเดิม

## Signup and account trust — 17 October 2026 (prepared)

หน้า login/signup ใช้ `BrandLogo size="large"` ตามคำปรับล่าสุด ให้กวางเป็นจุดเด่นหลักด้วย `h-18 sm:h-20` และลดชื่อ KorKru เป็น `text-2xl` เท่าหัวข้อหน้า คงข้อความรองและ gap เดิม ขนาดปกติ/compact ยังใช้กับส่วนอื่นตามเดิม

ตัวเลือกบทบาทสมัครสมาชิกใช้ ToggleGroup แบบปุ่มมีขอบสองช่องเท่ากัน สูงอย่างน้อย 52px พร้อมพื้นอ่อน/เงาบางและวงกลมสถานะ เมื่อเลือกใช้กรอบม่วง พื้นม่วงอ่อนและเครื่องหมายถูก มี hover/pressed/focus ชัดเจน ไม่เพิ่มคำอธิบายหรือเลือกบทบาทไว้ล่วงหน้า ไอคอนตกแต่งซ่อนเมื่อ container แคบกว่า 280px เพื่อรักษาชื่อบทบาทให้อ่านได้ ใช้ aria-pressed และการควบคุมคีย์บอร์ดเดิม ไม่มี radio/checkbox ซ้อนในปุ่ม

ตาม UI-020/UI-084/UI-085/UI-086/UI-087/UI-088/UI-089/UI-090/UI-091/UI-092/UI-093/UI-094 หน้าสร้างงานรวมการเลือกโจทย์ คะแนนรายข้อ จำนวนข้อต่อหน้า และเวลาทำใน `Card` เดียวชื่อ “โจทย์ คะแนน และเวลา” โดยเรียงตาม dependency ของงานจริง: เลือกโจทย์ → ตั้งคะแนนรายข้อ → ตั้งเวลา และไม่เสนอการสร้างแฟ้มโจทย์ระหว่างมอบหมายงาน; ครูจัดแฟ้มจากหน้าคลังแฟ้มก่อน แล้วเลือกแฟ้มหรือโจทย์ที่มีอยู่มาใช้ในงาน ส่วน “คะแนนเต็มที่แสดงผล” ต้องอยู่ใน `Card` “ชุดโจทย์ที่นักเรียนได้รับ” เดียวกัน และเมื่อสุ่มต้องวางคู่กับจำนวนข้อที่ให้นักเรียนทำในแถวเดียวกันตั้งแต่จอ `sm` ขึ้นไปโดยไม่ใช้กรอบซ้อน และหัวข้อ “เลือกโจทย์” ต้องมี `*` สี `destructive` พร้อมข้อความ “จำเป็น” สำหรับ screen reader เพราะไม่อนุญาตให้สร้างงานที่ไม่มีโจทย์ ส่วน “เพิ่มจากแฟ้มโจทย์ที่มีอยู่” และ “เลือกโจทย์รายข้อ” ต้องพับเมื่อคลิกนอกกรอบ แต่ไม่พับจาก interaction ภายในหรือ dialog ตัวอย่าง และต้องสลับกรอบที่เปิดได้ในคลิกเดียว ส่วน “คะแนนแต่ละข้อ” ต้องมีปุ่ม “ดูโจทย์ทั้งหมด” เพื่อเปิดตัวอย่างครบตามลำดับปัจจุบันในหน้าต่างเดียว มีคำสั่งเล็ก “ทุกข้อ 1 คะแนน” และ “คะแนนตามข้อย่อย” สำหรับปรับคะแนนโจทย์ที่เลือกทั้งชุด; คำสั่งล่าสุดที่ใช้สำเร็จต้องคงพื้น `primary` และเครื่องหมายถูกพร้อม `aria-pressed`/live status จนกว่าจะเปลี่ยนคะแนนรายข้อหรือสมาชิกโจทย์ เพื่อยืนยันผลโดยไม่ทำให้ครูเข้าใจผิด และใช้การกดค้างลากบริเวณหมายเลข/ชื่อโจทย์เพื่อเรียงแทนลูกศรขึ้นลง โดยคงช่องเลขที่พิมพ์ตำแหน่งแล้วกด Enter ได้และไม่ให้ gesture ลากครอบปุ่มดูตัวอย่าง ช่องคะแนน หรือปุ่มลบ; ภายใน dialog ดูทั้งหมด เลขข้อของแต่ละการ์ดเป็นดรอปดาวน์สำหรับย้ายตรงไปยังตำแหน่งปลายทาง ต้องแสดงคำอธิบาย “เลือกเพื่อย้ายโจทย์ไปยังลำดับที่ต้องการ” เมื่อวางเมาส์หรือโฟกัสด้วยแป้นพิมพ์ และต้องอัปเดตลำดับจริงชุดเดียวกับรายการคะแนนโดยไม่โหลดเนื้อหาโจทย์ซ้ำ ส่วน preview จากแฟ้มยังเป็น read-only ไม่มีตัวควบคุมลำดับ เมื่อเลือกสุ่มให้ปิดช่อง/คำสั่งคะแนนรายข้อ แสดงทุกข้อเป็น 1 คะแนน และอธิบายว่าคะแนนดิบเท่ากับจำนวนข้อที่ตอบถูก ส่วนหน้าแก้ไขงานใช้กติกาเดียวกันแต่ยังรวมคะแนนรายข้อกับคะแนนเต็มแสดงผลไว้ใน `Card` “ตั้งค่าคะแนน” เดิม มีหัวข้อย่อยและ `Separator` แบ่งส่วน ไม่ใช้กรอบซ้อนหรือซ่อนความต่างของคะแนนจริงกับคะแนนที่แสดง; ## Style presets

สไตล์ทั้งเว็บคุมด้วย CSS variable ใน `app/globals.css` ไม่ใช่ class ในแต่ละไฟล์ แกนที่หมุนได้:

- `--primary`, `--success`, `--warning`, `--flag`, `--destructive` และ token สีอื่น — ความหมาย ไม่ใช่การตกแต่ง
- `--radius` — ความมนทั้งเว็บ (Tailwind คำนวณ `rounded-*` จากค่านี้)
- `--spacing` — ความโปร่ง/แน่น (Tailwind คำนวณ `p-*`, `gap-*`, `m-*` จากค่านี้)
- `--elevation-sm|md|lg|xl` — เงา

เปลี่ยนสไตล์ทั้งเว็บด้วยการใส่ `data-style` บน `<html>` ใน `app/layout.tsx`:

```
<html lang="th" data-style="warm">
```

preset ที่มีให้:

| preset | ลักษณะ |
| --- | --- |
| `soft` | มน โปร่ง เงานุ่มฟุ้ง |
| `sharp` | เหลี่ยม แน่น ไม่มีเงา ใช้เส้นขอบแทน |
| `warm` | พื้นครีม primary terracotta |
| `minimal` | เกือบขาวดำ น้ำหนักตัวอักษรเบา เส้นขอบบาง |
| `playful` | หนา มนมาก เงาทึบแบบ offset |

ไม่ใส่ = ค่าเริ่มต้น (indigo, มนปานกลาง) — ปัจจุบันแอปตั้ง `data-style="playful"` ไว้

ทุก preset ผ่าน WCAG AA (ตัวอักษรบนปุ่ม primary ≥ 4.5:1) ทั้งโหมดสว่างและมืด ถ้าเพิ่ม preset ใหม่ต้องวัด contrast ก่อนใช้

สีแบ่งเป็น 2 ชนิด — อย่าสลับกัน:

- **สีที่มีความหมาย** (`--primary`, `--success`, `--warning`, `--flag`, `--destructive`) เปลี่ยนค่าได้ แต่ห้ามเปลี่ยนว่าอะไรหมายถึงอะไร
- **ฉากหลังทึบ** (`--overlay`) ใช้กับ modal และภาพที่ต้องหรี่ — preset ปรับความเข้ม/โทนได้
- **พื้นมืดกลับสี** (`--surface-inverse` + `-foreground` / `-muted` / `-border`) ใช้กับแบนเนอร์ การ์ดหัวเรื่อง และ chrome ของ super-admin ที่ตั้งใจให้มืดทั้งสองโหมด — preset ปรับโทนได้
- **สีตกแต่ง** (`--tint-1` … `--tint-4`) ใช้แยกแยะรายการเฉยๆ เช่น stat card, ไอคอน, ป้ายหมวดหมู่ — สลับได้อิสระ preset ควรปรับให้เข้ากับ primary ของตัวเอง (เช่น `playful` ใช้ primary ม่วงแดง จึงดัน tint-1 ไปทางน้ำเงินไม่ให้ดูเหมือนพลาด)

preset ปรับได้ 5 แกน: สี, `--radius`, `--spacing`, `--elevation-*` และ typography (`--font-weight-*`, `--text-*`, `--tracking-*`) — Tailwind v4 คำนวณ utility จากตัวแปรเหล่านี้อยู่แล้ว จึงไม่ต้องแก้ component

ดูผลของแต่ละ preset บนคอมโพเนนต์จริงได้ที่ `/style-preview` (เปิดเฉพาะตอน `next dev` — production จะ 404)

เพิ่ม preset ใหม่โดยคัดลอกบล็อก `[data-style="..."]` ท้าย `globals.css` แล้วแก้ค่า ไม่ต้องแก้ไฟล์อื่น

**preset เปลี่ยนได้เฉพาะการตกแต่ง** ห้ามเปลี่ยนว่าสีไหนหมายถึงอะไร — เขียวยังคงหมายถึงสำเร็จ ส้มยังคงหมายถึงโจทย์ที่ถูกรายงาน ในทุก preset

สิ่งที่ยังเป็นค่าคงที่โดยตั้งใจ: แถบสเกลเปอร์เซ็นไทล์ — เป็นเนื้อหาและความหมาย ไม่ใช่การตกแต่ง preset จึงไม่ควรเปลี่ยน

ชุดสีปกห้องเรียน (`COVER_PRESETS` ใน `app/(app)/classrooms/_components/classroom-meta.ts`) เคยเป็น hex ไล่เฉดคงที่ แต่เปลี่ยนมาเป็นสีพื้นเรียบที่อ้าง token ตามที่เจ้าของผลิตภัณฑ์สั่ง จึงเปลี่ยนตาม preset และโหมดสว่าง/มืดด้วย ผลที่ตามมาคือการสลับ preset จะเปลี่ยนโทนสีปกที่ครูเลือกไว้ — แลกกับการได้ contrast ที่ผ่าน AA ทั้งสองโหมดโดยไม่ต้องดูแลชุด hex เอง

ภาพปกห้องเรียนใช้ `ClassroomCoverPattern` และ stable key จาก `lib/classroom-cover-patterns.ts` จำนวน 11 แบบ ทุกรูปทรงใช้ `currentColor` สีเดียวหลายระดับ opacity โดยไม่มี hex หรือ palette ฝังในภาพ จึงเปลี่ยนตาม `COVER_PRESETS`, preset และ light/dark mode ได้ · ตาม UI-057 พื้นที่ภาพอยู่ในครึ่งสามเหลี่ยมขวาบนเหนือเส้นทแยงจากซ้ายบนไปขวาล่าง ส่วนซ้ายล่างต้องสงบเพื่อรองรับชื่อห้อง ภาพใช้รูปทรงทึบโปร่งแสงร่วมกับเส้นรายละเอียดได้ ไม่จำกัดเป็น line art และใช้ `placement="end"` กับ `meet` เพื่อรักษาตำแหน่งโดยไม่ crop · ชุดนี้เป็นองค์ประกอบต้นฉบับของ KorKru ไม่คัดลอกหรือเลียนแบบชุดปกของ Google Classroom และลายกวางต้องอิงเครื่องหมายแบรนด์ที่อนุมัติใน `public/brand/deer-mark.svg` ไม่ใช้กวางสต็อก · ตาม UI-083 ส่วนเลือกภาพปกแสดงหัวข้อ “ภาพปกห้องเรียน” แล้วตามด้วยตัวเลือกทันที ไม่แสดงข้อความอธิบายงานออกแบบหรือการเปลี่ยนสีตามธีม · ตัวเลือกปกต้องแสดงภาพอย่างเดียวโดยไม่มีชื่อวิชาหรือคำอธิบายชี้นำทั้ง caption และ tooltip ผู้ใช้เป็นผู้กำหนดความหมายเอง ส่วน accessible name ใช้เลขลำดับกลาง เช่น “ภาพปกแบบที่ 1” · หน้าเริ่มสร้างห้องต้องสุ่ม stable key หนึ่งครั้งต่อฟอร์มและคงค่านั้นจนบันทึก ไม่สุ่มใหม่จาก re-render; การทำสำเนาคงปกต้นฉบับและสุ่มเฉพาะห้องเก่าที่ไม่มี key · ห้องเก่าหรือ key ที่ไม่รู้จักในจุดแสดงผลยังใช้ลาย `classroom` และต้องไม่ render markup/URL ที่มาจาก metadata โดยตรง

ตัวอักษรบนหน้าปกต้องผสมกับ `--foreground` ด้วย `color-mix` เสมอ ห้ามวางสี token เต็มความเข้มบนพื้น `/10` เพราะวัดจริงแล้วได้เพียง 1.9–4.5:1 ซึ่งตกเกณฑ์ AA เกือบทุกสี

องค์ประกอบใหม่ต้องใช้ token และ primitive ใน `components/ui/` ไม่เขียน class สีหรือทรงเอง — `npm run lint:tokens` ตรวจข้อนี้ 4 อย่าง:

| ตรวจอะไร | ใช้อะไรแทน |
| --- | --- |
| สี palette ดิบ (`bg-gray-100`, `text-white`, `bg-black/50`) | token ใน `globals.css` |
| การ์ดเขียนมือ | `<Card>` |
| form control เขียนมือ | `<Input>` / `<Textarea>` / `<NativeSelect>` |
| ปุ่มเขียนมือ | `<Button>` / `<IconButton>` |
| class ผิดรูป (`bg-primary/10/40`) | — Tailwind ทิ้งเงียบๆ ต้องแก้ |

`<NativeSelect>` คือ `<select>` ธรรมดาที่จัดสไตล์ให้ตรงกับ `<Input>` ส่วน `<Select>` (base-ui) เป็น dropdown แบบเต็มรูปแบบสำหรับกรณีที่ต้องการมากกว่านั้น

## UI behavior

### คลังฝึกแบบกะทัดรัดและไม่สื่อเป็นคะแนน

- ใช้คำว่า **“คลังฝึก”** ในทางเข้าสร้างภายในห้องเรียน และไม่วางทางเข้าคลังฝึกใน sidebar หลัก เพราะคลังทุกชุดต้องผูกกับห้องเรียน; แสดง Badge “ไม่มีคะแนน” ภายในหน้าครู/นักเรียนที่อาจสับสนกับแบบฝึกหัด ห้ามใช้ “ส่งงาน”, “คะแนน”, “ผ่าน/ไม่ผ่าน”, “ความแม่นยำ” หรือคำที่สื่อการจัดอันดับกับ progress
- หน้าสร้างใช้ step indicator เดียวกับ assignment แต่เปลี่ยนเป็น “รายละเอียดและโจทย์ → ตั้งค่า → ตรวจสอบและสร้าง”; ส่วนเลือกโจทย์ใช้ disclosure “เพิ่มจากแฟ้มโจทย์ที่มีอยู่” และ “เลือกโจทย์รายข้อ” ร่วมกับ assignment และพับไว้เป็นค่าเริ่มต้น; ห้ามนำส่วนคะแนนรายข้อ เวลาทำ การจ่ายชุดโจทย์ หรือเงื่อนไขจบมาแสดง และ control ตั้งค่าต้องมี persisted behavior จริง ห้ามทำสวิตช์ตัวอย่างที่บันทึกไม่ได้
- การเลือกห้องใช้ `ClassroomPicker` ร่วมกับ assignment: flow ที่เข้าจากห้องเรียนตรึงห้องหลักและซ่อนห้องอื่นใต้ “มอบหมายให้ห้องเรียนอื่นด้วย” ในขั้นตั้งค่า ส่วน flow กลางเลือกหลายห้องในข้อมูลพื้นฐานได้; ต้องบอกเมื่อเลือกหลายห้องว่าแต่ละห้องมีคลังฝึกและความคืบหน้าแยกกัน ห้ามรวม roster หรือ progress ข้ามห้อง
- หลังเลือกโจทย์ให้แสดงทุกข้อใน compact scroll list ตาม pattern ของ assignment แต่ตัด preset คะแนน ช่องคะแนนรายข้อ และการจัดลำดับออก เหลือเลขลำดับสำหรับอ้างอิง ปุ่มดูตัวอย่าง และปุ่มเอาออก; ชื่อคลังฝึกและหัวข้อเลือกโจทย์ต้องแสดงเครื่องหมาย `*` ที่มองเห็นได้พร้อมข้อความสำหรับ screen reader
- หน้าตั้งค่าใช้แถว toggle ชุดเดียวกับ assignment เฉพาะการตรวจรายข้อ เฉลย รหัสผ่าน เครื่องคิดเลข กระดาษทด สับข้อ และสลับตัวเลือก; เมื่อเปิดรหัสผ่านต้องแสดง field บังคับทันที และกระดาษทดของคลังฝึกต้องไม่มี action แนบวิธีทำ
- นักเรียนต้องพบหน้ารอก่อนเข้ารายการโจทย์ หน้ารอใช้ภาษาชัดเจนว่าไม่สร้างรอบทำ ไม่จำกัดเวลา ไม่มีการส่งงานและไม่คิดคะแนน พร้อมแสดงคำชี้แจง จำนวนข้อ และปุ่มเข้าคลังฝึก โดยไม่โหลด question payload หรือสร้าง accepted-check event ก่อนนักเรียนเลือกข้อและกดตรวจ
- หน้า desktop ใช้หัวสูงประมาณ 72–88px, toolbar ค้นหา+แท็กไม่เกินประมาณ 96px, แถวโจทย์ 64–72px และแถว progress 44–48px; ใช้ `Card padding="md"` เฉพาะกลุ่มงานที่ต้องมีพื้นผิว ไม่ครอบทั้งหน้าหรือซ้อน Card
- search และ multi-tag AND อยู่ toolbar เดียว แท็กไม่เกินสองบรรทัดก่อนยุบเป็น “+N”; metadata ชื่อ/แท็ก/เคยตอบ/จำนวนครั้งอยู่แถวเดียวเมื่อพื้นที่พอ และเนื้อโจทย์ยาวเปิดรายละเอียดแยก
- หน้าความคืบหน้าใช้ table/list compact และลำดับ roster เป็นค่าเริ่มต้น ไม่เรียงจากจำนวนครั้ง ไม่ใช้กราฟ/สีแดงเขียว/กล่อง KPI สูงหลายใบ และใช้ถ้อยคำ “เคยตอบ X จาก Y ข้อ” แทนเปอร์เซ็นต์
- touch target ต้องอย่างน้อย 44×44px แม้พื้นผิวกะทัดรัด; ที่ 320px ห้ามล้นแนวนอน ที่ 1440×900 นักเรียนควรเห็นอย่างน้อย 5 แถวและครูเห็น roster อย่างน้อย 7 แถวเหนือ fold
- loading, empty, no-result, error และ permission-denied เป็นคนละ state; ห้ามเปลี่ยน authorization failure เป็นรายการว่าง และปุ่มย้อนกลับต้องคืน query/tag/page เดิมตามกติกา `lib/back-link.ts`
- navigation ทั้งหมดซ่อนเมื่อ server feature flag ปิด; mock/fixture ต้องมีป้ายตัวอย่างหรืออยู่หลัง local/Staging lab guard เท่านั้น

- ตาม UI-036 ไม่มี control อัปโหลดรูปหน้าปกห้องเรียนและไม่ render รูปเก่าเป็นพื้นหลัง; เก็บการอ่าน/เขียน metadata เก่าไว้ภายในเพื่อ backward compatibility เท่านั้น
- ตาม UI-037 หัวการ์ดห้องเรียนสีทั้งแถบต้องเป็นพื้นที่คลิกของลิงก์เปิดห้อง รวมข้อความและไอคอนที่เป็นเนื้อหา; เฉพาะปุ่มลาก คัดลอก ถังขยะ และ control อื่นที่มี action ของตัวเองเท่านั้นที่อยู่เหนือ link overlay
- ตาม UI-038 กรอบ “ห้องเรียนปัจจุบัน” ใน contextual sidebar ใช้ `rounded-lg` เพื่อคงรูปทรง Card แม้ style preset เพิ่มค่า `--radius`; สีธีมและ control ภายในยังใช้ token/พฤติกรรมเดิม
- ตาม UI-039 สวิตช์ “จำกัดจำนวนที่นั่ง” ต้องอยู่ติดกับชื่อในกลุ่มเดียวกันและไม่มี helper text ซ้ำ เพื่อไม่ให้ถูกอ่านว่าเป็น control ของช่องวันเปิด/ปิดคอร์สที่อยู่ข้างกัน; สวิตช์ยังต้องผูก accessible label กับชื่อเดิม
- ตาม UI-040 ชุดเลือกวิธีเก็บคะแนนในฟอร์มงานใช้หัวข้อ “เลือกคะแนน” และคำสั้น “ครั้งที่ดีที่สุด / เฉลี่ย / ครั้งล่าสุด” เรียงหนึ่งบรรทัด; คำเต็มจาก `SCORE_STRATEGY_LABELS` ยังคงใช้ในรายงานและข้อความสรุปที่ต้องอ่านโดยไม่มีบริบท
- ตาม UI-041 ตัวเลือก streak แสดงอยู่เสมอเพื่อให้เห็นความสัมพันธ์กับชุดโจทย์ แต่ต้องเป็นปุ่ม `disabled` สีเทาเมื่อเลือกทำทุกข้อ โดย UI-047 ย้ายเหตุผล “ใช้ได้เมื่อเลือกสุ่มโจทย์” ไปอยู่ใน tooltip ของตัวเลือก; การกลับไปทำทุกข้อต้องเลือกโหมด “อนุญาตให้ทำ” อัตโนมัติ และเมื่อเปิด streak ต้องคงช่องกำหนดจำนวนข้อที่ตอบถูกติดต่อกัน
- ตาม UI-042 เมื่อเปิด “จำกัดจำนวนที่นั่ง” ในหน้าสร้าง/ทำสำเนาห้องเรียน ให้แสดงช่องตัวเลขต่อจากสวิตช์ทันทีโดยไม่มี label “จำนวนที่นั่งสูงสุด” ซ้ำ เพื่อให้ช่องจำนวนอยู่ในแถวเดียวกับช่องวันเปิด/ปิดคอร์ส; ช่องยังต้องมี accessible name และหน่วย “คน”
- ตาม UI-045 ชุดเงื่อนไขจบในฟอร์มงานวางช่องตัวเลขไว้ในประโยคบนตัวเลือกโดยตรง: จำนวนครั้ง, ค่าเกณฑ์ผ่าน และจำนวนข้อถูกติดต่อกัน; การโฟกัสช่องเลือกเงื่อนไขนั้น ส่วนด้านล่างมีเฉพาะ control รองที่ไม่ซ้ำกับประโยค ได้แก่ วิธีเลือกคะแนนและตัวเลือกขั้นสูงของ streak
- ตาม UI-046 ตัวเลือกแบบ Card ในหน้าสร้างงานห้ามใช้เส้น `border-primary` หนาหรือม่วงเข้มเป็น selected state; ใช้เส้น `border-border` 1px ร่วมกับพื้น `bg-primary/10`, check หรือเงาเบา และคง focus ring ไว้สำหรับคีย์บอร์ด ตัวเลือกที่มีค่าตัวเลขต้องใช้ช่องแคบพอให้คำ หน่วย และช่องอยู่บรรทัดเดียวที่ 320px
- ตาม UI-047 หัวข้อชุดเงื่อนไขจบต้องระบุประเภทงานเป็น “เงื่อนไขการทำแบบฝึกหัดเสร็จ” หรือ “เงื่อนไขการทำข้อสอบเสร็จ”; คำอธิบายแต่ละเงื่อนไขและเหตุผลที่ streak ยังเลือกไม่ได้แสดงผ่าน tooltip ของ Card เมื่อ hover/focus ไม่วางเป็นข้อความกินพื้นที่ใต้แถว และหน่วยเกณฑ์ผ่านต้องสลับ `%`/`คะแนน` ได้จากปุ่มต่อท้ายช่องตัวเลขโดยไม่มีชุดเลือกซ้ำด้านล่าง
- ตาม UI-048 ปุ่มหน่วยเกณฑ์ผ่านต้องมีลูกศรลงเพื่อบอกว่าเปิดรายการได้; กดปุ่มเปิดดรอปดาวก่อนโดยไม่เปลี่ยนหน่วย แล้วเปลี่ยนค่าเฉพาะเมื่อผู้ใช้เลือก `%` หรือ `คะแนน` จากรายการ โดยข้อความ “ผ่านเกณฑ์”, ช่องตัวเลข และปุ่มหน่วยต้องอยู่บรรทัดเดียวกันเสมอ
- ตาม UI-015 ตัวเลือกห้องปัจจุบันเมื่อย่อบน desktop ใช้ปุ่ม School เปิดรายการเปลี่ยนห้องโดยไม่มีปุ่มลูกศรขึ้น–ลงอีกปุ่ม เมนูเต็ม/มือถือคงลูกศรเดิม; ตัวเรียกทั้งสองอยู่ใน DropdownMenu เดียวและซ่อนตาม breakpoint ไม่อิงสถานะย่ออย่างเดียวจนเปลี่ยนหน้าตามือถือ
- ปุ่มหลักหนึ่งจุดต่อ section เมื่อเป็นไปได้
- ทุก mutation ต้องมี pending, success และ error feedback
- หน้า data ต้องมี loading, empty และ permission-denied states
- destructive action ต้องบอกผลกระทบและขอการยืนยันตามความรุนแรง
- ขอการยืนยันด้วย `ConfirmDialog` / `useConfirm()` ใน `components/ui/confirm-dialog.tsx` เท่านั้น ห้ามใช้ `window.confirm` — มันบอกไม่ได้ว่ากำลังจะลบอะไร จัดสไตล์ไม่ได้ และครูอ่านแล้วนึกว่าเบราว์เซอร์ error
- ข้อความยืนยันต้องบอกทั้งสิ่งที่จะหายและสิ่งที่ยังอยู่ เช่น "แฟ้มนี้จะถูกลบถาวร — โจทย์ข้างในยังอยู่ในคลัง" และปุ่มยืนยันต้องเป็นคำกริยาที่จะเกิดขึ้นจริง (`ลบถาวร`, `นำออก`) ไม่ใช่ `ตกลง`
- การกระทำที่ย้อนกลับได้ (เก็บเข้าคลัง อนุมัติ) ใช้ปุ่มยืนยันสีปกติ ส่วนที่กู้คืนไม่ได้ใช้ `variant="destructive"`
- การเพิ่ม/เอาโจทย์ออกในหน้าแฟ้มโจทย์เป็นแบบ "ร่างก่อน ยืนยันทีหลัง" — ข้อที่ติ๊กเพิ่มใช้ checkbox และพื้นหลังสื่อสถานะโดยไม่ขึ้นป้ายข้อความซ้ำ ส่วนข้อที่ติ๊กออกขึ้นป้าย “จะเอาออก”; ยังไม่มีผลจนกดยืนยัน
- **ปุ่มย้อนกลับหมายถึงหน้าที่ผู้ใช้เพิ่งมาจาก ไม่ใช่หน้าแม่ตามเส้นทาง URL** — หน้าเดียวเข้าถึงได้จากหลายที่ (เช่น หน้านำเข้าจาก Word เข้าได้ทั้งจากหน้าเลือกวิธีนำเข้าและจากปุ่มบนคลังโจทย์) หน้านั้นจึงตอบเองไม่ได้ว่าผู้ใช้มาจากไหน · ฝั่งที่ลิงก์เข้าไปต้องบอกด้วย `withBackHref(target, from)` แล้วปุ่มย้อนกลับอ่านคืนด้วย `resolveBackHref`/`backHrefFromSearchParams` (`lib/back-link.ts`)
  - พา view เดิมไปทั้ง URL รวม query ด้วย คลังโจทย์ที่กรองคำว่า "นิวตัน" อยู่หน้า 2 จึงกลับมาเหมือนตอนที่จากไป ไม่ใช่รายการเปล่าหน้า 1
  - `fallback` คือที่ที่น่าจะมาจากมากที่สุดเมื่อไม่มีอะไรถูกจำไว้ (เปิดจาก bookmark, พิมพ์ URL เอง, หรือลิงก์เก่า) ไม่จำเป็นต้องเป็นหน้าแม่ตามเส้นทาง
  - **ค่าที่จำไว้มาจากเบราว์เซอร์ จึงไม่เชื่อ** `resolveBackHref` คืนเฉพาะ path ภายในแอป ปฏิเสธ URL ที่มี scheme และ `//host` / `/\host` ที่เบราว์เซอร์อ่านเป็น protocol-relative — ด้วยเหตุผลเดียวกับที่ `safeQuestionsRedirect` มีอยู่ ปุ่มย้อนกลับที่เชื่อค่าใน URL คือ open redirect
  - หน้าที่เป็นปลายทางของเมนูด้านซ้ายไม่ต้องมีปุ่มย้อนกลับ (เช่น `/questions/new`, `/questions/import`) เพราะไม่ได้มีหน้าก่อนหน้าที่แน่นอน
- อย่าซ่อน authorization error ด้วย empty state
- Form ต้องมี label ที่อ่านได้ด้วย assistive technology

## ข้อมูลจริงกับต้นแบบ

- Mock/prototype ต้องมีป้ายชัดหรือซ่อนจาก production navigation
- ห้ามใช้เลขสุ่มเป็น analytics โดยไม่ระบุว่าเป็นข้อมูลตัวอย่าง
- ห้ามแสดง invoice, usage, plan หรือ cancellation สำเร็จหากไม่มี backend จริง
- ห้ามอ้าง PDPA, ISO, encryption, SLA, SSO, trial หรือราคาเป็นข้อเท็จจริงโดยไม่มีหลักฐานและการอนุมัติ

## Content principles

- ยืนยันการทำงานด้วยข้อความที่ตรงกับผลจริง
- อธิบายการสุ่มและการตรวจคะแนนให้ครูเข้าใจและตรวจสอบได้
- บอกชัดว่าส่วนใดตรวจอัตโนมัติและส่วนใดต้องให้ครูตรวจ
- หลีกเลี่ยงข้อความที่ทำให้ครูเชื่อว่าระบบตัดสินนักเรียนแทนครู
- ข้อมูลสุขภาพ ครอบครัว และความเครียดไม่ควรปรากฏใน dashboard รวมโดยไม่จำเป็น

### พื้นที่เรียนรู้ของนักเรียนแบบรวม

- เมนู **พื้นที่เรียนรู้ของฉัน** รวมหน้าหลัก ห้องเรียน และสรุปงานของนักเรียนไว้ใน `/dashboard` เริ่มด้วยห้องเรียน ตามด้วยสรุปงานและประกาศ ปฏิทินย่อใช้พื้นที่ด้านข้างเมื่อจอกว้างพอ
- สรุปจำนวนงานอยู่แถวเดียวกับหัวข้อด้วย Badge ขนาดเล็ก และยอมให้ขึ้นบรรทัดใหม่บนจอแคบ รายการงานใช้ Card สั้น มีแถบสีและไอคอนจาก metadata ห้องเรียนที่มอบหมายงานจริง โดยอ่านจาก ID ห้องที่นักเรียนเข้าถึงได้ ประวัติการสอบเปิดดูผ่าน disclosure เพื่อประหยัดพื้นที่แนวตั้ง
- Grid ห้องเรียนและตำแหน่งฟอร์มเข้าร่วมต้องอิงความกว้าง container ของเนื้อหา แทนความกว้าง viewport อย่างเดียว เพื่อไม่ให้ sidebar กับปฏิทินบีบ Card และข้อมูลจนอ่านไม่ได้

### ห้องเรียนและงานของนักเรียนแบบกระชับ

- หัวห้องเรียนของนักเรียนต้องอ่านสีปก ไอคอน และลายตกแต่งที่ครูเลือกผ่าน helper และ `ClassroomCoverPattern` ชุดเดียวกัน ทั้งห้องวิชาและโฮมรูมใช้ `StudentClassroomHeader`; รักษาชื่อห้องและครูให้ชัดบนมือถือด้วยข้อความที่ขึ้นบรรทัดได้
- ตัวกรองสถานะใช้ ToggleGroup ต่อเนื่อง ประเภทงานใช้ Select และอยู่ในแถบเดียวเมื่อพื้นที่พอ หลีกเลี่ยงกรอบสถิติที่ซ้ำกับจำนวนในตัวกรอง ใช้ container query จัด grid ตามพื้นที่เนื้อหาจริง
- การ์ดงานนักเรียนกดได้ทั้งกรอบ ใช้ Link + Card พร้อม focus ring และชื่อ action ตามสถานะ ลดปุ่มเริ่มทำที่ซ้ำกับพื้นที่การ์ด เหลือชื่อ ข้อมูลโจทย์ เวลา เกณฑ์ และสถานะในแถวสั้น ใช้สีและไอคอนของธีมห้องเป็นจุดนำสายตา; คะแนนที่ครูซ่อนหรือยังไม่ถึงเวลาแสดงต้องไม่ปรากฏ รวมข้อความผ่าน/ไม่ผ่านที่อนุมานจากคะแนน

### ข้อมูลส่วนตัวนักเรียน

- หน้าโปรไฟล์นักเรียนไม่มี navigation card ซ้ำกับ sidebar หลัก ขอบซ้ายใช้ padding ของ main และบน desktop ขอบขวาใช้ notification anchor ของ shell; จอเล็กใช้ความกว้างเต็ม ช่องข้อมูลต้องอิง container query เพื่อไม่บีบฟอร์มเมื่อเปิด sidebar
- หัวข้อข้อมูลตัวตน การศึกษา และติดต่อใช้ป้าย “ดูได้: …” แทนคำอธิบายยาว ป้ายเป็นปุ่มเปิด HoverCard ที่ใช้ได้ทั้ง hover, keyboard และแตะ และรายละเอียดต้องตรงกับข้อมูลที่ server เปิดเผยจริง โดยไม่อ้างว่าทุกช่องในส่วนการศึกษาเปิดให้ครูประจำวิชาทั้งหมด
- การจัดรูปใช้ Dialog พร้อมกรอบลาก/ลูกศร ปุ่มซูมและเริ่มใหม่ ใช้ “ใช้รูปนี้” สำหรับตัวอย่างในหน้า ไม่แสดงข้อความว่าบันทึกถาวร เมื่อขอยกเลิก/คลิกนอก/Escape ใช้ ConfirmDialog ที่อยู่ใน context ของ Dialog เดิมแต่แยก popup เพื่อคงร่างและคืน focus ได้ถูกต้อง

### พื้นที่เรียนรู้และประกาศที่รับทราบ

- คอลัมน์เนื้อหาหน้ารวมใช้ความกว้างเต็ม main โดยปฏิทินชิดขอบขวาภายใน padding ของ shell และ sticky; จอแคบกลับเป็นคอลัมน์เดียว Grid ห้องเรียนรวม Homeroom ก่อนวิชาและใช้ 3 คอลัมน์เมื่อ container พอ งานในห้องเรียนใช้หลักเดียวกันและหัวหมวดมีพื้นสี/ไอคอน/ตัวหนาที่เด่นกว่าข้อมูลรอง
- สรุปงานใช้ Card ครอบจำนวน ตัวเรียง และรายการเลื่อนภายใน ไม่ใส่หัวข้อซ้ำ “งานที่ต้องทำ” ประวัติคะแนนเป็น disclosure สูงจำกัด เปิด/ปิดและ click-away/Escape ได้; ขนาดหัวข้อห้องเรียน สรุปงาน และประกาศล่าสุดต้องเท่ากัน ประกาศล่าสุดมีธีมของห้องที่ประกาศ
- Popup ประกาศใช้ธีมห้อง ชื่อวิชา ผู้ประกาศ เวลาสร้างและเวลาที่แจ้งซ้ำจริง ไฟล์/ลิงก์ใช้ renderer เดิม รับทราบสำเร็จแล้วค่อยเปลี่ยนคิว Error ต้องคงประกาศไว้ รูปขยายเป็น popup อ่านอย่างเดียว nested ในประกาศ เมื่อพักคิวไม่สร้าง receipt
- คำว่า “รับทราบแล้ว” ใช้กับ explicit receipt เท่านั้น ไม่เปลี่ยนชื่อข้อมูลการแสดงบนหน้าจอเป็นการรับทราบ ไอคอน BellRing แจ้งใหม่ต้องยืนยันผลว่าทุกคนต้องรับทราบรอบใหม่ และสถานะ/คำอธิบายต้องใช้ตัวเลขของรอบปัจจุบัน

### เครื่องมือระหว่างทำข้อสอบและแบบฝึกหัด

- แถบเครื่องมือใช้ Card ขนาดกะทัดรัดและ sticky ใน scrollport จริง สถานะตัดบรรทัดได้ ปุ่มหลักเป็นไอคอนบนจอแคบพร้อม accessible label และคงเป้าสัมผัสอย่างน้อย 44px; การเปลี่ยนข้อเผื่อความสูงแถบและ padding ของ scrollport เพื่อให้หัวโจทย์อยู่ใต้แถบ
- แผงขวาแบ่งเป็น Card เวลา/ความคืบหน้าและ Card เลขข้อ/คำอธิบาย/ส่งคำตอบ กรอบสูงพอดีเนื้อหาจนถึงขีดจำกัด ให้เฉพาะเลขข้อเลื่อนเมื่อมีข้อเยอะ โดยปุ่มส่งอยู่ท้ายแผง สถานะสีต้องมีคำอธิบายและชื่อเข้าถึงได้ ไม่ใช้การขยายปุ่มที่ทำให้ grid กระโดด
- ใช้สี primary กับข้อในหน้าปัจจุบัน, success กับข้อที่ตอบ/ตรวจถูก, destructive กับตรวจยังไม่ถูก และ flag กับปักธง ใช้ timer role พร้อม aria-live off เพื่อไม่ขัดการอ่านโจทย์ทุกวินาที โหมดโฟกัสคงเครื่องมืออยู่นอกพื้นที่เลื่อนของโจทย์

### ผลคะแนนและลายน้ำเฉลย — 14 ตุลาคม 2026

- `SubmissionScoreSummary` ใช้ Card กระชับ เปอร์เซ็นต์เป็น badge ข้างคะแนน/ผลผ่านและจำนวนข้อ วันเวลาขึ้นบรรทัดใหม่ใน container แคบ ไม่ใช้วงคะแนนใหญ่กับช่องว่างแนวตั้งหลายชั้น
- ตัวเลือกเฉลยบอก “คำตอบของคุณ” แม้ตรงกับเฉลย สีไม่เป็นตัวบอกสถานะเพียงอย่างเดียว คำตอบว่างใช้ “ไม่ได้ตอบข้อนี้” และตัวเลือกอ้างอิง index ของรอบสอบ
- ลายน้ำเฉลยเป็นข้อมูลตัวตนสามบรรทัดซ้ำทั่ว viewport ตามการเลื่อนหน้าและเหนือป๊อปอัป ไม่รับ pointer ไม่เข้าสู่ accessibility tree ไม่มีปุ่มปิด ใช้สี semantic โปร่งใสเพื่อให้อ่านโจทย์ได้ วันที่อ้างอิง server และ monotonic elapsed time


### สีสถานะงานและปฏิทินห้องเรียน — 14 ตุลาคม 2026

- หน้ารายวิชาและโฮมรูมใช้ student-learning-stage และคอลัมน์ปฏิทิน sticky ร่วมกับ dashboard สีธีมวิชายังคงอยู่ที่ header/icon/group ส่วนแถบซ้ายการ์ดเป็นสถานะกำหนดส่งเดียวกับจุดปฏิทิน
- เขียวคือทำครบเงื่อนไขแล้วพร้อมติ๊ก/ป้ายส่งแล้ว/พื้นและเงาเขียวอ่อน แดงคือเลยกำหนด เหลืองคือภายใน 48 ชั่วโมง และ primary คือยังไม่ถึงกำหนดหรือไม่มีกำหนด ต้องมีคำอธิบายสีเมื่อ hover/focus และไม่ใช้สีเป็นตัวบอกสถานะเพียงอย่างเดียว
- ย้ายงานและกลุ่มที่ทำครบแล้วลงท้ายโดยรักษาลำดับค้างเดิม ปฏิทินบอกขอบเขตรายวิชาหรือรวมทุกวิชาและนับเฉพาะงานที่มีกำหนดส่งในปฏิทิน
