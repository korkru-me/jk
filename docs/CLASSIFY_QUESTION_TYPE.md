# ประเภทโจทย์ `classify` (ตารางจำแนก)

อัปเดตล่าสุด: 12 กันยายน 2026 · สถานะ: **เฟส 4 จาก 7 เสร็จ — ยังสร้างโจทย์ไม่ได้**
· schema พร้อม · นักเรียนตอบและระบบตรวจได้แล้ว · **เหลือฟอร์มสร้างโจทย์ (เฟส 5)**

เอกสารนี้คือช่องทาง handoff ของงานนี้ตาม `AGENTS.md` แชตและ memory ของ agent ไม่ใช่ช่องทาง handoff
ใครมาทำต่อ (Claude Code หรือ Codex เครื่องไหนก็ตาม) ให้เริ่มจากไฟล์นี้

## โจทย์ที่ต้องการรองรับ

ใบงานรูปแบบ "ตารางจำแนกประเภท" ที่ครูวิทยาศาสตร์ใช้กันทั่วไป — หนึ่งตาราง หนึ่งข้อ:

| ภาพ | จำแนกตามแหล่งกำเนิด | จำแนกตามชนิดของมอนอเมอร์ |
|---|---|---|
| (รูป) เนื้อหมู | ☑ พอลิเมอร์ธรรมชาติ ☐ พอลิเมอร์สังเคราะห์ | ☐ โฮโมพอลิเมอร์ ☑ โคพอลิเมอร์ |
| (รูป) ยางรัดของ | ☐ พอลิเมอร์ธรรมชาติ ☑ พอลิเมอร์สังเคราะห์ | ☑ โฮโมพอลิเมอร์ ☐ โคพอลิเมอร์ |
| (รูป) เชือกป่าน | ☑ พอลิเมอร์ธรรมชาติ ☐ พอลิเมอร์สังเคราะห์ | ☑ โฮโมพอลิเมอร์ ☐ โคพอลิเมอร์ |

**แถว** = สิ่งที่ถูกจำแนก (รูป + ชื่อ) · **คอลัมน์** = มิติการจำแนก + ชุดตัวเลือกของมิตินั้น · **ช่อง** = เลือก 1 ตัวเลือก

### ทำไมไม่ใช้ `composite` ที่มีอยู่

ทำได้ แต่ไม่ควร: 3 แถว × 2 คอลัมน์ = 6 parts ชนิด `mcq` ครูต้องพิมพ์ตัวเลือกซ้ำ 6 ชุด
ผังออกมาเป็น ก) ข) ค) เรียงแนวตั้ง ไม่ใช่ตาราง และที่สำคัญกว่านั้น
**ตัวเลือกเป็นของคอลัมน์ ไม่ใช่ของช่อง** — ไม่มีประเภทไหนที่มีอยู่ที่แสดงความสัมพันธ์นี้ได้

และคำตอบของ classify มีพิกัด 2 มิติ (แถว × คอลัมน์) ถ้าแบนเป็นลิสต์เดียวตามแบบ `composite`
หน้าผลสอบกับหน้าตรวจจะเห็นข้อย่อย 6 ข้อเรียงกันโดยไม่รู้ว่าข้อไหนคือแถวไหนคอลัมน์ไหน
ครูจะไม่มีวันเห็นว่า "เด็กพลาดมิติแหล่งกำเนิดเป็นพิเศษ" ซึ่งเป็นข้อมูลที่มีค่าที่สุดของโจทย์แบบนี้

## การตัดสินใจที่เจ้าของผลิตภัณฑ์เคาะแล้ว (12 กันยายน 2026)

| เรื่อง | ที่เลือก |
|---|---|
| ชื่อ type | `classify` — ป้ายไทย "ตารางจำแนก" |
| prefix เฉลย | `CLS:` (ตรึงลง `submission_answers.correct_answer` เปลี่ยนทีหลังไม่ได้) |
| คะแนน | **ช่องละ 1 คะแนน ได้คะแนนบางส่วน** — กติกาเดียวกับ `COMP:` และ `FILL:` |
| ขอบเขตรุ่นแรก | **แต่ละช่องเลือกได้ 1 ค่าเท่านั้น** (radio) โหมดหลายค่าเพิ่มทีหลังได้โดยไม่ทำลายโจทย์เก่า |
| เบรนช์ | `feat/classify-question-type` แตกจาก `fix/composite-part-images` ซึ่งแตกจาก `origin/master` |

## รูปร่างข้อมูล

`lib/types.ts` — `ClassifyConfig` เก็บใน `questions.extra_data`

```ts
columns: [{ id, title, options: string[] }]   // ตัวเลือกอยู่ที่คอลัมน์ ครูพิมพ์ครั้งเดียว
rows:    [{ id, text, image_urls?, answers: Record<columnId, optionIndex> }]
row_label_style?: PartLabelStyle              // undefined = 'number' (3.1, 3.2, …)
```

`answers` คีย์ด้วย **column id ไม่ใช่ตำแหน่ง** — สลับหรือลบคอลัมน์แล้วเฉลยของทุกแถวจะไม่เลื่อนไปชี้หมวดผิด

คำตอบนักเรียนและเฉลยที่ตรึงไว้ใช้รูปเดียวกัน: กริด row-major ของ **ตำแหน่งตัวเลือก**
`CLS:[[0,1],[1,0],[0,0]]` — ตำแหน่งไม่ใช่ข้อความ ด้วยเหตุผลเดียวกับที่ปรนัยเก็บ `MCQ:<position>`
(ตัวเลือกสองอันมีข้อความเหมือนกันได้ เทียบข้อความแล้วจะให้คะแนนผิดตัว)

## กติกาที่ต้องไม่แก้โดยไม่อ่านก่อน

ทั้งหมดอยู่ที่ `lib/classify.ts` ที่เดียว เพราะ **เฉลยที่ตรึง · คะแนนเต็ม · จำนวนข้อย่อยบนการ์ด ต้องเป็นเลขเดียวกัน**

1. **ช่องที่ครูไม่ได้ใส่เฉลย ไม่นับเป็นคะแนนเต็ม และไม่ถูกตรวจ**
   เคยพลาดมาแล้วกับข้อย่อยเติมคำของ `composite` — `naturalMaxScore` นับข้อย่อยที่ตัวเรนเดอร์ไม่มีช่องให้กรอก
   นักเรียนเสียคะแนนให้ช่องที่ครูไม่เคยให้มา (ดู `docs/FEATURE_STATUS.md`)
   ที่นี่ `classifyCellCount` นับเฉพาะช่องที่ตอบได้และตรวจได้ ทั้งสองฝั่งจึงตรงกันโดยโครงสร้าง

2. **เฉลยที่ชี้เลยจำนวนตัวเลือกของคอลัมน์ ถือเป็นช่องที่ไม่ได้ใส่เฉลย**
   เกิดจากการนำเข้าไฟล์ หรือครูลดจำนวนตัวเลือกทีหลัง ปล่อยไว้จะกลายเป็นช่องที่ไม่มีใครตอบถูกได้

3. **ตัวหารตอนให้คะแนนมาจากเฉลยที่ตรึงไว้ ไม่ใช่ `extra_data` ปัจจุบัน**
   ต่างจากสาขา `COMP:`/`FILL:` ที่อ่าน `naturalMaxScore` สด ๆ — ถ้าครูลบคอลัมน์ทิ้งหลังนักเรียนตอบไปแล้ว
   ตัวหารสดจะหดลงขณะที่ `earned` ยังมาจากกริดเดิมที่กว้างกว่า แล้ว `scaleScore` จะจ่ายเกินคะแนนที่โจทย์มี
   (มีเทสต์คุมไว้: `stays within the question's worth after the teacher deletes a column`)

4. **classify ไม่มีสถานะ "รอครูตรวจ"** — `is_correct` ไม่เคยเป็น null

### เลย์เอาต์: `<table>` เดียว สองหน้าตา

เหนือ `lg` เป็นตารางจริง · ต่ำกว่า `lg` ทุก element ของตารางกลับเป็น block (`block lg:table-cell`)
แต่ละแถวจึงกลายเป็นการ์ดที่ซ้อนมิติลงมา · หัวตารางซ่อนตัวเองแล้วแต่ละช่องพิมพ์ชื่อคอลัมน์ของตัวเองแทน
(กลุ่ม radio ที่ไม่มีป้ายกำกับคือกลุ่มที่ตอบไม่ได้)

**ทำไม `lg` ไม่ใช่ `md`** — วัดมาแล้วไม่ได้เดา: ที่ 768 และ 812 (มือถือแนวนอน) ตารางไม่ล้นก็จริง
แต่แถบข้างของหน้าสอบเบียดจนสามคอลัมน์เหลือที่น้อยมาก "พอลิเมอร์ธรรมชาติ" หักเป็น 3 บรรทัด
กฎ responsive บอกให้ตัด breakpoint ตรงที่เนื้อหาเริ่มอ่านไม่ได้ ไม่ใช่ตรงความกว้างของอุปกรณ์ที่มีชื่อ
และบอกตรง ๆ ว่ามือถือแนวนอนต้องไม่ได้เลย์เอาต์แบบ desktop ที่อัดแน่น

## ข้อจำกัดที่ยังค้างอยู่ ต้องรู้ก่อนทำเฟสต่อไป

1. **schema พร้อมแล้ว แต่ค่า enum `classify` อยู่บนฐาน production ก่อนที่ UI จะมี**
   ปลอดภัย: การเพิ่ม label ไม่ rewrite แถวไหน และยังไม่มีทางเขียนค่านี้ลงไปจนกว่าฟอร์มของเฟส 5 จะขึ้น
   แต่แปลว่า **ห้าม revert migration สองตัวนี้** — Postgres ลบค่า enum ออกไม่ได้ ถ้าต้องถอยต้องสร้าง type ใหม่ทั้งตัว

   งาน SEB เฟส 3 (`20260905072556_add_exam_seb_password_drafts`) ยังค้างไม่ apply เหมือนเดิมบนเบรนช์ของมัน
   แต่ไม่มีบน `master` จึงไม่พ่วงมากับ classify — นั่นคือเหตุผลที่เบรนช์นี้แตกจาก master
   เมื่อเบรนช์ SEB rebase มาทับ master ทีหลัง มันจะเห็น migration ของ classify เป็นของที่ apply แล้ว ไม่ชนกัน

2. **`/exam-screen-lab` ไม่มีบน `master`** อยู่บนเบรนช์ SEB เท่านั้น (commit `47dd7a2`)
   เฟส 4 วางแผนจะใช้หน้านี้พิสูจน์ตัวเรนเดอร์โดยไม่ต้อง login และไม่ต้องมีข้อมูลใน DB
   ต้อง cherry-pick commit ห้องทดลองมา (เป็น dev-only ปิดใน production อยู่แล้ว)
   หรือพิสูจน์ผ่านปุ่มดูตัวอย่างใน `/questions/new` แทน — ตัดสินตอนเริ่มเฟส 4

3. **กฎ responsive ใหม่ (commit `525aaad`, 12 กันยายน 2026)** ทำให้ responsive เป็น definition of done
   กระทบเฟส 4 เต็ม ๆ: รองรับ iPad และมือถือทั้งสองแนว · ห้าม horizontal scroll ระดับหน้า ·
   **touch target ≥ 44×44 px** ซึ่งเป็นข้อที่ตารางที่มี radio เรียงเป็นกริดชนง่ายที่สุด ·
   ข้อความไทยยาวต้องตัดบรรทัดได้ · ตรวจโดยย่อ-ขยายต่อเนื่องไม่ใช่แค่ความกว้างของอุปกรณ์ที่มีชื่อ

4. **`DOMAIN.md` และ `FEATURE_STATUS.md` ยังไม่เขียนถึง classify โดยตั้งใจ** — จะเขียนในเฟส 7
   ตอนที่มันใช้งานได้จริง `AGENTS.md` ห้ามนำเสนอ UI ที่ยังไม่เสร็จเป็นความจริงของ production

5. **โหมดพิมพ์ยังไม่อยู่ในขอบเขต** — `components/exam/print-worksheet.tsx` ไม่รองรับแม้แต่ `composite`
   เป็นงานคนละก้อน ต้องตัดสินใจแยก
