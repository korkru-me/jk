# งานกลุ่มจากหน้าสร้างแบบฝึกหัด — 23 พฤศจิกายน 2569

## พฤติกรรม

- หน้าสร้างแบบฝึกหัดเริ่มต้นเป็นงานเดี่ยว งานกลุ่มเปิดช่องจำนวนสมาชิกขั้นต่ำ–สูงสุด นับรวมผู้ส่ง และใช้ตัวเลือกโจทย์จากคลังเดิม
- ตัวแทนตอบโจทย์และเลือกชื่อเพื่อนในห้องเดียวกันตอนส่ง กลุ่มส่งหนึ่งครั้ง Server ตรวจจำนวนคน ผู้ได้รับมอบหมาย ชื่อซ้ำ และการส่งซ้ำข้ามกลุ่ม
- คำตอบและการตรวจอยู่ที่ตัวแทนชุดเดียว Header ของสมาชิกแสดงคะแนนจากต้นทาง ทั้งเมื่อระบบตรวจ ครูแก้คะแนน ปรับคะแนนส่งช้า หรือโมฆะข้อ
- Admin เจ้าของห้องและ Admin ผู้ช่วยสอนที่มีสิทธิ์จัดการใช้ความสามารถครูได้ รวมถึงตัวตรวจเจ้าของรหัสออก SEB โดย SQL ปรับเฉพาะ RPC ที่ติดตั้งอยู่แล้ว

## ข้อมูลและสิทธิ์

Migration ที่ต้องใช้คือ `20261122232814_exercise_group_submission.sql` ซึ่งสร้างด้วย Supabase CLI และยังรอลง Staging จากนั้นจึง Production

`exercise_group_members` เปิด RLS และเพิกถอนสิทธิ์ browser การจองกลุ่มและการ freeze ใช้ RPC เฉพาะ service role หลังตรวจ session และเจ้าของ submission สมาชิกอ่านคำตอบต้นทางได้ตามเวลาแสดงผลเดิม การเป็น Admin ยังต้องผ่านสิทธิ์ของห้องและงานนั้น

การตรวจประวัติล่าสุดพบ Staging มี 168 เวอร์ชันและรายการ remote-only `20261009142610` ส่วน Production มี 155 เวอร์ชันและ SEB 12 รายการที่รอลงตามเดิม มีโฟลเดอร์ชั่วคราวที่ fetch ประวัติจริงของ Staging เพื่อเตรียมส่งเฉพาะ migration ใหม่ รอบนี้ยังไม่มีการ apply, repair หรือ replay migration บน hosted

## ผลตรวจ local

PGlite ตรวจ Admin เจ้าของห้องและคนนอก จำนวนสมาชิก ชื่อซ้ำ คนนอกห้อง revision ขัดแย้ง การส่งซ้ำ การใช้ header ของสมาชิกที่มีร่างเดิม คะแนนร่วมกัน การแก้คะแนน และสิทธิ์อ่านตามเวลาเผยแพร่

Chrome ตรวจหน้าสร้างจริงโดยเลือกงานกลุ่ม 3–5 คนและโจทย์สองข้อจากคลัง ผ่านหน้าทบทวนและรับ payload ที่มีโหมด จำนวนสมาชิก และ question IDs ตามที่เลือก ใช้ข้อมูลสมมติและการบันทึกในหน่วยความจำเท่านั้น

หน้าส่งนับตัวแทนในจำนวนสมาชิก จำกัดเพื่อนสูงสุดตามที่ครูตั้ง และปิดการยืนยันเมื่อไม่ครบขั้นต่ำ ตรวจที่ 390px แล้วไม่ล้นแนวนอน ทดสอบค่าเริ่มต้นงานเดี่ยวและช่วงสมาชิกผิดบน primary localhost:3000 ด้วย หลังตรวจแยก candidate ไว้พอร์ต 3094 และคืนเฉพาะ patch ของรอบนี้จาก primary เพื่อรอ schema ที่ต้องลงก่อนปล่อย เก็บงานค้างเดิมของผู้ใช้ไว้ครบ

TypeScript, design-token lint และ Webpack production build ผ่าน Vitest ผ่าน 353 suites / 4,940 tests รวมสัญญาฐานข้อมูลงานกลุ่ม 7 กรณีและการปฏิเสธคะแนนอัตโนมัติของร่างหมดเวลาที่ไม่มีสมาชิกครบ Next.js MCP ของ preview รายงาน configErrors และ sessionErrors ว่าง

ตัวอย่างพร้อมเปิดตรวจอยู่ที่ `http://127.0.0.1:3094/exam-screen-lab/assignment-creation?type=exercise` และ `http://127.0.0.1:3094/exam-screen-lab?group=1&type=exercise&perPage=5`

## ผลตรวจ hosted และสถานะล่าสุด

เจ้าของอนุญาตใช้คีย์เฉพาะ Staging และปล่อย Production หลังผ่านการทดสอบแล้ว ลง `20261122232814_exercise_group_submission.sql` เฉพาะ Staging และปล่อยโค้ดผ่าน PR #151 (`1d20981597999bca39c984241cab151cac009a08`) ไม่แตะ 12 migrations ของ SEB

Chrome เข้า canonical Staging ผ่านสิทธิ์เดิมโดยไม่อ่าน/เปลี่ยน deployment protection แอดมินจำลองสร้างแบบฝึกหัดกลุ่ม 3–5 คนพร้อมโจทย์คลังสองข้อ คะแนนรวม 20 ได้สำเร็จ หน้าส่งนับตัวแทนรวมในกลุ่ม ปิดปุ่มเมื่อมีเพียงสองคน และเลือกรายชื่อห้องเดียวกันได้ RPC ปฏิเสธจำนวนคนผิด ชื่อซ้ำ และต่างห้องแบบไม่ทิ้งสมาชิกค้าง

การส่งจริงพบ receipt ของเพื่อนไม่ใส่ `org_id` ซึ่ง hosted บังคับ NOT NULL จึง rollback การส่งทั้งรายการ ไม่เกิดคะแนนหรือสมาชิกครึ่งกลุ่ม เพิ่ม `20261123013055_exercise_group_receipt_org.sql` เพื่อคัดลอกสังกัดต้นทาง และปรับสัญญา PGlite ให้มี NOT NULL เหมือน hosted แทนการแก้ migration ที่ลงแล้ว ต้องลงตัวแก้ Staging แล้วทดสอบส่ง/ตรวจและอ่านผลจากสมาชิกอีกครั้ง ก่อนลงสองรายการของงานกลุ่มใน Production

ข้อมูลทดสอบเป็นแปดบัญชีจำลองกับสองห้องและสองโจทย์ มี manifest ส่วนตัวเพื่อ cleanup แบบตรวจ provenance ห้ามอ้างว่าทดสอบ hosted ผ่านครบหรือปล่อย Production จนกว่าหลักฐานขั้นตอนเหล่านั้นจะครบ
